## 0. `pitch/` — 기획 발표용

제품을 **이야기 순서대로 여덟 장**으로 나누고, 기술 질문용 네 장을 뒤에 붙였다. 구현/미구현을 구분하지 않고 완성된 서비스의 모습을 보여준다.
색은 진행 상태가 아니라 **역할**을 뜻한다 — 사용자 / 서비스 / 미디어 / AI / 저장소 / 외부.

| 파일 | 쓸 자리 |
|---|---|
| `00-overview` | 제품 전체를 한 장으로 — 첫 슬라이드 |
| `01-authoring` | 강사가 강의를 만들어 공개하기까지 |
| `02-enrollment` | 학생이 강의를 찾아 듣기 시작하기까지 |
| `03-live` | 수업이 실제로 진행되는 순간 |
| `04-captions` | 말이 자막이 되는 과정 — 제품의 차별점 |
| `05-materials` | 올린 자료가 검색 가능한 지식이 되는 과정 |
| `06-qa` | 질문에 근거를 달아 답하는 방식 |
| `07-replay` | 지난 수업을 다시 보는 방식 |
| `08-data` | 데이터를 어떻게 나눠 두었는가 |
| `09-servers` | 실제로 어떤 서버에 어떻게 얹었는가 |
| `10-backend-modules` | 백엔드 안이 어떻게 나뉘어 있는가 — 유지보수 질문의 답 |
| `11-request-path` | 요청 하나가 어떤 검사를 거치는가 |
| `12-architecture` | 구성 요소 전부를 한 장에 — 기술 발표의 중심 슬라이드 |
| `13-trust` | 백엔드를 우회하는 경로가 안전한 이유 |

앞 여덟 장이 발표 본문, 뒤 여섯 장(`08`~`13`)은 질문이 나올 때 꺼내는 장이다.
`index.html`을 브라우저로 열면 열네 장을 한 번에 훑어볼 수 있다.

**이 장들은 손으로 그린 게 아니라 `tools/build_deck.py`가 생성한다.** 고칠 일이 있으면
SVG를 직접 만지지 말고 스크립트의 노드·연결선 정의를 고친 뒤 다시 돌린다.

```bash
cd docs/architecture/tools && python3 build_deck.py   # → ../pitch/*.svg + 겹침 검증
```

레이아웃 엔진(`layout.py`)이 **겹침을 구조적으로 배제한다** — 노드는 열에만 놓이고 화살표는
거터의 전용 레인으로만 흐르며, 라벨은 선·노드를 피해 자동으로 자리를 잡는다.
열을 건너뛰는 의존(예: `curriculum → auth`)은 본문 위쪽 전용 레인으로 우회한 뒤
목표 열 바로 왼쪽 거터에서 내려온다 — 중간 모듈을 관통하지 않는다.
`check_overlap.py`가 매 실행마다 이를 검증하고 위반을 출력한다. **현재 14장 모두 겹침 0건.**

## 1. `liveclass-architecture.drawio` — 편집 원본

서비스를 **기능 단위로 자른** 15개 탭이다. 각 탭 하단에 그 슬라이스의 설계 근거와 미해결 지점을 적어 뒀다.

| 탭 | 슬라이스 |
|---|---|
| 00 | 기능 슬라이스 지도 — 무엇이 되고 무엇이 비었는지 한 장 |
| 01 | 인증과 세션 |
| 02 | 커리큘럼 탐색 (공개 카탈로그) |
| 03 | 커리큘럼 관리 (강사) |
| 04 | 섹션·레슨 구조 편집 — 재정렬과 `structure_version` CAS |
| 05 | 수강 신청과 승인 |
| 06 | 라이브 세션 수명주기 |
| 07 | 실시간 채팅 |
| 08 | 자료 업로드 (presigned) |
| 09 | 녹화와 다시보기 |
| 10 | 라이브 자막 (CP2) |
| 11 | 용어·근거 RAG (CP3) |
| 12 | 배포 토폴로지 |
| 13 | 백엔드 모듈 의존 |
| 14 | 스키마 소유권 |

**여는 법** — 셋 중 아무거나.
- [app.diagrams.net](https://app.diagrams.net) 에서 열기 (설치·로그인 불필요)
- VS Code + `Draw.io Integration` 확장 설치 후 파일 더블클릭
- draw.io 데스크톱 앱

**내보내기** — `File → Export as → SVG / PNG / PDF`. 슬라이드에는 SVG가 가장 깔끔하다.

## 2. `tools/` — 생성 스크립트

`.drawio`를 **처음 만들 때** 쓴 스크립트다. 노드·연결선을 파이썬 데이터로 정의하고 mxGraphModel XML로 내보낸다.

```bash
cd docs/architecture/tools && python3 build_slices.py   # → liveclass-architecture.generated.drawio
```

> ⚠️ 출력 파일 이름이 다르다(`.generated.drawio`). **원본을 덮어쓰지 않는다** —
> draw.io에서 손으로 고친 내용이 스크립트 재실행으로 날아가지 않게 하기 위해서다.
> 최초 생성 이후로는 `liveclass-architecture.drawio`가 원본이고, 스크립트는 참고용이다.
> 슬라이스를 통째로 다시 뽑고 싶을 때만 쓴다.

## 표기 규칙

그림 전체가 같은 언어를 쓴다.

| 표기 | 뜻 |
|---|---|
| 초록 실선 | 구현·동작 확인됨 |
| 회색 점선 | 미착수 — 설계 의도 (CP2~CP3) |
| 파란 굵은 테두리 | 그 그림의 주인공 |
| 주황 원통 | 상태 저장소 |
| 빨간 화살표 | 백엔드를 우회하는 데이터 경로 |

빨간 화살표가 핵심이다 — 미디어와 파일 바이트는 Spring을 통과하지 않지만, 그 앞에는 반드시 Spring이 발급한 증명(LiveKit JWT · presigned URL)이 있다.
