# 공개 페이지 — 웰컴 · 커리큘럼 목록 · 로그인 · 회원가입

> 원본: [../components/PUBLIC_PAGES.md](../components/PUBLIC_PAGES.md) · 로드맵: [00_ROADMAP.md](00_ROADMAP.md)

레이아웃: `PublicLayout` (헤더+본문+푸터) 공통 사용. 네 화면 모두 헤더·푸터 톤을 통일한다.

| 화면 | 라우트 | 접근 |
|---|---|---|
| 웰컴 | `/` | 전체 |
| 커리큘럼 목록 | `/curriculums` | 전체 |
| 로그인 | `/login` | 비로그인 |
| 회원가입 | `/signup` | 비로그인 |

---

## 1. 웰컴 (`/`)

### 목적
서비스 첫 진입점. 핵심 가치(실시간 수업·자막·AI 근거·따라잡기)를 소개하고 탐색·가입으로 유도한다.

### 화면 구성
```text
WelcomeHero            — 한 줄 소개 + 대표 CTA
FeatureHighlights       — 라이브 / 자막 / AI 근거 / 따라잡기 기능 소개 카드
FeaturedCurriculumSection — 추천 커리큘럼 카드 목록 + 전체 보기
RoleQuickActions        — 로그인 상태별 빠른 행동
```

### 역할별 `RoleQuickActions`
| 사용자 | 표시 |
|---|---|
| 비로그인 | 로그인, 회원가입 |
| 학생 | 내 커리큘럼, 최근 학습 이어보기 |
| 강사 | 커리큘럼 생성, 운영 중인 커리큘럼 |

### 상태
- 추천 커리큘럼: loading / 결과 없음 / 조회 실패(카드 영역만 실패 표시, 나머지 히어로·CTA는 유지) / success

### 다음 화면
커리큘럼 카드 → 커리큘럼 상세 · "전체 보기" → 커리큘럼 목록 · 로그인/회원가입 · (학생)내 커리큘럼 · (강사)커리큘럼 생성/내 커리큘럼

---

## 2. 커리큘럼 목록 (`/curriculums`)

### 목적
비로그인 포함 모든 사용자가 공개 커리큘럼을 검색·필터·정렬해 상세로 이동한다.

### 화면 구성
```text
CurriculumListHeader     — 페이지 제목·설명
CurriculumSearchControls — 검색 입력 + 필터 + 정렬
CurriculumResultSummary  — 검색 조건·결과 수 요약
CurriculumGrid           — CurriculumCard 반응형 그리드
```

### 커리큘럼 카드 — 관계별 표시
| 관계 | 카드 추가 정보 |
|---|---|
| 비로그인 | 상세 보기 |
| 학생·미수강 | 수강 가능 상태 |
| 수강생 | 학습 진행률 + 학습 계속하기 |
| 해당 커리큘럼 강사 | 관리하기 + 다음 레슨 |
| 다른 강사 | 상세 보기 + 수강 정책 안내 |

카드 공통 골격(대표 이미지·제목·강사·상태·주요 행동)은 웰컴 추천 카드, 내 커리큘럼 카드와 동일한 시각 언어를 사용한다.

### 상태
- 최초 로딩 / 조건 변경 후 로딩 / 검색 결과 없음(조건 초기화 유도) / 공개 커리큘럼 자체 없음(서비스 소개 유도) / 조회 실패+재시도 / success

### 다음 화면
카드 → 커리큘럼 상세 · 수강생 카드의 "학습 계속하기" → 레슨 상세 또는 라이브 세션 상세

## 3. 로그인 (`/login`)

### 목적
사용자를 인증하고, 인증이 필요해 로그인으로 이동했던 원래 목적지로 복귀시킨다.

### 화면 구성
```text
AuthPageIntro     — 화면 제목·안내
LoginForm
├─ UserIdField
├─ PasswordField
├─ LoginErrorMessage
└─ LoginSubmitButton
SignupLink        — 회원가입으로 이동
```

### 상태
- 기본 입력 / 클라이언트 입력 오류 / 제출 중 / 인증 실패(계정 없음·비밀번호 불일치 안내) / 성공 후 이동

### 다음 화면
성공 → 원래 목적지(없으면 역할별 기본 화면: 학생·강사 모두 웰컴 또는 내 커리큘럼) · SignupLink → 회원가입

---

## 4. 회원가입 (`/signup`)

### 목적
강사 또는 학생 유형을 선택해 계정을 생성한다.

### 화면 구성
```text
AuthPageIntro
AccountTypeSelector      — 강사 / 학생 선택
SignupForm
├─ CommonAccountFields    — 이름·아이디·비밀번호 등 공통 입력
├─ InstructorFields | StudentFields  — 유형별 전용 입력(확정된 경우만)
├─ TermsAgreement         — 약관 동의(확정된 경우만)
├─ SignupErrorMessage
└─ SignupSubmitButton
LoginLink
```

같은 폼을 강사·학생이 공유하고, 유형에 따라 일부 입력 영역만 추가되는 구조로 디자인한다(완전히 다른 두 폼이 아님).

### 상태
- 계정 유형 미선택 / 기본 입력 / 아이디 중복 확인 중·사용 가능·중복 / 입력 오류 / 제출 중 / 가입 실패 / 가입 완료

### 다음 화면
가입 완료 → 로그인(또는 자동 로그인 후 역할별 기본 화면) · LoginLink → 로그인

---

## 공통 미확정 표시 (참고용, 프로토타입에서는 임의로 확정해 디자인)
- 로그인·회원가입을 독립 페이지 대신 데스크톱 모달로 표시할 가능성 있음 — 프로토타입은 독립 페이지 기준으로 만들되 모달 변형 여지를 남긴다.
- 추천 커리큘럼 선정 기준, 목록 필터·정렬 항목, 강사/학생 전용 가입 필드는 미확정 — 프로토타입에서는 그럴듯한 예시값으로 채운다.
