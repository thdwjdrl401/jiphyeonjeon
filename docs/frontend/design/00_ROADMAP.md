## 2. 공통 레이아웃 셸

모든 화면은 아래 네 셸 중 하나를 사용한다. 각 셸의 시각적 골격은 프로토타입 전체에서 동일하게 유지한다.

### `PublicLayout` — 상단 GlobalHeader + 본문 + 하단 GlobalFooter
- 사용: 웰컴, 커리큘럼 목록, 로그인, 회원가입, 커리큘럼 상세
- 헤더: 비로그인은 로그인·회원가입 버튼 / 로그인 사용자는 내 커리큘럼·사용자 메뉴(+ 강사면 커리큘럼 생성)
- 모바일: 전역 메뉴를 drawer로 전환

### `WorkspaceLayout` — 상단 GlobalHeader + 좌측 WorkspaceSidebar + 본문(Breadcrumbs 포함)
- 사용: 내 프로필, 내 커리큘럼, 커리큘럼 생성/관리, 레슨 생성/수정/상세, 라이브 세션 생성/수정/상세/점검/처리 현황
- 사이드바 메뉴: 학생 — 내 커리큘럼·내 프로필 / 강사 — 내 커리큘럼·커리큘럼 생성·내 프로필(+ 해당 커리큘럼 강사만 관리 메뉴)
- 모바일: 사이드바를 작업 메뉴 drawer로 전환

### `LessonLayout` — 상단 헤더 + 주 콘텐츠(미디어) + 보조 패널 + 상태 영역
- 사용: 라이브 레슨, VOD 레슨
- 일반 footer·workspace sidebar 없음. 데스크톱은 미디어와 보조 패널을 나란히, 좁은 화면은 보조 패널을 탭/drawer로 전환

### `SystemLayout` — 브랜드 링크만 있는 최소 헤더 + 단순 본문
- 사용: 접근 불가, 찾을 수 없음
- 현재 상태: 별도 레이아웃 컴포넌트 없이 `ForbiddenPage`·`NotFoundPage`가 `system-page` 마크업으로 구현(`frontend/src/pages/`)

## 4. 역할·관계 축 (모든 화면 공통 전제)

프로토타입은 화면마다 아래 축의 조합으로 달라지는 상태를 함께 디자인해야 한다.

- **계정 유형**: 비로그인 / 학생 / 강사
- **커리큘럼과의 관계**: 해당 커리큘럼 강사 / 수강생 / 학생·미수강 / 수강 승인 대기 / 강사·비운영자 / 그 외
- **레슨 상태**: `DRAFT` → `AI_NOT_READY` → `READY` → `PUBLISHED`
- **라이브 세션 상태**: `DRAFT` → `SCHEDULED` → `OPEN` → `STARTING` → `LIVE` → `ENDING` → `ENDED` (또는 `CANCELLED` / `FAILED`)
- **녹화·다시보기 상태**: 자산 처리(`FINALIZING`~`READY`/`FAILED`) + 공개(`DRAFT`/`READY_FOR_REVIEW`/`PUBLISHED`/`WITHDRAWN`). 새 정상 경로는 `READY + PUBLISHED`를 원자적으로 확정

각 화면 문서의 "역할별 화면"은 이 축들의 조합 중 실제로 화면이 달라지는 지점만 정리한 것이다.

## 5. 공통 상태 어휘

모든 화면 문서에서 아래 다섯 가지 상태를 공통 어휘로 사용한다. 프로토타입에서 각 화면 최소 loading/empty/error/success 4종은 디자인한다.

| 상태 | 디자인 지침 |
|---|---|
| `loading` | 레이아웃을 유지하는 skeleton. 권한 확인 전에는 민감 버튼·패널을 먼저 노출하지 않음 |
| `empty` | 원인에 맞는 안내 + 대표 행동 1개(예: 검색 결과 없음 → 조건 초기화, 첫 데이터 없음 → 생성/탐색 유도) |
| `error` | 실패 원인(네트워크/권한/찾을 수 없음)을 구분해 표시, 재시도 행동 제공 |
| `partial` | 일부 영역만 실패해도 나머지 화면은 유지(예: AI 기능 장애가 영상·채팅을 막지 않음) |
| `success` | 정상 데이터 표시 |

## 6. 화면 간 이동 그래프

프로토타입에서 실제로 클릭 가능하게 연결해야 하는 주요 경로다. 각 화면 문서의 "다음 화면" 절에 더 세부적으로 반복 표기한다.

```text
웰컴 ──▶ 커리큘럼 목록 ──▶ 커리큘럼 상세 ──▶ (수강 신청 없음) 로그인/회원가입
웰컴/헤더 ──▶ 로그인 ⇄ 회원가입
로그인 성공 ──▶ 원래 목적지 복귀 (없으면 역할별 기본 화면)
헤더 사용자 메뉴 ──▶ 내 프로필 / 내 커리큘럼 / 로그아웃

내 커리큘럼(강사) ──▶ 커리큘럼 생성 ──▶ 커리큘럼 상세/관리
내 커리큘럼(강사) ──▶ 커리큘럼 관리 ──▶ 레슨 생성 ──▶ 레슨 상세
커리큘럼 관리 ──▶ 레슨 수정
커리큘럼 상세(강사) ──▶ 커리큘럼 관리
커리큘럼 상세(수강생) ──▶ 레슨 상세 / 라이브 세션 상세 / VOD 레슨

레슨 상세(강사, PUBLISHED, 세션 없음) ──▶ 라이브 세션 생성
레슨 상세 ──▶ 라이브 세션 상세
라이브 세션 상세(강사) ──▶ 사전 점검 ──▶ 라이브 레슨(강의실)
라이브 세션 상세(수강생) ──▶ 입장 전 점검 ──▶ 라이브 레슨(강의실)
강사 라이브 종료 성공 ──▶ 녹화 처리 현황(2초→5초 폴링)
녹화 처리 현황(자산 READY + replay PUBLISHED) ──▶ VOD 레슨(강사, 자동 이동)
수강생 라이브 종료 감지 ──▶ 현재 HLS 마지막 버퍼까지 재생(자동 이동 없음)
레슨 상세(다시보기 공개됨) ──▶ VOD 레슨

권한 부족 ──▶ 접근 불가
잘못된 경로/존재하지 않는 리소스 ──▶ 찾을 수 없음
```

## 7. 이 정제본에서 의도적으로 뺀 것

- 컴포넌트별 `소유 영역`(`features/*`, `pages`, `shared`) — 코드 구조이며 화면에 보이지 않음
- LiveKit/Egress/WebSocket/SSE 등 연동 프로토콜 세부, `sessionMs` 동기화 계산 로직
- 문서별 "미확정 사항" · "이후 기능 후보" 절 — 아직 정해지지 않았거나 범위 밖인 내용
- 정확한 API 필드명 — 화면에 표시되는 정보의 종류만 유지

## 8. 아직 없는 것 (Claude가 직접 정해야 함)

원본 명세에는 색상·타이포그래피·여백·톤앤매너 등 비주얼 디자인 언어가 전혀 정의되어 있지 않다. 프로토타입 생성 시 서비스 성격(실시간 강의 + AI 학습 보조)에 맞는 비주얼 시스템을 새로 제안해야 한다.
