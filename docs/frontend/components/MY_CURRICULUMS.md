# LiveClass AI — 내 커리큘럼 컴포넌트

> 컴포넌트 원칙: [README.md](README.md) · 공통 레이아웃: [COMMON.md](COMMON.md) · 페이지 기준: [PAGES.md](../PAGES.md)

## 1. 목적

내 커리큘럼은 로그인 사용자가 자신의 계정 유형에 맞는 커리큘럼과 다음 행동을 한곳에서 확인하는 개인 대시보드다.

- 강사: 운영하는 커리큘럼과 다음 운영 작업 확인
- 학생: 수강 중·수강 완료 커리큘럼과 다음 학습 확인

강사와 학생은 같은 라우트와 `WorkspaceLayout`을 사용하지만, 본문 대시보드는 계정 유형에 따라 다르게 조합한다.

## 2. 컴포넌트 트리

```text
MyCurriculumsPage
├─ MyCurriculumsHeader
└─ InstructorCurriculumDashboard | StudentLearningDashboard

InstructorCurriculumDashboard
├─ InstructorCurriculumSummary
├─ InstructorNextLesson
├─ InstructorCurriculumControls
└─ CurriculumGrid
   └─ CurriculumCard[]

StudentLearningDashboard
├─ StudentLearningSummary
├─ ContinueLearningSection
├─ StudentCurriculumControls
└─ CurriculumGrid
   └─ CurriculumCard[]
```

강사·학생 대시보드는 목적과 정보가 다르므로 본문 조합은 분리하되, 커리큘럼 요약 표시와 목록 배치는 공통 컴포넌트를 재사용한다.

## 3. 컴포넌트 책임

### 3.1 공통

| 컴포넌트 | 소유 영역 | 책임 |
|---|---|---|
| `MyCurriculumsPage` | `pages` | 계정 유형에 맞는 대시보드 선택과 페이지 상태 처리 |
| `MyCurriculumsHeader` | page 전용 | 페이지 제목과 계정 유형별 대표 행동 배치 |
| `CurriculumGrid` | `features/curriculum` | 커리큘럼 카드의 반응형 목록 배치 |
| `CurriculumCard` | `features/curriculum` | 공통 커리큘럼 정보와 사용 맥락별 요약 표시 |

### 3.2 강사

| 컴포넌트 | 소유 영역 | 책임 |
|---|---|---|
| `InstructorCurriculumDashboard` | page 조합 | 강사의 운영 정보와 목록 조합 |
| `InstructorCurriculumSummary` | `features/curriculum` | 운영 커리큘럼·예정 live session 등 핵심 수치 요약 |
| `InstructorNextLesson` | `features/lesson` | 가장 가까운 예정 또는 진행 중 레슨 안내 |
| `InstructorCurriculumControls` | `features/curriculum` | 검색·상태 필터·정렬 조합 |

### 3.3 학생

| 컴포넌트 | 소유 영역 | 책임 |
|---|---|---|
| `StudentLearningDashboard` | page 조합 | 학생의 학습 정보와 목록 조합 |
| `StudentLearningSummary` | `features/enrollment` | 수강·완료·예정 학습 정보 요약 |
| `ContinueLearningSection` | `features/enrollment` | 마지막으로 학습한 커리큘럼과 레슨 이어보기 |
| `StudentCurriculumControls` | `features/enrollment` | 검색·학습 상태 필터·정렬 조합 |

## 4. 공통 페이지 구성

### 4.1 `MyCurriculumsHeader`

**공통 표시**

- 내 커리큘럼 제목
- 현재 계정 유형에 맞는 짧은 안내

**강사 대표 행동**

- 커리큘럼 생성

**학생 대표 행동**

- 커리큘럼 탐색

### 4.2 검색·필터·정렬

강사와 학생은 목록을 탐색하는 목적이 다르므로 하나의 거대한 controls 컴포넌트로 합치지 않는다.

- 공통 검색 입력과 선택 UI는 `shared`에서 재사용 가능
- 상태 옵션과 필터 조합은 각 feature가 소유
- 검색·필터·정렬 상태는 URL query parameter에 보존하는 것을 우선 검토

## 5. 강사 대시보드

### 5.1 표시 정보

- 내가 생성하고 운영하는 커리큘럼
- 커리큘럼별 공개·모집·진행 상태
- 섹션·레슨 편성 현황
- 다음 예정 또는 현재 진행 중인 live session
- 수강생 수 또는 처리할 수강 신청이 도입되면 관련 요약

### 5.2 커리큘럼 카드

강사 맥락의 `CurriculumCard`에는 다음 정보를 우선한다.

- 커리큘럼 제목과 대표 이미지
- 운영 상태
- 섹션·레슨 수
- 다음 예정 live session의 일정과 상태
- 관리가 필요한 상태

**주요 행동**

- 커리큘럼 상세
- 커리큘럼 관리
- 다음 live session 상세·입장

카드에 모든 운영 기능을 넣지 않고, 대표 행동만 제공한 뒤 상세 관리 페이지로 연결한다.

### 5.3 상태 분류 후보

목록 탭 또는 필터는 실제 커리큘럼 상태가 확정된 뒤 정한다. 현재 후보는 다음과 같다.

- 준비 중
- 모집 중
- 진행 중
- 종료

이 명칭은 UI 후보이며 API 상태 계약이 아니다.

### 5.4 빈 상태

운영 중인 커리큘럼이 없으면 다음을 제공한다.

- 첫 커리큘럼 생성 안내
- 커리큘럼 생성으로 이동
- 서비스에서 강사가 할 수 있는 작업의 짧은 설명

검색·필터 결과가 비어 있는 경우에는 생성 CTA보다 조건 초기화를 우선한다.

## 6. 학생 대시보드

### 6.1 표시 정보

- 수강 중인 커리큘럼
- 종료되었거나 수강 완료한 커리큘럼
- 커리큘럼별 학습 진행률
- 마지막으로 학습한 레슨
- 다음 예정 live session

### 6.2 `ContinueLearningSection`

학생이 페이지에 진입했을 때 가장 먼저 이어갈 수 있는 학습을 보여준다.

- 최근 학습 커리큘럼과 레슨
- 마지막 재생 또는 학습 지점
- 이어보기 행동
- 최근 학습 정보가 없으면 영역을 숨기거나 다음 예정 live session으로 대체

이어보기 기준과 재생 위치 데이터는 레슨 명세 및 API 설계 단계에서 확정한다.

### 6.3 커리큘럼 카드

학생 맥락의 `CurriculumCard`에는 다음 정보를 우선한다.

- 커리큘럼 제목과 강사
- 진행 상태
- 완료 레슨 수와 전체 레슨 수
- 학습 진행률
- 다음 예정 또는 마지막 학습 레슨

**주요 행동**

- 학습 계속하기
- 커리큘럼 상세
- 진행 중인 live session 강의실 입장

### 6.4 상태 분류 후보

목록 탭 또는 필터 후보는 다음과 같다.

- 수강 예정
- 수강 중
- 수강 완료

수강 완료의 판정 기준이 확정되기 전까지 UI와 API 상태로 고정하지 않는다.

### 6.5 빈 상태

수강 중인 커리큘럼이 없으면 다음을 제공한다.

- 커리큘럼 탐색 안내
- 커리큘럼 목록으로 이동

검색·필터 결과가 비어 있는 경우에는 조건 초기화를 우선한다.

## 7. `CurriculumCard` 재사용 기준

웰컴, 커리큘럼 목록, 내 커리큘럼에서 기본 카드 골격은 재사용한다.

### 7.1 공통 골격

- 대표 이미지
- 제목
- 강사 또는 운영 정보
- 커리큘럼 상태
- 주요 행동

### 7.2 맥락별 차이

| 사용 맥락 | 추가 정보 |
|---|---|
| 웰컴 | 추천 이유 또는 짧은 소개 |
| 공개 목록 | 수강 가능 상태와 기본 메타데이터 |
| 강사 대시보드 | 운영 상태와 다음 레슨 |
| 학생 대시보드 | 학습 진행률과 이어보기 |

하나의 카드에 다수의 boolean props를 추가하기보다 명확한 표시 맥락을 전달하거나, 공통 카드 골격에 맥락별 보조 영역을 조합한다. 정확한 props는 구현 시 TypeScript로 정의한다.

## 8. 페이지 상태

### 8.1 로딩

- 계정 유형 확인 전 강사·학생 대시보드를 먼저 노출하지 않음
- 요약 영역과 커리큘럼 카드 skeleton 표시

### 8.2 정상

- 계정 유형에 맞는 요약·대표 행동·목록 표시
- 다음 레슨이나 최근 학습 데이터가 없어도 전체 목록은 유지

### 8.3 빈 상태

- 강사: 첫 커리큘럼 생성 안내
- 학생: 커리큘럼 탐색 안내
- 필터 결과 없음: 현재 조건 초기화

### 8.4 조회 실패

- 목록 조회 실패와 요약 영역 일부 실패를 구분
- 가능한 영역은 유지하고 실패한 영역에 재시도 제공

### 8.5 인증 만료

- 로그인으로 이동
- 다시 로그인한 후 내 커리큘럼으로 복귀

## 9. 주요 사용자 행동

### 9.1 강사

- 커리큘럼 생성
- 커리큘럼 검색·필터·정렬
- 커리큘럼 상세·관리 이동
- 다음 live session 상세·입장

### 9.2 학생

- 수강 커리큘럼 검색·필터·정렬
- 마지막 학습 이어보기
- 커리큘럼 상세 이동
- 다음 live session 상세·입장
- 새 커리큘럼 탐색

## 10. 필요한 데이터

실제 필드와 API는 [API_MAP.md](../api/API_MAP.md)에서 확정한다.

### 10.1 공통

- 현재 사용자 계정 유형
- 검색·필터·정렬·페이지 상태

### 10.2 강사

- 운영 커리큘럼 요약 목록
- 커리큘럼별 운영 상태
- 섹션·레슨 수
- 다음 예정·진행 중 live session의 `sessionId`·lesson 요약
- 도입 시 수강생 및 승인 대기 요약

### 10.3 학생

- 수강 커리큘럼 요약 목록
- 커리큘럼별 학습 진행 정보
- 마지막 학습 레슨과 이어보기 지점
- 다음 예정·진행 중 live session의 `sessionId`·lesson 요약

## 11. 미확정 사항

1. 강사 계정이 다른 커리큘럼을 수강할 수 있는 경우 한 페이지에서 운영·수강 목록을 어떻게 구분할지
2. 강사·학생 목록의 확정 상태와 탭 구성
3. 수강 완료 판정 기준
4. 커리큘럼 카드에 표시할 수강생 수와 운영 지표 범위
5. 다음 live session과 최근 학습 중 어떤 정보를 상단에서 우선할지
6. 페이지네이션과 무한 스크롤 중 선택
7. 검색·필터 상태를 URL에 보존할 범위
8. 최근 학습 레슨이 여러 개일 때 하나만 보여줄지 목록으로 제공할지

## 12. 이후 확인할 기능 후보

- 학생의 찜한 커리큘럼
- 학습 목표 또는 주간 학습량 요약
- 강사의 처리 대기 수강 신청 알림
- 강사의 커리큘럼별 간단 통계
- 커리큘럼 카드 빠른 메뉴

후보 기능은 채택되기 전까지 필수 컴포넌트나 API로 간주하지 않는다.
