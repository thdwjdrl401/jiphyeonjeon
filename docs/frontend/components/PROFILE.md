# LiveClass AI — 내 프로필 컴포넌트

> 컴포넌트 원칙: [README.md](README.md) · 공통 레이아웃: [COMMON.md](COMMON.md) · 페이지 기준: [PAGES.md](../PAGES.md)

## 1. 목적

내 프로필은 로그인 사용자가 자신의 계정 정보와 가입 유형을 확인하고, 수정 가능한 프로필 정보를 관리하는 개인 설정 페이지다.

- 강사: 수강생에게 공개할 소개와 전문 분야 관리
- 학생: 기본 계정 정보와 학습 요약 확인

계정 유형 변경, 커리큘럼 운영·수강 목록, 상세 학습 분석은 이 페이지에서 처리하지 않는다.

> **구현 현황(2026-07)**: `displayName`(공통 프로필)·`bio`/`expertise`(강사 공개 프로필) 편집 폼은 **백엔드가 아직 없다 — 준비 중**(`ProfileEditForm`, `InstructorPublicProfileForm`은 저장 API 대기). 반대로 **프로필 이미지 지정은 백엔드가 구현되어 있으나**(`PUT /api/me/profile-image {assetId}`, 결과는 `/auth/me`의 `profileImageUrl`) **아직 FE UI가 없다**. 현재 조회 가능한 사용자 정보는 `GET /api/auth/me`(`userId`·`email`·`displayName`·`role`·`profileImageUrl`)뿐이다. 인증 식별자는 `email`이다.

## 2. 컴포넌트 트리

```text
ProfilePage
└─ WorkspaceLayout
   ├─ ProfileHeader
   ├─ AccountIdentitySection
   │  ├─ AccountIdentitySummary
   │  └─ AccountTypeBadge
   ├─ ProfileEditSection
   │  └─ ProfileEditForm
   ├─ InstructorPublicProfileSection    강사만
   │  └─ InstructorPublicProfileForm
   ├─ StudentProfileSummary             학생만
   ├─ AccountSecuritySection
   │  └─ PasswordChangeEntry
   ├─ SessionActions
   └─ AccountDangerZone
      └─ AccountDeletionEntry
```

강사·학생이 같은 페이지와 공통 계정 영역을 사용한다. 역할별 입력을 하나의 거대한 폼에 boolean 조건으로 섞지 않고 별도 영역으로 조합한다.

## 3. 컴포넌트 책임

| 컴포넌트 | 소유 영역 | 책임 |
|---|---|---|
| `ProfilePage` | `pages` | 인증 사용자 조회, 역할별 프로필 영역과 페이지 상태 조합 |
| `ProfileHeader` | page 전용 | 페이지 제목과 짧은 안내 표시 |
| `AccountIdentitySection` | `features/profile` | 계정 식별 정보와 가입 유형 조합 |
| `AccountIdentitySummary` | `features/profile` | 아이디·이름 등 계정 기본 정보 표시 |
| `AccountTypeBadge` | `features/auth` | 강사·학생 가입 유형을 읽기 전용으로 표시 |
| `ProfileEditForm` | `features/profile` | 공통 수정 가능 정보의 입력·검증·저장 |
| `InstructorPublicProfileSection` | `features/profile` | 강사 공개 프로필 설명과 미리보기 조합 |
| `InstructorPublicProfileForm` | `features/profile` | 공개 소개·전문 분야 입력·저장 |
| `StudentProfileSummary` | `features/learning` | 수강·완료·다음 학습의 간단한 요약과 이동 |
| `AccountSecuritySection` | `features/auth` | 비밀번호 변경 등 보안 설정 진입 |
| `SessionActions` | `features/auth` | 로그아웃 행동 제공 |
| `AccountDangerZone` | `features/account` | 회원 탈퇴 진입과 영향 안내 분리 |

## 4. 접근 권한

- 로그인 사용자만 접근
- 현재 로그인한 본인의 프로필만 조회·수정
- URL이나 입력값으로 다른 사용자 프로필을 선택하지 않음
- 인증 확인 전 프로필 데이터를 먼저 노출하지 않음
- 인증 만료 시 로그인으로 이동하고 성공 후 프로필로 복귀
- 모든 수정 요청은 서버에서 본인 여부를 다시 검증

다른 사용자가 보는 공개 강사 프로필 페이지가 필요해지면 별도 공개 페이지로 분리한다.

## 5. 공통 계정 영역

### 5.1 읽기 전용

- 계정 아이디
- 강사 또는 학생 가입 유형
- 가입 유형에 따라 제공되는 주요 기능 안내

계정 아이디와 가입 유형은 초기 범위에서 변경할 수 없다.

### 5.2 수정 가능

- 사용자 이름 또는 표시 이름 (**수정 API 미구현 — 준비 중**)
- 실제 회원가입 계약에 포함된 수정 가능한 공통 프로필 정보

이메일·전화번호는 계정 계약이 확정되기 전까지 필수 필드로 추가하지 않는다. 프로필 이미지는 지정 API(`PUT /api/me/profile-image`)가 이미 구현되어 있으나 이 폼에 연결하는 FE UI는 아직 없다.

### 5.3 저장 원칙

- 공통 프로필과 강사 공개 프로필은 저장 상태를 분리
- 변경이 없으면 저장 행동 비활성화
- 저장 중 중복 제출 방지
- 저장 실패 시 입력값 유지와 필드·폼 오류 표시
- 페이지 이탈 시 저장되지 않은 변경 안내

## 6. 강사 공개 프로필

강사 계정에만 다음 영역을 제공한다.

- 공개 소개
- 전문 분야
- 수강생에게 표시될 내용의 간단한 미리보기
- 운영 중인 커리큘럼으로 이동

운영 커리큘럼 전체 목록과 통계는 [MY_CURRICULUMS.md](MY_CURRICULUMS.md)에서 제공하고 이 페이지에 중복 구현하지 않는다.

소개·전문 분야의 길이와 입력 형식은 API 계약에서 확정한다. 공개 프로필을 저장하기 전 개인정보가 포함되지 않도록 짧은 안내를 제공한다.

## 7. 학생 프로필 요약

학생 계정에는 편집 필드 대신 다음 학습 요약을 제공한다.

- 수강 중인 커리큘럼 수
- 완료한 커리큘럼 또는 레슨 요약
- 다음 예정 live session
- 내 커리큘럼으로 이동

관심 분야와 추천 설정은 추천 기능이 실제로 도입될 때 추가한다. 상세 진행률과 최근 학습 목록은 [MY_CURRICULUMS.md](MY_CURRICULUMS.md)에서 제공한다.

## 8. 계정 유형

- 회원가입 때 선택한 강사·학생 유형을 읽기 전용으로 표시
- 프로필에서 계정 유형 변경 기능을 제공하지 않음
- 역할 전환이 필요해지면 데이터·권한 이전 정책을 먼저 정의
- 강사 계정이 다른 커리큘럼을 수강하는 정책과 계정 유형 자체 변경을 구분

## 9. 보안과 세션 행동

### 9.1 비밀번호 변경

- 별도 폼이나 별도 보안 페이지로 진입
- 현재 비밀번호 확인이 필요한 정책을 서버 계약에서 정의
- 비밀번호 입력값을 프로필 일반 폼 상태와 섞지 않음
- 성공 후 다른 세션을 종료할지 여부는 인증 정책에서 결정

초기 API 범위에 비밀번호 변경이 없다면 `PasswordChangeEntry`를 노출하지 않는다.

### 9.2 로그아웃

- 전역 사용자 메뉴와 같은 로그아웃 feature 재사용
- 처리 중 중복 실행 방지
- 성공 후 웰컴 또는 로그인으로 이동
- 로그아웃 실패 시 현재 페이지에서 재시도

## 10. 회원 탈퇴

- 일반 저장 행동과 시각적으로 분리된 위험 영역에 배치
- 영향 안내와 명시적 재확인 제공
- 강사는 운영 중인 커리큘럼·예정 라이브가 있으면 탈퇴 제한 가능
- 학생은 진행 중인 수강·학습 기록 처리 정책 안내 필요
- 탈퇴 완료 후 세션 제거와 웰컴 이동

실제 삭제·보존·복구 정책이 확정되기 전에는 탈퇴 진입점만 두거나 기능을 비활성화한다. 프론트에서 단순 확인만으로 계정을 즉시 삭제하지 않는다.

## 11. 페이지 상태

### 11.1 초기 로딩

- 인증 사용자와 역할 확인
- 계정·프로필 영역 skeleton 표시
- 역할 확인 전 강사·학생 전용 영역을 먼저 노출하지 않음

### 11.2 정상

- 공통 계정 정보와 역할별 영역 표시
- 각 저장 영역의 변경·저장 상태를 독립적으로 관리

### 11.3 저장 중·성공

- 실행한 폼만 저장 중 표시
- 저장 완료 후 서버 결과로 화면 갱신
- 성공 메시지는 해당 영역 가까이에 제공

### 11.4 저장 실패

- 필드 검증 오류와 일반 요청 실패 구분
- 입력값 유지
- 인증 만료면 로그인 복귀 흐름으로 전환

### 11.5 일부 조회 실패

- 기본 계정 정보가 성공하면 역할별 학습·커리큘럼 요약 실패가 전체 페이지를 막지 않음
- 실패한 보조 영역에 재시도 제공

## 12. 주요 사용자 행동

### 12.1 공통

- 계정 정보와 가입 유형 확인
- 수정 가능한 공통 프로필 저장
- 비밀번호 변경 진입
- 로그아웃
- 회원 탈퇴 정책 확인·진입

### 12.2 강사

- 공개 소개·전문 분야 저장
- 공개 프로필 미리보기
- 운영 커리큘럼으로 이동

### 12.3 학생

- 학습 요약 확인
- 내 커리큘럼으로 이동

## 13. 필요한 데이터

정확한 필드와 API는 [API_MAP.md](../API_MAP.md)에서 확정한다.

- 현재 인증 사용자
- 계정 아이디와 가입 유형
- 공통 프로필 정보와 수정 가능 필드
- 강사 공개 소개·전문 분야
- 강사의 운영 커리큘럼 요약
- 학생의 수강·완료·다음 레슨 요약
- 각 계정 행동의 허용 여부와 제한 사유

## 14. 반응형과 접근성

- 모바일에서는 공통 계정·역할별 프로필·보안·위험 영역 순서 유지
- 읽기 전용 값과 입력 필드를 시각적으로 구분
- 저장 성공·실패 메시지를 해당 폼과 연결
- 오류 발생 시 첫 오류 필드로 이동하거나 오류 요약에서 연결
- 회원 탈퇴 확인 대화상자의 포커스 이동·가두기·복귀 처리
- 계정 유형을 색상만으로 구분하지 않음

## 15. 미확정 사항

1. 공통 프로필의 실제 수정 가능 필드
2. 강사 공개 소개·전문 분야의 입력 형식과 최대 길이
3. 비밀번호 변경과 다른 세션 종료 정책
4. 회원 탈퇴 시 커리큘럼·수강·학습 데이터 처리 정책
5. 공개 강사 프로필 상세 페이지 도입 여부

## 16. 이후 기능 후보

- 프로필 이미지 FE UI (백엔드 `PUT /api/me/profile-image`는 이미 구현됨 — FE UI만 없음)
- 이메일·전화번호 인증과 변경
- 학생 관심 분야·추천 설정
- 공개 강사 프로필 페이지
- 전체 세션 조회·강제 로그아웃
- 계정 유형 전환 정책

후보 기능은 채택되기 전까지 필수 컴포넌트나 API로 간주하지 않는다.
