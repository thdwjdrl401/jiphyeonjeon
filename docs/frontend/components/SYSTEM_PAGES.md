# LiveClass AI — 시스템 페이지 컴포넌트

> 컴포넌트 원칙: [README.md](README.md) · 공통 레이아웃: [COMMON.md](COMMON.md) · 페이지 기준: [PAGES.md](../PAGES.md)

## 1. 범위

`SystemLayout`을 사용하는 다음 두 페이지를 함께 정의한다.

현재 상태: `SystemLayout`·`SystemPage`·`SystemMessagePanel` 컴포넌트는 없다. `ForbiddenPage`·`NotFoundPage`가 `BrandLink`와 `system-page` 마크업을 직접 조합한다(`frontend/src/pages/`).

- 접근 불가
- 찾을 수 없음

두 페이지는 원인을 설명하고 사용자가 안전한 경로로 복구하도록 돕는다. 서버 오류 세부 정보나 권한이 없는 리소스의 존재 여부를 노출하지 않는다.

## 2. 공통 구성 원칙

- 브랜드 링크와 단순한 본문만 제공
- 오류 코드보다 사용자가 이해할 수 있는 원인과 다음 행동을 우선
- 대표 복구 행동 하나와 필요한 보조 행동만 제공
- 브라우저 뒤로 가기를 유일한 복구 방법으로 사용하지 않음
- 인증 상태와 실패 원인에 따라 복구 목적지를 변경
- 개발용 오류 메시지·스택·리소스 내부 식별자를 노출하지 않음
- 접근할 수 없는 보호 리소스는 필요하면 존재하지 않는 것처럼 처리

## 3. 공통 컴포넌트

```text
SystemPage
└─ SystemLayout
   └─ SystemMessagePanel
      ├─ SystemStatusIcon
      ├─ SystemStatusTitle
      ├─ SystemStatusDescription
      ├─ SystemPrimaryAction
      ├─ SystemSecondaryActions
      └─ SupportReference              필요한 경우만
```

| 컴포넌트 | 소유 영역 | 책임 |
|---|---|---|
| `SystemLayout` | `app` | 브랜드 링크와 단순한 본문 배치 |
| `SystemMessagePanel` | `shared` | 상태 제목·설명·행동의 공통 골격 |
| `SystemStatusIcon` | `shared` | 장식 또는 상태 의미를 보조하는 아이콘 |
| `SystemPrimaryAction` | page 조합 | 현재 원인에 가장 적합한 복구 행동 선택 |
| `SystemSecondaryActions` | page 조합 | 웰컴·내 커리큘럼·이전 화면 등 보조 동선 |
| `SupportReference` | `shared` | 문의 시 사용할 비민감 추적 식별자 표시 |

오류 원인 판정과 복구 행동 선택은 공통 패널이 아니라 각 페이지가 담당한다.

## 4. 접근 불가 페이지

### 4.1 목적

인증된 사용자가 현재 리소스나 행동에 필요한 권한이 없을 때 원인과 복구 동선을 안내한다.

비로그인 `401`은 원칙적으로 이 페이지를 거치지 않고 로그인으로 이동한다. 인증 후에도 권한이 없는 `403`을 접근 불가 페이지가 담당한다.

### 4.2 컴포넌트 트리

```text
ForbiddenPage
└─ SystemMessagePanel
   ├─ ForbiddenMessage
   ├─ ForbiddenPrimaryAction
   └─ ForbiddenSecondaryActions
```

### 4.3 원인별 복구 행동

| 원인 | 대표 행동 | 보조 행동 |
|---|---|---|
| 비로그인 | 로그인 후 원래 목적지 복귀 | 웰컴 |
| 학생·미수강 | 커리큘럼 상세에서 수강 확인 | 내 커리큘럼 |
| 수강 승인 대기 | 커리큘럼 상세에서 상태 확인 | 내 커리큘럼 |
| 강사 전용 기능 | 내 커리큘럼 | 커리큘럼 목록 |
| 다른 강사의 관리 리소스 | 내 커리큘럼 | 웰컴 |
| 권한 회수·수강 종료 | 커리큘럼 상세 | 내 커리큘럼 |

비로그인 항목은 로그인 리다이렉트가 실패하거나 사용자가 접근 불가 화면에 직접 도달한 경우를 위한 보조 처리다.

### 4.4 표시 원칙

- 계정 유형만으로 실패 원인을 추론하지 않음
- 서버 또는 라우트 가드가 정규화한 실패 사유 사용
- 다른 강사의 커리큘럼 이름·수강생·자료 등 보호 정보 비노출
- 수강 신청이 가능한 경우에만 수강 동선 제공
- 권한이 회수된 이유가 공개 가능한 범위에서만 설명
- 원래 목적지는 안전한 내부 경로만 보존

## 5. 찾을 수 없음 페이지

### 5.1 목적

라우트가 존재하지 않거나 사용자가 요청한 커리큘럼·섹션·레슨·라이브 세션을 찾을 수 없을 때 안전한 탐색 경로를 제공한다.

### 5.2 컴포넌트 트리

```text
NotFoundPage
└─ SystemMessagePanel
   ├─ NotFoundMessage
   ├─ NotFoundPrimaryAction
   └─ NotFoundSecondaryActions
```

### 5.3 표시 원칙

- 잘못된 URL과 삭제·비공개·권한 없는 보호 리소스를 필요하면 같은 일반 문구로 처리
- 리소스가 존재했는지 또는 누가 소유했는지 노출하지 않음
- 사용자가 입력한 URL을 HTML로 다시 출력하지 않음
- 자동으로 다른 페이지로 이동하지 않음
- 검색 입력은 초기 범위에서 추가하지 않고 커리큘럼 목록으로 연결

### 5.4 인증 상태별 행동

| 사용자 | 대표 행동 | 보조 행동 |
|---|---|---|
| 비로그인 | 웰컴 | 커리큘럼 목록 |
| 학생 | 내 커리큘럼 | 커리큘럼 목록 |
| 강사 | 내 커리큘럼 | 커리큘럼 목록 |

브라우저 히스토리가 안전하게 존재하면 `이전 페이지`를 보조 행동으로 추가할 수 있다.

## 6. 인증·라우팅 처리

### 6.1 `401`

- 현재 내부 경로를 `returnTo`로 보존
- 로그인으로 이동
- 로그인 성공 후 원래 목적지를 다시 요청
- 다시 `403`이면 접근 불가 페이지 표시
- 외부 URL이나 검증되지 않은 경로를 복귀 경로로 사용하지 않음

### 6.2 `403`

- 인증 상태를 유지
- 서버의 정규화된 사유에 맞는 접근 불가 안내
- 권한 변경으로 재시도 가능하면 원래 리소스 재조회 제공 가능

### 6.3 `404`

- 라우트 자체가 없으면 찾을 수 없음 페이지
- API 리소스가 없으면 동일 페이지 또는 현재 페이지의 리소스 없음 상태
- 보호 정보 노출을 막기 위해 서버가 `404`로 응답한 경우 일반 안내 사용

## 7. 상태와 실패 처리

### 7.1 정상 표시

- 상태 제목·설명·대표 행동 표시
- 인증 상태를 확인할 수 있으면 역할에 맞는 복구 행동 제공

### 7.2 인증 확인 중

- 잘못된 역할별 행동을 먼저 표시하지 않음
- 짧은 상태 확인 후 공통 복구 행동 또는 역할별 행동 선택

### 7.3 복구 행동 실패

- 같은 페이지에서 다시 시도할 수 있는 행동 제공
- 5xx·네트워크 장애를 권한 없음이나 찾을 수 없음으로 오인하지 않음
- 서비스 장애 페이지가 필요해지면 별도 문서와 라우트로 분리

## 8. 주요 사용자 행동

### 8.1 접근 불가

- 로그인
- 커리큘럼 상세에서 수강·승인 상태 확인
- 내 커리큘럼 이동
- 커리큘럼 목록 또는 웰컴 이동

### 8.2 찾을 수 없음

- 웰컴 이동
- 내 커리큘럼 이동
- 커리큘럼 목록 이동
- 안전한 경우 이전 페이지 이동

## 9. 필요한 데이터

정확한 사유 코드와 전환 규칙은 [API_MAP.md](../api/API_MAP.md)에서 확정한다.

- 현재 인증 상태와 계정 유형
- 정규화된 접근 실패 사유
- 안전하게 검증된 원래 목적지
- 수강 신청·승인 상태처럼 복구 행동에 필요한 최소 정보
- 문의에 사용할 수 있는 비민감 추적 식별자

페이지는 오류 응답 전체나 서버 메시지를 그대로 렌더링하지 않는다.

## 10. 반응형과 접근성

- 제목은 한 페이지에 하나의 명확한 `h1` 사용
- 상태 아이콘에만 의미를 의존하지 않음
- 대표 행동에 초기 포커스를 강제로 이동하지 않음
- 오류 설명과 복구 행동을 읽기 순서대로 배치
- 장식 아이콘은 보조기기에서 숨김
- 문의 식별자는 복사 가능하되 사용자·리소스 민감 정보 제외

## 11. 미확정 사항

1. 서버가 제공할 정규화된 접근 실패 사유 코드
2. 문의 채널과 추적 식별자 표시 여부
3. 권한이 없는 보호 리소스를 `403`과 `404` 중 어떤 기준으로 응답할지
4. 공통 서비스 장애 페이지 추가 여부

## 12. 이후 기능 후보

- 서비스 장애·점검 페이지
- 권한 요청 흐름
- 접근 실패 문의 연결
- 찾을 수 없음 페이지의 커리큘럼 검색

후보 기능은 채택되기 전까지 필수 컴포넌트나 API로 간주하지 않는다.
