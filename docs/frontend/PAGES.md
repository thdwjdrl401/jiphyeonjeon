# LiveClass AI — 프론트엔드 페이지·컴포넌트·API 맵

> 정본 아키텍처: [architecture.md](../architecture.md) · 공유 계약: [CONTRACT.md](../CONTRACT.md)
>
> 이 문서는 프론트엔드 관점에서 **페이지 → 컴포넌트 → 사용자 행동 → 연동**을 단계적으로 구체화한다. 시스템 구조와 공유 계약을 새로 정의하지 않으며, 확정된 계약은 `CONTRACT.md`를 따른다.

## 1. 현재 작성 범위

이번 초안은 **페이지와 라우팅 경계만** 다룬다. 페이지별 컴포넌트, REST API, WebSocket 이벤트, LiveKit/HLS 연동은 페이지 구성을 검토한 뒤 후속 단계에서 작성한다.

라우트는 프론트엔드 설계를 위한 제안이며 아직 공유 계약이 아니다.

## 2. 용어와 접근 권한

### 2.1 콘텐츠 구조

콘텐츠는 인프런·Udemy와 유사하게 다음 계층으로 구성한다.

```text
커리큘럼
└─ 섹션
   └─ 레슨
      └─ 라이브 세션
```

- **커리큘럼(`curriculum`)**: 사용자가 탐색하고 수강하는 최상위 단위
- **섹션(`section`)**: 커리큘럼 안에서 관련 레슨을 순서대로 묶는 단위
- **레슨(`lesson`)**: 실제 라이브 수업 및 종료 후 VOD가 되는 최소 학습 단위
- **라이브 세션(`liveSession`)**: 레슨의 일정·입장·진행·종료를 관리하는 실제 라이브 인스턴스
- 레슨은 반드시 특정 섹션에, 섹션은 반드시 특정 커리큘럼에 속한다.
- MVP에서는 레슨과 라이브 세션을 1:1로 제한하지만 별도 ID와 생명주기를 사용한다.
- 다시보기는 라이브 세션의 Egress 자산에서 생성되며 레슨의 학습 콘텐츠로 제공한다.

### 2.2 사용자 용어

- **강사(`instructor`)**: 강사 유형으로 가입한 사용자. 커리큘럼을 생성할 수 있다.
- **학생(`student`)**: 학생 유형으로 가입한 사용자. 커리큘럼에 수강 신청할 수 있다.
- **수강생(`enrollee`)**: 특정 커리큘럼에 참가한 학생을 해당 커리큘럼의 문맥에서 부르는 명칭
- **그 외 사용자**: 해당 커리큘럼의 강사도 수강생도 아닌 비로그인 사용자 또는 로그인 사용자
- `admin`은 현재 페이지 설계 범위에서 제외하고 추후 별도로 고려한다.

### 2.3 접근 권한 기준

- 비로그인 사용자는 웰컴, 커리큘럼 목록, 커리큘럼 상세, 로그인, 회원가입에 접근할 수 있다.
- 로그인 사용자는 가입 시 선택한 강사 또는 학생 유형을 가진다.
- 강사만 커리큘럼을 생성할 수 있다.
- 해당 커리큘럼을 운영하는 강사만 커리큘럼 관리와 내부 콘텐츠 편집에 접근한다.
- 학생은 커리큘럼에 참가한 뒤 해당 커리큘럼의 수강생이 된다.
- 레슨 상세·라이브·VOD 접근 여부는 커리큘럼 수강 상태를 기준으로 판단한다.

## 3. 페이지 분리 원칙

- 탐색의 첫 진입점인 웰컴 페이지와 실제 커리큘럼 목록을 분리한다.
- 사용자는 개별 레슨이 아니라 커리큘럼 단위로 참가한다.
- 섹션은 독립적인 학습 페이지보다 커리큘럼 상세의 목차 및 커리큘럼 관리의 편성 단위로 사용한다.
- 커리큘럼 상세는 모두에게 공개하되, 커리큘럼 강사·수강생·그 외 사용자에 따라 행동과 정보를 다르게 노출한다.
- 레슨 상세, 라이브 세션 상세·점검, 라이브 강의실, VOD 재생은 사용자 목적과 화면 수명주기가 달라 별도 페이지로 분리한다.
- 레슨 준비 상태, 라이브 상태, 다시보기 상태를 서로 다른 축으로 관리하고 조합해 진입 가능한 페이지와 행동을 결정한다.
- 인증이 필요한 페이지는 로그인 후 원래 목적지로 돌아올 수 있어야 한다.
- 로그인·회원가입은 독립 URL을 제공하되, 데스크톱에서는 모달 형태로 표시할 수 있다.

### 3.1 상태 모델

서로 다른 관심사를 하나의 `status`로 합치지 않는다.

| 상태 축 | 값 | 의미 |
|---|---|---|
| 레슨 | `DRAFT` | 레슨 기본 정보 작성 중 |
| 레슨 | `AI_NOT_READY` | 필수 PPTX 또는 AI 처리가 준비되지 않음 |
| 레슨 | `READY` | 필수 자료·AI 처리가 완료되어 강사 게시 가능 |
| 레슨 | `PUBLISHED` | 강사가 공식 게시하여 수강생에게 노출 가능 |
| AI 처리 | `NOT_STARTED`·`PROCESSING`·`READY`·`FAILED` | 대기·처리 중·완료·실패 UI 구분 |
| 라이브 세션 | `DRAFT`·`SCHEDULED`·`OPEN`·`STARTING`·`LIVE`·`ENDING`·`ENDED`·`CANCELLED`·`FAILED` | 일정 작성부터 종료까지의 실제 세션 상태 |
| 녹화 자산 | `REQUESTED`·`STARTING`·`RECORDING`·`FINALIZING`·`VERIFYING`·`READY`·`FAILED` | Egress 요청부터 HLS 검증까지의 기술 상태 |
| 다시보기 공개 | `DRAFT`·`READY_FOR_REVIEW`·`PUBLISHED`·`WITHDRAWN` | 강사 검수 가능 여부와 수강생 공개 여부 구분 |

- 레슨 `PUBLISHED`를 라이브 진행·종료 상태로 사용하지 않는다.
- `isPublished` 같은 별도 boolean을 두지 않고 레슨의 공식 공개 여부는 `lessonStatus=PUBLISHED`로 판단한다.
- 라이브 시작은 레슨 `PUBLISHED`, 필수 PPTX 존재, AI 준비 완료, 진행 중인 자료 작업 없음, 라이브 세션 `SCHEDULED` 또는 `OPEN`, 사전 점검 통과를 모두 요구한다.
- `AI_NOT_READY`에서는 라이브 시작을 허용하지 않는다.
- PPTX 자료는 레슨 전부터 수강생에게 공개한다.
- 라이브 종료 직후에는 `liveSessionStatus=ENDED`, `videoAssetStatus=FINALIZING`일 수 있다.
- Egress HLS 검증이 끝나 `videoAssetStatus=READY`가 되면 강사 미리보기·검수를 허용한다.
- 수강생 다시보기는 `videoAssetStatus=READY`와 `replayStatus=PUBLISHED`를 모두 만족할 때만 허용한다.
- VOD는 라이브 레슨의 Egress 녹화 결과로만 생성하며 영상 파일 업로드는 제공하지 않는다.
- AI 처리 실패는 라이브 영상·채팅 장애와 구분해서 표시한다.

## 5. 페이지별 역할

권한별 차이가 있는 페이지는 별도 페이지를 복제하지 않고 **공통 페이지 골격 + 관계별 조건부 컴포넌트**로 구성한다. 프론트엔드는 계정 유형만으로 권한을 추론하지 않고, 현재 사용자와 대상 커리큘럼의 관계 및 서버가 제공하는 허용 행동을 기준으로 컴포넌트를 노출한다.

### 5.1 웰컴

서비스의 첫 진입점으로, 제품의 핵심 가치와 대표 커리큘럼을 소개한다.

- LiveClass AI 서비스 소개
- 실시간 수업·자막·AI 근거 설명·따라잡기 핵심 기능 안내
- 추천 또는 인기 커리큘럼 일부 노출
- 전체 커리큘럼 탐색으로 이동

**사용자별 조건부 구성**

| 사용자 | 추가로 노출할 컴포넌트 |
|---|---|
| 비로그인 | 로그인·회원가입 CTA |
| 학생 | 내 커리큘럼, 최근 학습, VOD 이어보기 |
| 강사 | 커리큘럼 생성, 운영 중인 커리큘럼, 다음 live session |

### 5.2 커리큘럼 목록

비로그인 사용자를 포함한 모든 사용자가 공개 커리큘럼을 탐색하는 페이지다.

- 모집 중·진행 중·종료된 커리큘럼 탐색
- 주제·강사·진행 상태 기준 검색·필터·정렬
- 커리큘럼별 섹션·레슨 수와 전체 진행 기간 확인
- 검색 결과에서 커리큘럼 상세로 이동

목록 골격과 카드 컴포넌트는 공통으로 유지하고, 현재 사용자와 각 커리큘럼의 관계에 따라 카드 상태와 CTA를 변경한다.

| 관계 | 카드에 추가로 노출할 내용 |
|---|---|
| 비로그인 | 상세 보기 |
| 학생·미수강 | 수강 가능 상태와 상세 보기 |
| 수강생 | 학습 진행률과 학습 계속하기 |
| 해당 커리큘럼 강사 | 관리하기와 다음 예정 live session |
| 다른 커리큘럼의 강사 | 상세 보기와 수강 정책 안내 |

### 5.3 로그인

- 인증이 필요한 행동에서 이동한 경우 로그인 후 원래 페이지로 복귀
- 이미 로그인한 사용자는 웰컴 또는 이전 목적지로 이동
- 데스크톱 모달과 모바일 전체 화면이 동일한 URL과 상태를 공유할 수 있게 구성

### 5.4 회원가입

- 강사 또는 학생 유형 선택
- 계정 정보 입력
- 아이디 중복 확인과 입력 유효성 안내
- 가입 완료 후 로그인 또는 자동 로그인 흐름으로 이동
- 가입 완료 후 선택한 사용자 유형에 맞는 시작 동선 제공

### 5.5 내 프로필

공통 계정 정보 영역을 유지하고 가입 유형에 따라 필요한 프로필 영역만 추가한다.

**공통**

- 내 계정 정보 확인
- 강사 또는 학생 가입 유형 확인
- 사용자 이름 등 수정 가능한 프로필 정보 변경
- 가입 유형은 읽기 전용으로 표시하고 변경 기능은 제공하지 않음
- 비밀번호 변경 기능이 도입되면 별도 보안 폼으로 진입
- 로그아웃 및 회원 탈퇴 진입점

**강사 전용**

- 공개 강사 소개와 전문 분야
- 공개 프로필 미리보기와 운영 중인 커리큘럼 이동

**학생 전용**

- 수강·완료·다음 예정 live session의 간단한 학습 요약
- 내 커리큘럼 이동

관심 분야와 추천 설정은 추천 기능 도입 후 추가한다. 회원 탈퇴는 운영 커리큘럼·수강·학습 데이터 처리 정책을 확정한 뒤 활성화한다. 세부 구성은 [내 프로필 컴포넌트 명세](components/PROFILE.md)를 따른다.

### 5.6 내 커리큘럼

로그인 사용자의 유형에 따라 내용을 다르게 구성한다.

**강사**

- 내가 생성하고 운영하는 커리큘럼
- 커리큘럼별 수강생·섹션·레슨 현황
- 다음 예정 live session
- 커리큘럼 생성 및 관리로 이동

**학생**

- 내가 수강 중이거나 수강했던 커리큘럼
- 커리큘럼별 전체 레슨 수와 학습 진행 현황
- 다음 예정 live session
- 최근 학습한 VOD 레슨 이어보기

### 5.7 커리큘럼 생성

강사 유형 계정만 접근할 수 있다. 학생용 조건부 화면을 두지 않고 라우트 진입 단계에서 차단한다.

- 커리큘럼 제목과 소개 입력
- 전체 진행 기간과 대표 이미지 설정
- 참가·공개 정책 설정
- 생성 완료 후 커리큘럼 상세 또는 관리 페이지로 이동

정책 입력 범위는 아직 확정되지 않았으며, CP0에서는 제목과 최소 커리큘럼 정보만 제공할 수 있다.

### 5.8 커리큘럼 상세

커리큘럼 소개와 `섹션 → 레슨` 목차를 보여주는 공개 페이지다. 동일한 페이지에서 현재 사용자의 관계에 따라 행동을 구분한다.

커리큘럼 소개, 강사 정보, 공개 목차는 공통 컴포넌트로 유지하고 관리 행동·학습 진도·수강 CTA만 조건부로 노출한다. 강사 계정이라는 이유만으로 관리 기능을 노출하지 않으며, **해당 커리큘럼 강사인지** 별도로 확인한다.

**커리큘럼 강사**

- 전체 커리큘럼 정보와 공개 상태 확인
- 섹션·레슨 목차 확인
- 커리큘럼 관리로 이동
- 예정 또는 진행 중인 live session 상세·입장
- 종료된 레슨 VOD 확인

**수강생**

- 전체 커리큘럼 정보와 섹션·레슨 목차 확인
- 현재 학습 진행률과 완료 레슨 확인
- 예정·진행 중 레슨 상태 확인
- live session 상세·강의실 입장
- 종료된 레슨 VOD 재생

**그 외 사용자**

- 커리큘럼 소개, 강사 정보, 공개된 섹션·레슨 목차 확인
- 비로그인 사용자는 로그인 또는 회원가입으로 이동
- 로그인 학생은 수강 신청
- 로그인 강사는 수강 가능 여부에 따라 수강 신청 또는 안내 확인
- 강사·수강생 전용 레슨 콘텐츠에는 접근하지 못함

그 외 사용자는 화면상 하나의 그룹이지만 내부 상태는 비로그인, 학생·미수강, 수강 승인 대기, 강사·비운영자로 구분한다. 공개 목차와 실제 레슨 콘텐츠 접근 권한도 분리한다.

### 5.9 커리큘럼 관리

해당 커리큘럼을 운영하는 강사만 접근할 수 있다. 수강생이나 다른 강사용 조건부 화면을 두지 않고 라우트 진입 단계에서 차단한다.

- 커리큘럼 기본 정보와 참가 정책 수정
- 수강생 목록과 수강 상태 관리
- 섹션 생성·수정·삭제·순서 변경
- 섹션 내부 레슨 생성·수정·삭제·순서 변경
- 레슨 상태와 연결된 라이브 세션 일정 확인
- 진행 중 또는 종료된 커리큘럼에서 허용할 수정 범위는 추후 결정

섹션 편성은 이 페이지에서 처리하며, 현재 단계에서는 별도 섹션 상세 페이지를 두지 않는다.

### 5.10 레슨 생성

해당 커리큘럼을 운영하는 강사가 특정 섹션 안에서 레슨을 생성한다.

권한이 없는 사용자를 위한 조건부 화면은 두지 않고 라우트 진입 단계에서 차단한다.

- 상위 커리큘럼과 섹션 정보 확인
- 레슨 제목과 설명 입력
- 섹션 내 마지막 순서로 추가
- 기본 정보를 먼저 `DRAFT`로 저장
- 필요한 초기 PPTX 강의 자료를 한 번에 복수 선택·업로드
- 초기 자료 전체의 AI 준비 상태 확인
- 생성 완료 후 커리큘럼 관리 또는 레슨 상세로 이동

자료 없이 `DRAFT` 저장은 가능하지만 라이브를 시작할 수는 없다. 등록 가능한 PPTX 개수는 제한하지 않는다. AI 사용 여부 입력과 녹화 영상 업로드 입력은 제공하지 않는다.

### 5.11 레슨 수정

- 권한이 없는 사용자를 위한 조건부 화면은 두지 않고 라우트 진입 단계에서 차단
- 해당 커리큘럼을 운영하는 강사만 접근
- 레슨 제목·설명 변경. 순서와 소속 섹션은 커리큘럼 관리에서 변경
- 초기 준비 이후 PPTX는 하나씩 즉시 추가·삭제하며 일괄 적용 단계는 두지 않음
- 추가 자료만 기존 Vector DB에 증분 임베딩하고 삭제 자료의 chunk·embedding만 제거
- 삭제 자료에 의존하는 AI 근거·산출물만 무효화·재생성하고 관계없는 결과는 유지
- `LIVE`에서는 전체 잠금, `ENDED`에서는 제목·설명만 수정
- 종료된 레슨의 자료 변경은 자료 revision과 VOD 게시본 정책을 정한 뒤 후속 도입

세부 생성·수정 흐름은 [레슨 생성·수정 공통 폼 명세](components/LESSON_FORM.md)를 따른다.

### 5.12 레슨 상세

특정 레슨의 준비·게시 상태, 자료, 연결된 라이브 세션과 다시보기를 보여주는 허브 페이지다. `WorkspaceLayout`을 사용하며 일정 편집·사전 점검·라이브·VOD 플레이어는 각각 전용 페이지에서 처리한다.

- 상위 커리큘럼과 섹션 목차로 돌아가는 동선 제공
- 커리큘럼 강사 또는 수강생이 아니면 접근 차단
- 접근할 수 없는 경우 사유 안내
- 레슨 상태 변경을 감지해도 자동 이동하지 않고 명시적인 게시·라이브 세션·다시보기 행동 제공
- 연결된 `liveSessionId`와 세션 일정·상태 요약 표시
- 강사는 lesson 생성 이후 라이브 세션을 미리 예약하거나 기존 세션 관리로 이동
- 수강생은 라이브 세션 상세에서 일정·입장 가능 상태 확인
- 활성 PPTX 자료 확인·다운로드, 자료 변경은 레슨 수정으로 이동

관계와 여러 상태 축을 함께 사용하여 조건부 컴포넌트를 결정한다.

| 조건 | 해당 커리큘럼 강사 | 수강생 |
|---|---|---|
| `DRAFT` | 레슨·자료 편집, 세션 초안 생성 가능 | 접근 불가 |
| `AI_NOT_READY` | AI 처리 상태·재시도, 세션 일정 관리 | 접근 불가 |
| `READY` | 게시 전 최종 확인·레슨 게시, 세션 일정 관리 | 접근 불가 |
| `PUBLISHED` + 세션 없음 | 라이브 세션 생성 | 게시 레슨·자료 확인 |
| `PUBLISHED` + 세션 존재 | 라이브 세션 상세·관리 | 라이브 세션 상세 |
| 자산 `FINALIZING/VERIFYING` | 녹화 처리 현황 | 다시보기 준비 중 안내 |
| 자산 `READY` + replay `READY_FOR_REVIEW` | 미리보기·게시본 검수·replay 게시 | 게시 대기 안내 |
| 자산 `READY` + replay `PUBLISHED` | 다시보기·게시본 관리 | 다시보기 재생 |
| 자산 `READY` + replay `WITHDRAWN` | 미리보기·재게시 검토 | 공개 중단 안내 |

AI 준비가 끝나 `READY`가 된 레슨을 강사가 게시하면 `PUBLISHED`로 전환한다. 게시된 레슨에 연결된 라이브 세션의 일정·진행 상태는 lesson 상태에 합치지 않는다. 세부 구성은 [레슨 상세 컴포넌트 명세](components/LESSON_DETAIL.md)를 따른다.

### 5.13 라이브 세션 생성·수정·상세·입장 전

라이브 일정과 실제 진행 상태는 `lessonId`가 아닌 별도 `liveSessionId`로 관리한다. MVP에서는 한 레슨에 라이브 세션 하나만 만들 수 있다.

**강사**

- 생성된 lesson에 라이브 세션 일정 생성. lesson 게시·AI 준비 전에도 예약은 가능
- 시작 전 일정 변경·취소
- `DRAFT → SCHEDULED → OPEN` 상태와 입장 가능 시각 확인
- 사전 점검에서 카메라·마이크·네트워크·LiveKit·Egress·STT 확인
- 레슨 AI 준비 상태가 아니거나 LiveKit·Egress 문제가 있으면 시작 차단
- 시작 요청 중 `STARTING`, 종료 요청 중 `ENDING`을 별도 표시
- 종료 후 녹화 처리 현황으로 이동

**수강생**

- 라이브 세션 상세에서 일정·카운트다운·녹화 고지 확인
- `OPEN` 이후 입장 전 점검으로 이동
- 스피커·autoplay·네트워크·표시명 확인. 카메라·마이크 점검은 제공하지 않음
- `LIVE`가 확인된 뒤 강의실 입장
- 점검 완료 문맥 없이 강의실 주소에 직접 접근하면 같은 세션의 입장 전 점검으로 복귀
- `CANCELLED`·`FAILED`·`ENDED` 상태별 안내와 복구 동선 확인

세부 구성은 [라이브 세션 준비·상세 컴포넌트 명세](components/LIVE_SESSION.md)를 따른다.

### 5.14 라이브 레슨

미디어와 실시간 데이터가 함께 동작하는 `sessionId` 기준 전용 페이지다. 새로고침·일시 단절·늦은 입장을 고려하여 라이브 세션 상세와 분리한다.

**공통**

- 상위 커리큘럼·섹션과 현재 레슨 정보 표시
- LiveKit 기반 실시간 오디오·영상
- 메시지 작성 시 `질문으로 등록`을 선택할 수 있는 실시간 채팅
- partial/final/revised 자막
- 전문용어와 자료·발화 근거
- 참가자와 연결 상태
- WebRTC 현재 라이브와 Egress HLS를 결합한 라이브 되감기
- 빨간 점이 있는 `LIVE` 버튼으로 현재 시점 복귀

**강사 전용**

- 라이브 세션 종료
- 카메라·마이크·화면 공유
- 녹화·Egress 및 AI 자막 처리 상태
- AI Q&A와 질문으로 등록된 라이브 채팅의 질문 개수·집중 시점 핀 확인
- 핀 선택 시 학생 식별 정보 없이 익명 질문 원문 확인

**수강생 전용**

- 현재 시점 북마크
- 개인 AI Q&A
- 늦은 입장·재접속 따라잡기(후속)
- LiveKit 미디어 수신 전용

수강생 발언 요청과 강사 승인에 따른 일시적 마이크 허용은 후속 구현으로 남긴다. 강사 전용 버튼을 숨기는 것과 별개로 세션 종료·미디어 발행 등의 실제 권한은 서버에서도 검사해야 한다. 세부 구성은 [라이브 레슨 컴포넌트 명세](components/LIVE_LESSON.md)를 따른다.

### 5.15 VOD 레슨

종료된 동일 레슨을 재생하는 페이지다. 라이브 페이지와 화면 요소를 공유할 수 있지만, HLS 재생과 시간축 탐색이 중심이므로 라우트를 분리한다.

**공통**

- 같은 커리큘럼 목차와 이전·다음 레슨으로 이동
- HLS VOD 재생
- 마지막 재생 시점 자동 저장·이어보기와 90% 시청 완료 처리
- 강사가 검수·게시한 교정 자막과 자막 검색
- 구조 요약을 통한 구간 이동
- 전문용어와 PPTX 파일명·슬라이드 번호·추출 텍스트·원본 자료 및 발화 근거 확인
- 영상 시각과 동기화된 라이브 채팅 리플레이
- 레슨 맥락 기반 개인 AI Q&A와 근거 영상 시각 이동
- 라이브·VOD에서 저장한 북마크 확인·추가·이동·삭제
- 별도 패널에서 강사가 검수·게시한 퀴즈 응시

**강사 전용**

- AI 원본 후보·검수 초안·학생 공개 게시본을 구분하여 자막·용어·노트·퀴즈 검수·게시
- 검수 결과를 새 게시본 또는 새 퀴즈 버전으로 교체하고 기존 퀴즈 응시 기록 보존
- 자료 근거 연결과 VOD 공개 상태 확인
- 레슨 학습 통계
- 질문 등록 채팅과 라이브·VOD 개인 AI Q&A의 익명 질문 핀·구간별 원문 확인

**수강생 전용**

- 학습 진행률과 완료 상태
- 마지막 재생 지점부터 이어보기
- 퀴즈 버전별 응시 결과와 새 버전 재응시 가능 상태 확인

HLS `READY`는 기술적으로 재생 가능한 상태이며 수강생 자동 공개를 의미하지 않는다. 강사가 replay를 `PUBLISHED`로 전환해야 수강생에게 영상을 공개한다. AI 원본과 후보는 자동 게시하지 않고, 강사가 승인한 영역별 게시본만 수강생에게 제공한다. 영상은 AI 게시본 없이도 게시할 수 있으며, 이후 승인된 AI 콘텐츠를 영역별로 추가할 수 있다. 강사용 검수 패널은 우선 VOD 페이지 안에 배치하고, 기능이 복잡해지면 별도 관리 페이지로 분리한다. 세부 구성은 [VOD 레슨 컴포넌트 명세](components/VOD_LESSON.md)를 따른다.

### 5.16 접근 불가

- 비로그인 `401`은 로그인으로 이동하고 안전한 원래 목적지를 보존
- 인증 후 권한이 없는 `403`은 접근 실패 사유와 복구 행동 표시
- 커리큘럼 미수강, 승인 대기, 강사 전용 기능 등 접근 실패 사유 구분

실패 원인에 따라 복구 컴포넌트를 다르게 제공한다.

| 실패 원인 | 복구 행동 |
|---|---|
| 비로그인 | 로그인 후 원래 목적지 복귀 |
| 학생·미수강 | 커리큘럼 상세 및 수강 신청 |
| 수강 승인 대기 | 승인 대기 상태 안내 |
| 강사 전용 기능 접근 | 내 커리큘럼으로 이동 |
| 종료·삭제되었거나 권한이 회수된 레슨 | 커리큘럼 상세 또는 문의 동선 |

보호 리소스의 존재 여부를 노출하면 안 되는 경우 서버의 `404`를 일반적인 찾을 수 없음으로 처리한다.

### 5.17 찾을 수 없음

- 잘못된 URL 안내
- 삭제되었거나 존재하지 않는 커리큘럼·섹션·레슨·라이브 세션 안내
- 보호 리소스의 존재 여부와 내부 식별 정보 비노출
- 인증 상태에 따라 웰컴·내 커리큘럼·커리큘럼 목록으로 이동
- 자동 이동하지 않고 명시적인 복구 행동 제공

접근 불가와 찾을 수 없음은 `SystemLayout`을 공유하며 세부 구성은 [시스템 페이지 컴포넌트 명세](components/SYSTEM_PAGES.md)를 따른다.

| 회원가입에서 강사 유형 선택 후 가입 완료 | 로그인 또는 내 커리큘럼 |
| 회원가입에서 학생 유형 선택 후 가입 완료 | 로그인 또는 커리큘럼 목록 |
| 강사가 커리큘럼 생성 완료 | 커리큘럼 상세 또는 관리 |
| 학생이 커리큘럼 수강 완료 | 커리큘럼 상세 |
| 강사가 섹션에 레슨 추가 | 레슨 상세 또는 커리큘럼 관리 |
| 강사가 lesson 정보·자료 수정 선택 | 레슨 수정 |
| 강사가 live session 일정 수정 선택 | 라이브 세션 수정 |
| 강사가 사전 점검에서 세션 시작 완료 | `sessionId` 기준 라이브 레슨 |
| 수강생이 진행 중 세션 입장 | `sessionId` 기준 라이브 레슨 |

| 종료 레슨에서 다시 보기 선택 | VOD 레슨 |
| 권한 부족 | 접근 불가 |
| 존재하지 않는 커리큘럼·섹션·레슨·라이브 세션 또는 경로 | 찾을 수 없음 |

## 7. 페이지 단계에서 확인할 결정

아래 항목은 컴포넌트와 API를 구체화하기 전에 팀 확인이 필요하다.

1. 강사와 학생의 가입 화면을 역할 선택 후 하나의 폼으로 공유할지, 완전히 분리할지
2. 로그인·회원가입을 URL이 있는 모달로 구현할지 완전한 독립 페이지로 구현할지
3. 강사 계정도 다른 커리큘럼을 수강할 수 있게 할지
4. 커리큘럼 참가 방식을 즉시 수강·승인·초대 중 어떤 형태로 지원할지
5. 커리큘럼 상세에서 비수강 사용자에게 공개할 섹션·레슨 정보 범위
6. 섹션에 별도 소개·학습 목표가 필요한지
7. 강사용 종료 후 자막·요약 검수 페이지가 초기 범위에 필요한지
8. 커리큘럼 공개·초대·정원 정책을 어느 CP에서 도입할지
