# LiveClass AI 프론트엔드 결정 필요 항목

작성일: 2026-07-20

이 문서는 전체 페이지 UI 초안을 실제 API와 제품 정책으로 확정하기 위해 팀이 결정해야 할 항목을 우선순위로 정리한다. 체크한 결정은 관련 API 문서와 공유 계약에 함께 반영해야 한다.

## P0 — 실제 연동 전에 반드시 확정

### 1. 공개 커리큘럼의 사용자 관계 응답

- [ ] 목록·상세 응답에 `viewerContext`를 포함할지 별도 관계 API로 분리할지
- [ ] 비로그인, 미수강 학생, 승인 대기, 수강생, 운영 강사, 비운영 강사의 관계 enum
- [ ] `allowedActions`의 최종 enum과 `MANAGE_CURRICULUM` 사용 확정

권장안: 목록과 상세에 최소 `viewerContext`를 포함한다. 카드와 대표 CTA가 관계별로 달라 별도 요청은 waterfall과 사용자별 캐시 복잡도를 늘린다.

### 2. 수강 정책과 수강 API

- [ ] `IMMEDIATE`, `APPROVAL_REQUIRED`, `INVITATION_ONLY` 지원 범위
- [ ] 즉시 수강도 최종 상태를 `ACTIVE`로 반환할지
- [ ] 승인 대기 신청 취소와 재신청 허용 정책
- [ ] 강사 계정이 다른 강사의 커리큘럼을 수강할 수 있는지

권장안: CP0에서는 `APPROVAL_REQUIRED` 하나로 시작하고 신청·취소·승인 흐름을 완성한 뒤 나머지 정책을 추가한다.

### 3. 내 커리큘럼 응답

- [ ] 강사 대시보드 요약과 목록을 분리할지
- [ ] 학생 학습 요약과 수강 목록을 분리할지
- [ ] 진행률·완료 판정의 서버 계산 기준
- [ ] 다음 라이브와 최근 학습 중 대표 행동 우선순위

권장안: 요약과 목록을 분리한다. 한 영역의 실패가 전체 대시보드를 막지 않고 갱신 주기도 다르게 둘 수 있다.

### 4. 관리용 커리큘럼 조회

- [ ] 기본 정보와 전체 `섹션 → 레슨` 구조를 한 응답으로 줄지
- [ ] 구조 저장 시 `structureVersion` 기반 충돌 검사를 사용할지
- [ ] 커리큘럼 lifecycle별 수정 가능 범위
- [ ] 대표 이미지 업로드 형식·크기·비율과 presigned upload 적용
- [ ] 커리큘럼 공통 강의 자료의 업로드·목록·삭제 API와 presigned upload 적용
- [ ] 커리큘럼 공통 강의 자료의 허용 형식, 파일별 최대 크기와 개수 제한
- [ ] 상세 응답에 자료 목록을 포함할지 권한 전용 API로 분리할지

권장안: 관리 첫 조회는 기본 정보와 구조를 한 번에 반환하고, 저장은 기본 정보·구조·수강생으로 분리한다. 공통 강의 자료는 별도 첨부 리소스로 관리하고 파일별 업로드 결과를 반환한다. 운영 강사만 수정할 수 있고 `ACTIVE` 수강생과 운영 강사만 조회할 수 있게 서버에서 검사하며, 비로그인·승인 대기·미수강 사용자와 비운영 강사에게는 파일명 등 메타데이터도 반환하지 않는다.

### 5. 레슨과 PPTX 처리

- [ ] 초기 PPTX 복수 업로드의 부분 실패 처리 방식
- [ ] 파일별 최대 크기와 개수 제한
- [ ] `DRAFT → AI_NOT_READY → READY → PUBLISHED` 전환 API
- [ ] 게시 후 자료 변경 시 자동 비공개 또는 명시적 재게시 정책

권장안: 파일별 결과를 반환해 성공 파일은 유지하고 실패 파일만 재시도한다. 자료 변경 후에는 `READY`로 돌아가 강사가 명시적으로 재게시한다.

### 6. 라이브 입장·시작 권한

- [ ] `OPEN`이 저장 상태인지 서버 계산 상태인지
- [ ] 기본 입장 가능 창과 설정 허용 범위
- [ ] 강사 preflight 결과의 유효 시간
- [ ] 중복 접속과 이전 연결 종료 정책
- [ ] `FAILED` 세션 재시도 또는 새 세션 생성 정책

권장안: `OPEN`은 서버가 현재 시각과 정책으로 계산해 응답하고, 프론트는 예정 시각으로 상태를 변경하지 않는다.

## P1 — LiveKit/HLS 연동 전에 확정

### 7. 라이브 강의실 미디어 동작

- [ ] 수강생 token의 subscribe-only 보장
- [ ] 강사의 카메라·마이크·화면 공유 기본 상태
- [ ] WebRTC와 HLS 되감기 전환 시 `sessionMs` 보정 방식
- [ ] Egress 최근/전체 playlist 제공 방식과 재생 가능 범위
- [ ] 세션 종료 감지 후 이동 대상

권장안: 수강생은 미디어 수신 전용으로 시작한다. 과거 시점 선택 시 HLS로 전환하고 `LIVE` 버튼으로 WebRTC에 복귀한다.

### 8. 채팅·자막·AI 장애 정책

- [ ] STOMP 재연결과 REST 누락 메시지 복구 기준
- [ ] `clientMessageId` 보관 시간과 본인 메시지 판별
- [ ] 자막 partial/final/revised 교체 규칙
- [ ] AI SSE 중단 시 재시도·취소 UX
- [ ] Egress·STT·AI 부분 장애가 라이브를 종료시키는지

권장안: WebRTC 라이브를 최우선으로 유지한다. Egress·STT·AI 장애는 기능별 저하 상태로 표시하고 라이브 자체는 종료하지 않는다.

### 9. 다시보기 게시와 AI 게시본

- [ ] `videoAssetStatus=READY` 후 replay 기본 상태
- [ ] 영상만 먼저 게시하고 AI 콘텐츠를 나중에 추가할 수 있는지
- [ ] 자막·요약·용어·퀴즈 게시본의 버전 단위
- [ ] 새 퀴즈 버전 게시 후 기존 응시 기록 처리
- [ ] 90% 완료 판정의 시청 구간 합산 방식

권장안: 영상과 AI 영역을 독립적으로 게시한다. AI 원본은 보존하고 수강생에게는 강사가 승인한 현재 게시본만 노출한다.

## P2 — 운영 정책 확정 후 활성화

### 10. 프로필과 계정

- [ ] 표시 이름 수정 API
- [ ] 강사 소개와 전문 분야 형식·길이
- [ ] 비밀번호 변경 시 다른 세션 종료 여부
- [ ] 회원 탈퇴 시 운영·수강·학습 데이터 처리
- [ ] 공개 강사 프로필 페이지 도입 여부

권장안: 표시 이름과 강사 공개 프로필 저장을 분리한다. 탈퇴는 데이터 보존·운영 이관 정책 전까지 비활성화한다.

### 11. 반응형 미디어 패널

- [ ] 모바일에서 보조 패널을 하단 탭으로 유지할지 drawer로 전환할지
- [ ] 작은 화면에서 영상 최소 높이와 가로 모드 유도 여부
- [ ] 강사 운영 화면의 태블릿 최소 지원 폭

권장안: 초기에는 현재 구현처럼 영상 아래 탭 패널로 배치한다. 실제 수업 사용성 테스트 후 drawer 필요성을 판단한다.

### 12. 알림과 이탈 방지

- [ ] 저장되지 않은 폼 이탈 확인 범위
- [ ] 라이브 일정 변경·취소 알림 채널
- [ ] 처리 중 PPTX 업로드 페이지 이탈 시 동작
- [ ] 라이브 강의실 새로고침과 재접속 복원 상태

권장안: 서버 작업은 페이지 이탈 후에도 유지하고 재진입 시 작업 상태를 조회해 복원한다. 브라우저에서만 진행되는 파일 전송 중에는 명시적으로 이탈을 경고한다.

## 결정 기록 방법

1. 결정 항목을 체크하고 선택한 값을 이 문서에 기록한다.
2. API 필드·상태·경로에 영향을 주면 관련 `docs/frontend/api/` 문서와 `docs/CONTRACT.md`를 함께 갱신한다.
3. 기술 선택이나 되돌리기 어려운 정책이면 팀 ADR을 추가한다.
4. 실제 API 연결과 같은 변경에서 FE 계약 테스트를 추가한다.
