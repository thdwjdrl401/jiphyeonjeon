# ADR-0092: 라이브 종료 후 강의 상세로 돌아간다

> 관련 결정: [ADR-0059 종료 후 처리 현황](../songjeongki/0059-live-processing-status-is-two-axes.md) ·
> [ADR-0007 녹화 자동 게시](../choinhoo/0007-recording-ready-auto-publish-and-processing-polling.md)

- **상태**: 채택
- **일자**: 2026-08-06
- **적용 범위**: 강사 라이브 강의 종료 후 프런트엔드 이동 경로

## 맥락

강사가 라이브 강의를 종료하면 녹화 처리 현황으로 이동하고, 처리가 완료되면 다시보기 화면으로 자동
이동했다. 사용자는 강의를 종료했을 뿐인데 녹화 화면으로 연달아 이동하게 되고, 원래 작업하던 해당
커리큘럼과 강의의 맥락으로 돌아가려면 다시 탐색해야 했다.

강의 상세 화면은 이미 종료 상태, 녹화 준비 중, 다시보기 가능 여부와 검수 진입점을 표시한다. 따라서
종료 직후 반드시 별도 처리 현황 화면에 머물 필요가 없다.

## 결정

1. 강사의 라이브 종료 요청이 성공하면 종료 응답의 `curriculumId`, `sectionId`, `lessonId`로 해당 강의
   상세 경로를 만들어 `replace` 이동한다.
2. 종료 응답을 라이브 세션 캐시에 반영하고 강의 상세 쿼리를 무효화해 상세 화면이 종료 이후 상태를
   다시 읽도록 한다.
3. 녹화 처리는 백그라운드에서 계속한다. 처리 현황 페이지와 알림 진입점은 장애 확인과 직접 접근을
   위해 유지하며, 종료 버튼에서만 자동 진입하지 않는다.
4. 학생은 기존처럼 종료 상태를 강의실에서 안내받는다. 이번 결정은 강사가 직접 누르는 종료 완료
   동선만 변경한다.

## 결과

- 강사는 종료 후 방금 진행한 강의의 정보와 녹화 준비 상태를 한 화면에서 확인한다.
- 처리 완료를 기다리며 녹화/다시보기 화면으로 강제 이동하지 않는다.
- API 요청·응답과 녹화 처리 상태 계약은 변경하지 않는다.

## 검증

- 통합 테스트에서 종료 확인 버튼을 누른 뒤 해당 커리큘럼·섹션·강의 상세 경로로 이동하는지 확인한다.
- 이동 경로에 `/processing`과 `/replay`가 포함되지 않는지 함께 확인한다.
