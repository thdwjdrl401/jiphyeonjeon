# ADR-0087: 커리큘럼 히어로의 대표 이미지는 왼쪽 열에 두고 카드 높이를 지킨다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-08-06
- **관련**: Sub Ⅱ · [ADR-0086](0086-curriculum-period-editable-in-manage-info-tab.md)(운영 기간 — 이미지도 비어 있는 커리큘럼이 많다는 같은 사정을 다룬다)

## 맥락 (Context)

커리큘럼 상세의 제목 섹션(히어로)이 대표 이미지를 보여주지 않았다. 서버 응답에는 `thumbnailUrl`이
이미 내려온다. 배치 방향을 세 가지로 놓고 실제 데이터·실제 CSS로 목업을 만들어 비교했다.

1. **1a** 오른쪽 40% 풀블리드 패널 — 카드 높이 그대로
2. **1b** 상단 148px 배너 — 탐색 카드와 형태가 이어짐
3. **1c** 배너 위로 제목 블록이 올라타는 겹치기

비교 과정에서 두 가지가 드러났다.

- **목업이 히어로를 실제보다 넓게 그렸다.** 사이드바를 빼먹어 1176px로 그렸는데, 실제 본문 열은
  1440px 화면에서 **928px**다(1280px 컨테이너 − 사이드바 320px − gap 32px). 그래서 목업의
  종횡비 판단이 뒤집혔다 — 실제 이미지 슬롯은 가로형이 아니라 거의 정방형이다.
- **1a도 카드 높이를 지키지 못했다.** 이미지가 열을 가져가면 제목 폭이 864px → 530px로 줄고,
  원래 크기(1440px에서 51.8px)로는 지금 커리큘럼 제목 대부분이 두 줄이 되어 카드가 한 줄만큼
  길어진다. 1c를 먼저 구현했다가 되돌린 것도 같은 이유였다(배너 232px + 겹침으로도 +164px).

## 결정 (Decision)

**이미지를 왼쪽 36% 열에 풀블리드로 두고, 이미지가 있을 때만 제목을 한 급 낮춰(51.8px → 34.6px)
카드 높이를 지킨다.** 이미지가 없으면 배너도 열도 만들지 않고 지금 화면 그대로 둔다.

| | 값 | 이유 |
|---|---|---|
| 위치 | **왼쪽** | 오른쪽에 두면 히어로 옆 사이드바(수강 신청·강사 관리·자료)와 맞닿아 두 덩어리가 한 블록으로 뭉친다 |
| 폭 | 36% | 제목이 쓸 폭 530px 확보. 40%면 493px로 제목이 두 줄이 된다 |
| 제목(이미지 있을 때) | `clamp(1.55rem, 2.4vw, 2.2rem)` | 가장 긴 시드 제목(`라이브로 완성하는 Spring Boot`, 한글 9 + 영문 11 ≈ 498px)이 530px 안에 한 줄로 들어가는 크기 |
| 이미지 없을 때 | 변화 없음 | 대체 그림을 깔지 않는다 |
| 좁은 화면(≤960px) | 한 열로 쌓고 제목 크기 복귀 | 36% 열에 제목이 들어갈 폭이 없다 |

**긴 제목이 두 줄이 되어 카드가 길어지는 것은 받아들인다.** 제목 길이는 강사가 정하는 값이라
화면이 억지로 줄일 수 없다. 대신 제목 입력창에 `20자 안팎 권장`을 흐린 안내로 두어 그 길이를
알린다(`CurriculumFormPage`·`CurriculumManagePage`).

## 근거 (Rationale)

- **카드 높이가 판단 기준이다.** 상세는 수강 신청을 결정하는 화면이고 그 근거는 목차다. 히어로가
  150px 길어지면 목차가 첫 화면 밖으로 밀린다 — 1b·1c가 구조적으로 그렇다.
- **이미지 없는 커리큘럼이 적지 않다.** 실서버 커리큘럼 상당수가 `thumbnailUrl: null`이다. 히어로는
  첫 면을 통째로 차지하므로 뜻 없는 플레이스홀더가 제목·수강 신청보다 먼저 눈에 들어온다.
  목록 카드(`CurriculumCoverFallback`)와 판단이 다른 이유가 이것이다.
- **이미지는 장식이다**(`aria-hidden` + `alt=""`). 옆에서 제목과 소개가 같은 것을 말한다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| (선택) 왼쪽 36% + 제목 한 급 낮춤 | 카드 높이 유지, 사이드바와 분리 | 제목이 작아진다. 가로로 긴 사진은 좌우가 잘린다 |
| 오른쪽 40% | 텍스트가 먼저 읽힌다 | 사이드바와 맞닿아 뭉친다(사용자 확인) |
| 상단 148px 배너(1b) | 탐색 카드와 형태가 이어짐 | +149px. 1176px 폭에 148px는 8:1이라 위아래가 크게 잘린다 |
| 겹치기(1c) | 그림을 크게 쓰면서 높이 일부 절약 | +164px. 카드가 24px 안쪽으로 들어가 목차와 정렬축이 어긋난다 |
| 제목 크기 유지 | 히어로 인상이 그대로 | 카드가 항상 한 줄만큼 길어진다 — 이 배치를 고른 이유가 사라진다 |

## 영향·후속 (Consequences)

- **이미지 슬롯은 약 371 × 330px(≈1.1:1)이고, 이미지 비율은 레이아웃을 바꾸지 않는다.** 열 폭은
  36% 고정, 높이는 옆 텍스트가 정한다. 사진은 `object-fit: cover`로 중앙 기준으로 잘린다.
  → **정방형·세로 사진은 거의 안 잘리고, 가로로 긴 사진은 좌우가 크게 잘린다.** 실제로 올라온
  썸네일은 1170×1170 정방형이었다.
- 대표 이미지를 올릴 때 **정방형에 가깝게, 중요한 것은 가운데** 두는 편이 안전하다. 업로드 화면에서
  히어로 비율로 크롭해 보여주는 것이 후속 과제다(별도 MR).
- 기간 표시는 날짜 단위로만 줄바꿈한다(`.curriculum-metadata__date { white-space: nowrap }`) —
  묶지 않으면 좁은 칸에서 `2026` / `년 8월 21일`처럼 날짜 중간이 끊긴다.
- 하네스: **계약 테스트 불필요**(POLICY 🟢). 서버가 이미 주는 `thumbnailUrl`을 화면이 쓰기 시작한
  것으로 필드명·상태코드를 바꾸지 않았다. 이미지 유무에 따른 분기만 통합 테스트로 고정했다.
- 목업 산출물(세 방향 비교, 실제 폭 오류 포함)은 대화 기록에만 있다. 다시 비교할 일이 생기면
  **히어로 폭을 928px로** 잡아야 한다.
