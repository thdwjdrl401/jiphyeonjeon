# ADR-0006: 커리큘럼 게시는 단일 동작이고, 섹션·강의 각 1개 이상을 선행 조건으로 요구한다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-07-30
- **관련**: 브랜치 `feat/be-fe/curriculum-publish-preconditions`, [seominkyeong/0005](0005-lesson-has-no-draft-state.md)(전제), [seominkyeong/0002](0002-curriculum-and-lesson-publish-axes.md)(대체됨)

## 맥락 (Context)

[ADR-0005](0005-lesson-has-no-draft-state.md)로 공개 축이 커리큘럼 하나로 줄었다. 그런데 축을 줄이자
**빈 커리큘럼을 공개할 수 있게 됐다.** 예전에는 "게시된 강의가 0개면 우회로를 열지 않는다"는 가드가
게시 카드에 있었고([ADR-0002](0002-curriculum-and-lesson-publish-axes.md)), 그 가드가 강의 축과 함께
사라졌기 때문이다.

남은 문제 두 가지:

- **목차가 빈 커리큘럼이 카탈로그에 올라간다.** 수강 신청은 가능한데 들을 것이 없다.
- **게시 버튼이 아직 "복합 동작"의 흔적을 갖고 있었다.** `runPublish`는 단일 호출로 줄었지만
  `isPubliclyVisible` 판정에 `publishedLessonCount > 0`이 남아 있어, 공개 여부를 강의 수로도 보고 있었다.

## 결정 (Decision)

1. **게시 버튼은 단일 동작이다.** 비공개 → 공개 상태 전이만 수행한다. 강의 상태를 바꾸거나, 게시 대상을
   선택하게 하거나, 추가 확인 단계를 두지 않는다.
2. **선행 조건은 두 개다** — 섹션 1개 이상 **AND 커리큘럼 전체** 강의 1개 이상.
   강의는 커리큘럼 전체 기준이다. **섹션마다** 강의가 있어야 하는 것이 아니라, 어느 한 섹션에라도
   강의가 있으면 충족한다(빈 섹션을 남겨 둔 채로도 게시할 수 있다).
3. **조건은 FE·BE 양쪽에서 검사한다.** FE는 버튼을 잠그고 사유를 보여 주고, BE는 게시 API에서
   실제 행을 다시 세어 거절한다.
4. **거절은 409 `CURRICULUM_NOT_PUBLISHABLE`.** `CURRICULUM_STATE_CONFLICT`와 구분한다.
5. **안내 문구 정본은 세 문장이고 FE·BE가 같은 문장을 쓴다.**
   - 섹션 없음: `커리큘럼을 게시하려면 섹션을 1개 이상 추가해주세요.`
   - 강의 없음: `커리큘럼을 게시하려면 강의를 1개 이상 추가해주세요.`
   - 둘 다 없음: `커리큘럼을 게시하려면 섹션과 강의를 각각 1개 이상 추가해주세요.`
6. **비활성 사유는 tooltip과 인접 안내 두 곳에 모두 둔다.**
7. **공개 여부 판정에서 강의 수를 뺀다.** `isPubliclyVisible`은 `lifecycleStatus === 'PUBLISHED'`뿐이다.
8. **mock도 같은 조건을 검사한다.**

## 근거 (Rationale)

- **BE에서도 검사하는 이유**: 게시는 **되돌릴 수 없는 노출**이다(공개 뒤에는 삭제가 409로 막히고
  보관만 가능하다 — [ADR-0001](0001-draft-only-curriculum-delete.md)). 버튼을 우회한 직접 호출과,
  낡은 캐시를 든 화면(`staleTime` 30초)이 남으므로 서버가 마지막 방어선이어야 한다.
- **카운터 컬럼(`section_count`·`lesson_count`) 대신 실제 행을 세는 이유**: 그 값은 DB 트리거가
  유지하는 비정규화 값이다. 표시용으로는 충분하지만, 되돌릴 수 없는 동작의 게이트를 트리거 정합성에
  기대게 하고 싶지 않다. 게시는 드문 동작이라 쿼리 2번의 비용이 문제되지 않는다.
- **전용 오류 코드를 만든 이유**: `CURRICULUM_STATE_CONFLICT`는 "이미 게시됨·보관됨"처럼 **상태**가
  막는 경우다. 이쪽은 **내용**이 부족한 경우이고 사용자가 할 일이 다르다 — 기다리는 게 아니라
  섹션·강의를 추가해야 한다. 코드가 같으면 FE가 안내를 가를 수 없다.
- **문구 정본을 한쪽에 두는 이유**: 버튼 비활성 사유와 서버 거절 메시지가 다르면 같은 상황을 두 가지로
  설명하게 된다. 서버가 메시지를 만들고 FE는 같은 문장을 판정 모듈(`publishPreconditions.ts`)에
  복제해 둔다 — 완전한 단일 정본은 아니지만, 두 테스트가 같은 문장을 각각 못 박아 어긋나면 깨진다.
- **tooltip만으로 부족한 이유**: `title` 속성은 터치 기기에서 뜨지 않고 스크린리더 지원도 제각각이다.
  비활성 사유는 "왜 못 누르는지"라는 필수 정보이므로 화면에 보이는 문장으로도 함께 둔다.
- **섹션마다 강의를 요구하지 않는 이유**: 요청에 명시된 조건이고, 실제 작성 흐름과도 맞는다 —
  강사는 섹션 골격을 먼저 잡고 강의를 채워 나간다. 빈 섹션을 이유로 게시를 막으면 "일단 1강만 열고
  나머지는 준비 중" 같은 정상적인 운영을 못 한다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| **(선택) FE 버튼 잠금 + BE 재검증, 전용 409 코드** | 우회 불가, 사용자는 무엇을 해야 할지 알 수 있음 | 검사 로직이 두 곳에 있음(문구 복제) |
| (기각) FE만 검사 | 구현이 가장 적음 | 직접 호출·낡은 캐시로 빈 커리큘럼이 공개됨. 되돌릴 수 없다 |
| (기각) BE만 검사 | 정본이 하나 | 버튼을 눌러 봐야 실패를 앎. 왜 안 되는지 미리 알 수 없다 |
| (기각) 섹션마다 강의 1개 이상 요구 | 목차가 더 촘촘함 | 요청 범위 밖이고, 부분 공개라는 정상 운영을 막는다 |
| (기각) `CURRICULUM_STATE_CONFLICT` 재사용 | 새 코드 불필요 | 상태 문제와 내용 문제가 섞여 FE가 안내를 가를 수 없다 |

## 영향·후속 (Consequences)

- **BE**: `InstructorCurriculumService.publish`에 `requirePublishableStructure` 추가.
  `CurriculumNotPublishableException`(+ 핸들러 → 409 `CURRICULUM_NOT_PUBLISHABLE`) 신설.
- **FE**: `features/curriculum/publishPreconditions.ts` 신설(순수 판정).
  `CurriculumPublishPanel`이 `readiness`를 받아 버튼 비활성·`title`·인접 안내를 처리.
  `runPublish`가 조건 미충족 시 요청하지 않고, 서버 거절 메시지를 그대로 보여 준다.
  `isPubliclyVisible`에서 `publishedLessonCount` 잔재 제거. mock도 같은 조건을 검사.
- **계약 자물쇠**: 공유 계약(새 오류 코드·게시 실패 조건)이 생겼으므로 [POLICY](../../harness/POLICY.md)의
  "계약 테스트 필수"에 해당한다. `CurriculumLifecycleContractTest`에 세 케이스를 추가했다 —
  섹션 없음 409+문구, 빈 섹션만 있음 409+문구, **일부 섹션만 채워도 게시 성공**.
  FE는 `publishPreconditions.test.ts`(문구·판정)와 `CurriculumPublishPanel.test.tsx`(버튼 잠금·
  tooltip·인접 안내)로 고정했다.
- **기존 테스트 영향**: 커리큘럼을 발행하는 셋업이 **선행 조건을 채워야** 하게 됐다. 17개 계약 테스트
  파일에 섹션·강의 seed를 넣었고, 강의 수·목차 인덱스를 세는 5개 파일은 **발행 직후 seed를 지워**
  원래 구조를 유지했다. WebSocket 테스트 2개는 발행 순서를 내용 생성 뒤로 옮겼다(그게 실제 흐름이다).
- **후속**: 커리큘럼을 게시한 뒤 마지막 강의를 지우면 다시 빈 목차가 공개된 상태가 된다. 게시된
  커리큘럼의 강의 삭제에 같은 가드를 걸지는 이 ADR 범위 밖이다 — 판단이 필요하면 별도로 다룬다.
