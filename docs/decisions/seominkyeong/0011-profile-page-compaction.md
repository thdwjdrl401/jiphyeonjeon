# ADR-0011: 내 프로필 화면을 스크롤 없는 한 페이지로 — 요약 통계 제거·2열 배치·탈퇴 모달

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md) · 계약: [../../CONTRACT.md](../../CONTRACT.md)

- **상태**: 채택
- **일자**: 2026-07-31
- **관련**: [0010](0010-account-withdrawal-notice-and-password-reset.md)(탈퇴 안내·비밀번호 재설정 — §2·§3의 배치를 이 ADR이 갱신한다), [0009](0009-profile-identity-card-consolidation.md)(프로필 카드 통합), [songjeongki/0031](../songjeongki/0031-account-profile-security.md)(계정·프로필·보안 API)

## 맥락 (Context)

[0010]은 문구와 절차만 다루고 **"내 프로필 화면의 정보 밀도·레이아웃 개편"을 후속 작업으로
남겼다**(§영향·후속 마지막 줄). 이 ADR이 그 후속이다. 요청은 셋 — ① 한 페이지에 정보가 전부
들어오게, ② 불필요한 여백과 스크롤 제거, ③ 텍스트 줄바꿈 개선. 모노톤 디자인과 기존 코드 구조는
유지한다.

CSS 값(padding·font-size·gap)을 더해 계산한 학생 화면의 세로 예산은 다음과 같았다.

| 블록 | 높이 | 그 높이로 보여 주던 정보 |
|---|---|---|
| `PageHeader "내 프로필"` | ~72 + gap 16 | 제목 한 줄 |
| `ProfileIdentityCard` | ~112 | 이름·가입 유형·이메일 + 수정 버튼 |
| `Panel 나의 학습 요약` | ~182 (헤더 69 + 통계 행 73) | 숫자 4개 |
| `Panel 계정 보안` | ~816 | 비밀번호 3필드 + 탈퇴 안내·동의 |
| **합계** | **~1230** | 뷰포트 가용 높이 ~820 → **1.5화면** |

낭비의 출처는 세 가지였다.

1. **폭을 쓰지 않았다.** 콘텐츠 열이 1000px을 넘는데 카드를 세로로만 쌓아 오른쪽 절반이 비었다.
2. **패널 크롬이 내용보다 컸다.** 학습 요약 패널은 헤더(제목·설명·구분선) 69px + 통계 73px.
3. **탈퇴 안내가 카드에 펼쳐져 있었다.** 안내·질문·동의·버튼으로 ~290px — 페이지 높이의 1/4을
   "아직 누르지도 않은 동작의 설명"이 쓰고 있었다.

## 결정 (Decision)

### 1. 요약 통계를 두지 않는다

학생의 학습 요약 4칸(수강 중·완료·평균 진행률·완료한 강의)을 **없앤다.** 강사 활동 요약도 넣지
않는다. 요청자 결정이며, 근거가 있다 — **진도와 커리큘럼 현황은 대시보드와 내 커리큘럼이 이미
보여 준다.** 프로필 화면은 "이 계정을 확인하고 설정하는 곳"이고, 통계는 여기서 한 번 더 볼 이유가
없다. 그 자리를 비워 계정 정보가 한 페이지에 들어온다.

`ProfileIdentityCard`는 계정 정보만 낸다(요약 슬롯 없음). `ProfilePage`의 대시보드 요약 쿼리도
함께 지운다 — 프로필 화면은 더 이상 대시보드 API를 호출하지 않는다.

### 2. 페이지 제목을 눈썹 라벨로 줄인다

`PageHeader`(min-height 105px + 장식 막대)를 쓰지 않고 `h1.profile-page__eyebrow` 한 줄로 낸다.
바로 아래 카드가 이름·가입 유형·이메일로 같은 말을 하고, 사이드바에서도 "마이페이지"가 켜져 있다.
`usePageTitle('내 프로필')`은 그대로 두어 문서 제목과 히스토리는 바뀌지 않고, `h1`도 한 개를
유지한다 — 시각적 크기만 줄인다. 다만 **눈썹이라도 페이지 제목이므로 보조 텍스트보다는 크게**
둔다(`.88rem`) — 카드 안 소제목(`.86rem`)보다 작아지면 위계가 뒤집힌다.

### 3. 2열 배치: 왼쪽 편집 카드 / 오른쪽 계정 설정 — 두 역할 모두

| 열 | 강사 | 학생 |
|---|---|---|
| 왼쪽 | **강사 공개 프로필**(소개·전문 분야) | **프로필 수정**(닉네임·프로필 이미지) |
| 오른쪽 | 계정 설정(비밀번호 변경 · 회원 탈퇴) | 같음 |

학생 카드를 "공개 프로필"이라 부르지 않는다 — 강사의 소개·전문 분야는 커리큘럼 상세에서 수강생에게
공개되는 값이지만, 학생의 닉네임·이미지는 그런 공개 지면이 없는 자기 계정 표시 정보다.

학생에게는 강사 공개 프로필이 없어 왼쪽 열이 비었다. 그 자리에 **닉네임·이미지 편집을 인라인
카드로** 놓는다(§7) — 어느 역할이든 빈 칸이 남지 않는다. 1080px 아래로는 한 열로 쌓는다(두 열을
유지하면 폼 필드가 좁아져 줄바꿈이 늘어난다).

**두 카드는 시작점과 끝점을 맞춘다**(그리드 기본 `stretch`). 높이가 다르면 나란히 놓인 카드가
어긋나 보인다. 늘어난 쪽에 죽은 여백이 생기지 않도록 카드를 세로 flex로 만들고 **마지막 줄(공개
프로필의 저장 버튼 행, 계정 설정의 탈퇴 행)을 카드 바닥으로 내린다** — 늘어난 높이를 여백이 아니라
액션이 쓴다.

### 4. 계정 설정은 한 카드 — [0010] §2의 구분선 대신 카드 하나

비밀번호 변경과 회원 탈퇴는 **"계정 설정" 카드 한 장**에 함께 둔다. 둘 다 "이 계정을 어떻게 할
것인가"이고, 카드를 가르면 카드 수가 늘어나 한 페이지에 담기지 않는다. [0010] §2가 쓴 구분선
(`.settings-section`)은 탈퇴 진입 행 자체의 경계선(`.withdraw-trigger`의 `border-top`, 학생
화면에서는 `border-left`)이 대신한다. 컴포넌트 분리(`PasswordChangePanel` ·
`AccountWithdrawPanel`)와 그 이유(상태를 각자 소유)는 손대지 않는다.

**두 블록에 소제목(`h3`)을 단다** — `비밀번호 변경` · `회원 탈퇴`. 선만으로 가르면 어디까지가
비밀번호 변경인지 읽는 사람이 추론해야 한다. 대신 **카드 설명은 지운다** — "비밀번호 변경과 회원
탈퇴"라는 설명은 바로 아래 두 소제목이 그대로 하는 말이었다. 제목 두 개를 얻고 설명 한 줄을
반납해 높이는 그대로다.

탈퇴 진입 행의 버튼은 `align-items: flex-end`로 **설명 문구 블록의 밑변에 맞춘다.** 가운데
정렬이면 버튼이 두 줄(소제목 + 설명) 사이에 떠서 어느 줄과도 맞지 않는다.

### 5. 회원 탈퇴는 버튼 → 모달 — [0010] §3의 **배치**를 갱신한다

카드에는 진입 행만 둔다(소제목 + 한 줄 설명 + `회원 탈퇴` 버튼). 누르면
`AccountWithdrawModal`이 열리고, 그 안에서 안내 → 동의 → 실행을 끝낸다.

**안내를 줄인 것이 아니라 위치를 옮긴 것이다.** [0010] §3이 실제 서버 동작에 맞춰 고른 문구를
**한 글자도 바꾸지 않았다** — lead 문장, 보존 항목, 재가입 항목, 강사 전용 라이브 항목이 모달에
그대로 있다. 없앤 것은 "탈퇴를 진행하시겠습니까?" 한 줄뿐이고, 바로 아래 동의 체크박스가 같은
질문이라 중복이었다.

모달이 지키는 것:

- **최종 실행 버튼 이름은 `탈퇴하기`**. 진입 버튼과 같은 `회원 탈퇴`면 화면에 같은 이름의 버튼이
  둘이 되고, 어느 쪽이 실제로 탈퇴시키는지 이름만으로 구분되지 않는다.
- **409는 모달 안에 남는다.** 실패와 함께 닫아 버리면 왜 실패했는지가 사라지고 안내를 처음부터
  다시 읽어야 한다.
- **처리 중에는 닫히지 않는다**(Esc·배경 클릭·닫기 버튼 모두). 요청이 날아간 뒤 모달만 사라지면
  탈퇴가 됐는지 모르는 상태로 남는다.
- **닫으면 포커스가 진입 버튼으로 돌아온다.** 키보드 사용자가 페이지 맨 위로 튕기지 않는다.
- 동의 체크는 그대로 필수다 — 되돌릴 수 없는 동작 앞의 유일한 확인 단계다.

### 6. 프로필 카드는 `이름 + 배지` 한 줄 + 그 아래 이메일

이름 옆에 가입 유형 배지를 붙이고, 이메일만 아래 줄에 둔다. 배지는 이름을 수식하는 값이라 같은
줄에 있는 것이 자연스럽고, 두 줄이면 **카드가 아바타(58px) 높이 안에 들어와** 카드가 자라지 않는다
([0009]의 위계는 그대로다 — 이름이 가장 크고 나머지는 보조 정보. 배지와 이메일이 한 줄을 나눠 쓰던
배치만 바꿨다. 배지 옆에 이메일이 오면 둘이 한 항목처럼 읽힌다).

`dt`/`dd` 구조는 그대로다 — 배지는 `가입 유형`, 이메일은 `가입 이메일`이라는 감춘 `dt`를 각각
갖는다([0009]). 화면에서 레이블이 군더더기여도 스크린리더에는 무슨 값인지 알려 줄 이름이 필요하다.
`dl`이 둘로 나뉘는 이유는 이름(`h2`)이 배지와 같은 줄에 와야 하고, `dl` 안에 `h2`를 넣는 것은
유효하지 않기 때문이다.

이름이 길어 줄바꿈되면 배지는 이름의 마지막 줄 옆에 남는다(`flex-wrap`) — 배지만 홀로 다음 줄로
떨어지지 않는다.

### 7. 닉네임·이미지 편집: 학생은 인라인 카드, 강사는 모달

학생 화면에서 상단 카드의 **"프로필 수정" 버튼과 모달을 걷어내고**, 왼쪽 열의 "프로필 수정" 카드에서
닉네임·프로필 이미지를 바로 고친다. 한 페이지에 다 보이는 것이 목표인 화면에서, 이미 자리가 비어
있는 편집을 클릭 뒤로 감출 이유가 없다. 진입점을 하나만 두는 이유는 버튼과 카드가 같이 있으면 같은
일을 하는 입구가 둘이 되기 때문이다.

**강사는 계속 모달을 쓴다.** 강사 화면의 왼쪽 카드는 강사 공개 프로필(소개·전문 분야)이 이미
차지하고 있어 닉네임·이미지를 펼칠 자리가 없다. 두 카드를 만들면 3열이 되거나 카드가 세로로 늘어나
한 페이지를 넘긴다.

역할마다 겉모습이 다르므로 **상태와 필드는 공유한다** — `useBasicProfileDraft`(검증·미리보기·저장)
와 `BasicProfileFields`(입력 필드). 두 화면이 각자 로직을 들고 있으면 이미지 검증이나 닉네임 길이
규칙이 한쪽만 고쳐진다. 모달은 이제 크롬(배경·`role="dialog"`·Esc·스크롤 잠금·저장 중 닫기 차단)만
갖는다.

**닉네임 필드의 접근성 이름도 고정했다** — 감싸는 `label`이 도움말 `small`까지 품어 이름이
"닉네임 1자 이상 100자 이하로…"였다. `aria-labelledby`로 이름을 라벨 텍스트에 고정하고 도움말은
`aria-describedby`로만 연결한다([0010]이 비밀번호 필드에 세운 규칙과 같다).

### 8. 폼과 여백에서 반복되는 한 줄씩을 없앤다

- **새 비밀번호 / 확인을 한 행에 나란히.** 같이 채워야 하는 짝이라 눈이 위아래로 오갈 이유가 없다.
- **도움말과 불일치 오류가 한 자리를 번갈아 쓴다.** 동시에 필요한 상황이 없다. `id`는
  `password-form-hint` 하나로 유지한다 — 그래야 두 입력의 `aria-describedby`가 사라진 요소를
  가리키지 않는다.
- **"비밀번호를 잊으셨나요?" 링크를 액션 행 반대쪽으로.** 폼 아래 한 줄을 따로 쓰지 않는다.
  전역 규칙이 `a { color: inherit; text-decoration: none }`이라, 앞에 있던 안내문을 지우고 홀로
  두면 링크로 보이지 않으므로 밑줄을 넣었다.
- 페이지 gap 16→12, 패널 패딩 20/22→16/18, 폼 gap 20→12, 카드 아바타 76→58px. **이 페이지에서만**
  줄인다(`.profile-page` 스코프) — 다른 워크스페이스 화면의 여백 리듬은 건드리지 않는다.

### 9. 한국어 줄바꿈: `word-break: keep-all`

브라우저 기본값은 CJK를 글자 단위로 끊어 "보존됩니 / 다"처럼 어절 중간이 갈린다. `.profile-page`에
`keep-all`을 걸어 어절을 지키고, `text-wrap: pretty`로 마지막 줄에 한 단어만 남는 것을 막고,
문단 폭을 `62ch`로 제한한다.

**이메일은 반대 예외다.** 어절이 없어 `keep-all`이면 칸을 뚫는다 — `.profile-identity__email`에
`word-break: break-all`을 명시한다(예전의 `overflow-wrap: anywhere`를 대체). 말줄임은 여전히
쓰지 않는다([0009]) — 잘라 버리면 확인해야 할 계정을 읽을 수 없다.

## 근거 (Rationale)

- **2열이 세로 축소보다 큰 이유**: 여백을 줄이는 것은 잘해야 수십 px씩이고 계속하면 요소가 서로
  붙는다. 열을 하나 늘리는 것은 남는 폭을 쓰는 것이라 밀도를 해치지 않고 절반을 회수한다.
- **탈퇴를 모달로 옮긴 것이 안내 축소가 아닌 이유**: 카드에 펼쳐 두면 **탈퇴할 의사가 없는 모든
  사용자**가 매번 290px의 경고를 읽어야 하고, 정작 탈퇴하려는 사람에게는 정보량이 같다. 모달은
  같은 문장을 그 동작을 시작한 사람에게만, 결정 직전에 보여 준다 — 확인 단계로서는 오히려 강하다.
- **모노톤을 손대지 않은 이유**: 테마 레이어(`design-system.css`)가 이미 `border-radius: 0` ·
  `box-shadow: none` · `--paper-light`로 평면 hairline 카드를 만들고 있다. 카드 사이를 선으로만
  가르는 이 규칙이 밀도를 높이는 데 유리해서, 색·테두리·그림자는 그대로 두고 여백만 바꿨다.
- **모달을 새 파일로 뗀 이유**: `ProfileEditModal`과 같은 구조(backdrop·`role="dialog"`·Esc·
  body overflow 잠금·포커스 복귀)를 갖는다. 카드 안의 진입 행은 상태가 `isModalOpen` 하나뿐이라,
  둘을 한 파일에 두면 서로 무관한 관심사가 섞인다.

| 요약 통계 | 학생 4칸 유지 + 강사 4칸 추가 | 대시보드·내 커리큘럼과 중복이고, 한 페이지에 계정 정보를 담을 자리를 먹는다(요청자 결정) |
| 요약 통계 | 프로필 카드 아래에 물려 붙이기 | 카드 높이를 그대로 쓰는 값싼 배치이긴 하나, 중복 정보라는 판단이 우선한다 |
| 제목 | 큰 페이지 헤더 유지 | 아래 카드와 중복된 말에 88px을 쓴다 |
| 제목 | 제목을 프로필 카드 안으로 넣기 | 카드가 페이지 제목을 알아야 한다 — 레이어가 뒤집힌다 |
| 레이아웃 | 여백만 줄이고 1열 유지 | ~350px이 한계이고 그 이상은 요소가 붙는다. 남는 폭은 그대로 낭비 |
| 레이아웃 | 계정 설정을 좌측 세로 탭으로 | 탭은 정보를 감춰 "한 페이지 정보량"을 줄인다. 클릭도 늘어난다 |
| 학생 왼쪽 열 | 계정 설정 카드가 폭을 다 쓰고 카드 안을 좌우로 가르기 | 편집이 여전히 모달 뒤에 있고, 카드 안 2열은 화면 폭에 따라 규칙이 두 벌 필요하다 |
| 학생 왼쪽 열 | 카드에 미리보기만 두고 "프로필 수정"(모달) 버튼을 그 안으로 옮기기 | 자리가 있는데도 편집을 클릭 뒤로 감춘다 |
| 학생 카드 이름 | "공개 프로필"(강사 카드와 대응) | 학생의 닉네임·이미지는 공개 지면이 없다 — 이름이 사실과 다르다 |
| 편집 방식 | 두 역할 모두 모달 제거(강사 카드에 닉네임·이미지까지 합치기) | 강사 카드가 소개·전문 분야까지 안고 크게 높아져 한 페이지를 넘긴다 |
| 2열 높이 | 카드마다 자기 높이(`align-items: start`) | 나란한 두 카드의 끝점이 어긋나 보인다. 대신 늘어난 높이를 액션 행이 쓰게 했다 |
| 계정 설정 | 구분선만으로 두 블록 가르기 | 어디까지가 비밀번호 변경인지 추론해야 한다 — 선과 소제목을 함께 쓴다 |
| 계정 설정 | 비밀번호·탈퇴를 각각의 카드로 | 카드가 늘어 한 페이지를 넘긴다. 학생 화면에서는 특히 카드 두 장이 과하다 |
| 탈퇴 | 카드에 안내 전문 펼치기([0010] §3 배치) | 그것만으로 ~290px — 요청의 "스크롤 없이"와 정면으로 충돌한다 |
| 탈퇴 | 카드 안 접기(accordion) | 모달과 이득은 같은데, 되돌릴 수 없는 동작을 페이지 흐름 안에서 처리하게 되어 확인 단계가 약해진다 |
| 비밀번호 폼 | 평소 접어 두고 펼치기 | 카드가 이미 반 폭이라 접을 만큼 크지 않다. 클릭만 늘어난다 |
| 줄바꿈 | `keep-all`을 전역에 적용 | 다른 화면의 표·배지·좁은 칸이 함께 바뀐다. 이 화면 범위로 스코프한다 |

## 영향·후속 (Consequences)

- **FE 신규**: `AccountWithdrawModal`(안내·동의·실행 + 409 인라인 + 포커스 복귀) ·
  `ProfileEditPanel`(학생 인라인 편집 카드) · `useBasicProfileDraft`(편집 상태·검증) ·
  `BasicProfileFields`(공유 입력 필드).
- **FE 변경**: `ProfilePage`(요약 쿼리·통계 제거, 2열 조립, 계정 설정 카드, 역할별 편집 진입점) ·
  `ProfileIdentityCard`(요약 슬롯 없음, 아바타 축소, `이름 + 배지` 한 줄 + 아래 이메일,
  `onEdit` 없으면 수정 버튼을 그리지 않음) · `ProfileEditModal`(크롬만 남기고 상태·필드는 공유) ·
  `AccountWithdrawPanel`(패널 → 진입 행) · `PasswordChangePanel`(소제목·짝 필드·힌트 한 줄·액션 행) ·
  `workspace.css` · `design-system.css`.
- **[0009] 갱신**: 배지와 이메일이 한 줄을 나눠 쓰지 않고 각자의 줄을 갖는다(§6). 이메일을 한 번만
  보여 준다는 [0009]의 핵심 결정과 `dt`/`dd` 구조는 그대로다.
- **삭제된 CSS**: `.profile-stats`(+ 테마 규칙·미디어쿼리) · `.settings-section` · `.settings-aside` ·
  `.withdraw-panel__lead` · `.withdraw-panel__question` · `.profile-page__columns--single` 계열 ·
  `.profile-page .workspace-page-header` 계열. 다른 화면에서 쓰이지 않는 것을 확인했다.
- **세로 예산**: ~1230px → **두 역할 모두 ~500px**(1440px 폭, 같은 방식으로 계산한 값).
  스크롤 없이 들어온다.
- **BE·계약**: 변경 없음. 오히려 호출이 줄었다(프로필 화면이 대시보드 요약 API를 더 이상 호출하지
  않는다). 요청/응답 필드와 상태코드를 바꾸지 않았다. [POLICY](../../harness/POLICY.md) 기준
  **계약 테스트 대상이 아니다.**
- **테스트**: 558개 전체 통과. 갱신·추가한 단정은 — **요약 통계 부재**(두 역할, 레이블 8개를
  이름으로 확인), **계정 설정 카드 한 장에 비밀번호와 탈퇴 진입 + 소제목 두 개(`h3`)**,
  **이름과 배지가 같은 줄·이메일은 아래 줄**, **학생은 버튼 없이 프로필 수정 카드 / 강사는
  모달**(둘이 동시에 생기면 실패), **학생 카드에서 이미지+닉네임을 실제로 저장하고 저장 뒤 버튼이
  다시 잠김**, **열기 전에는 탈퇴 안내와 실행이 화면에 없음**, **취소 시 모달 닫힘 + 포커스 복귀 +
  탈퇴 미호출**, **409 시 모달 유지**.
  [0010]의 문구 회귀 테스트는 모달을 연 뒤 같은 문장을 그대로 확인한다 — **문장을 바꾸지 않았다는
  증거다.**
- **후속(BE 필요)**: 가입일·최근 접속을 카드 메타에 넣으려면 `AuthUser`에 필드가 필요하다.
  지금은 넣지 않았다.
