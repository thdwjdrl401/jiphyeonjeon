# ADR-0013: UI 폴리싱은 컴포넌트 단위로, 기존 값을 재사용해서 한다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택 (진행 중 — 컴포넌트마다 §4에 추가한다)
- **일자**: 2026-08-04
- **관련**: [0011](0011-profile-page-compaction.md)(프로필 화면 밀도)

## 맥락 (Context)

`design-system.css`는 기능 CSS 위에 얹는 **마지막 레이어**로, 수묵화 모노톤 톤을 위해 앞선
레이어의 카드·입력 스타일을 걷어낸다. 이 걷어내기가 지나쳐 일부 컴포넌트에서 **경계와 상태가
함께 사라졌다** — 카드는 `border: 0` + `background: transparent`, 입력란은 `background: transparent`.

한 차례 이것을 토큰 신설 + 전 화면 일괄 적용으로 고쳤다가 **롤백했다**. 범위가 넓어 레이아웃과
그리드 열 수까지 바뀌었고, 리뷰에서 어디가 왜 바뀐 것인지 분리해 볼 수 없었다. 되돌린 커밋은
`rollback/ui-readability-pass` 태그에 남겨 두었다.

## 결정 (Decision)

### 1. 컴포넌트 하나씩, 승인받은 항목만

`분석 → 개선안 제안 → 승인 → 수정 → before/after 보고` 순서를 컴포넌트마다 반복한다.
승인 범위를 넘는 것은 **같은 컴포넌트 안에서 같은 결함을 발견해도 손대지 않고 보고**한다.

### 2. 레이아웃은 손대지 않는다

페이지 레이아웃 · IA · 정보 구조 · 그리드 열 수 · 컴포넌트 위치 · 카드 순서 · 네비게이션 ·
Header · Sidebar는 변경 대상이 아니다. 바꾸는 것은 Border / Padding / Typography / 색 대비 /
Hover·Focus·Disabled / Badge / Divider / Empty·Loading 표현에 한한다.

### 3. 새 토큰·새 컨셉을 만들지 않고 **이미 있는 값**을 가져온다

같은 역할의 컴포넌트가 이미 쓰는 값이 있으면 그것을 쓴다. 커리큘럼 카드에 `내 커리큘럼`의
`dashboard-curriculum-card`가 쓰는 값(`--border-medium` 실선 + `--paper-light` 표면 + radius 0 +
그림자 없음)을 그대로 가져온 것이 이 규칙의 첫 적용이다. 새 시각 언어를 만드는 것이 아니라
**같은 위계의 것끼리 값을 맞추는** 작업이다.

### 4. 그림자는 쓰지 않는다

이 테마는 `design-system.css`에서 카드·패널 전체에 `box-shadow: none`을 명시적으로 건다.
hover 신호가 필요하면 **외곽선 강화 + 1px 이내의 들림**으로 낸다. 한 컴포넌트에만 그림자를
넣으면 앱에서 유일하게 그림자 있는 요소가 되어 톤이 깨진다.

요청자가 hover 예시로 "Shadow 약간 증가"를 들었으나, 위 이유를 설명하고 외곽선 강화 방식으로
합의했다. 그림자를 다시 검토하려면 이 절을 근거로 삼는다.

### 5. 대비는 계산해서 정한다

작은 글씨(≤12px)는 WCAG AA **4.5:1**을 기준으로 실측한 뒤 색을 고른다. 눈대중으로 "연하게"
두지 않는다. 보조 텍스트가 내려갈 수 있는 하한은 이미 정의된 `--ink-muted`다.

## 근거 (Rationale)

- 컴포넌트 단위면 **회귀 지점이 좁다.** 롤백한 변경은 12개 파일 1280줄이라 무엇이 문제인지
  가릴 수 없었다. 카드 하나는 2개 파일 63줄이다.
- 기존 값을 재사용하면 **일관성이 부수적으로 따라온다.** 토큰을 새로 만들면 "언제 무엇을 쓰나"를
  팀이 새로 배워야 한다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| **(선택) 컴포넌트 단위 + 기존 값 재사용** | 회귀 범위 좁음, 리뷰 가능, 학습 비용 0 | 전체 완료까지 회차가 많이 필요 |
| 표면 위계 토큰 신설 + 전 화면 일괄 적용 | 한 번에 일관됨, 재발 방지 | **실제로 롤백됨** — 레이아웃까지 바뀌고 리뷰 불가 |
| 화면별 CSS에 직접 값 추가 | 국소적 | 같은 스타일이 파일마다 복제됨 |

## 영향·후속 (Consequences)

### 계약·테스트

FE/BE 공유 계약 변경 **없음** — 시각 레이어만 바꾼다. 계약 테스트를 새로 추가하지 않는다:
[POLICY](../../harness/POLICY.md)의 "표준 CRUD·내부 헬퍼·UI 문구 → 불필요"에 해당한다.
회귀 없음은 매 회차 기존 테스트 전체 통과로 확인한다.

### 검증의 한계

이 저장소에 헤드리스 브라우저가 없어 **렌더링은 자동 검증할 수 없다.** 대신 회차마다
before/after를 실제 CSS로 렌더링한 HTML 문서를 만들어 사람이 대조한다. 시각 회귀 테스트
수단 도입은 별도 논의 대상이다.

## 4. 컴포넌트별 적용 기록

### 4.1 CurriculumCard — `/curriculums` (2026-08-04)

승인 범위: 카드 경계 · 대비/내부 위계 · 상호작용(미세) · 잘림 대응.

| 대상 | before | after | 근거 |
|---|---|---|---|
| 카드 외곽·표면 | `border: 0` · `transparent` | `1px --border-medium` · `--paper-light` | §3 — 내 커리큘럼 카드와 동일 |
| 표지 테두리 | 사방 `1px` | `border-bottom`만 | 카드 외곽선과 이중선이 됨 |
| 본문 여백 | `12px 0 0` | `13px 13px 12px` | 외곽선에 글자가 닿음. 5열 실측 폭 244.8px에서 제목 줄당 글자수가 이전과 같은 값 |
| 메타·푸터 색 | `--ink-500` 2.97:1 | `--ink-muted` 6.06:1 | §5 — 10.4px가 AA의 2/3 |
| 푸터 구분선 | `--border-medium` | `--border-soft` | 외곽선과 같은 강도면 안팎이 구별되지 않음 |
| hover | 반응 없음 | 외곽선 `--border-strong` + `translateY(-1px)` | §4 |
| focus 링 | 링크에 `offset: 4px` | 카드 경계에 `offset: 2px` | 키보드 탐색 단위가 카드 |
| 스켈레톤 | `border: 0` | 카드와 동일 | 로딩→완료 1px 밀림 방지 |

유지: radius `0` · `box-shadow: none` · 표지 높이 `138px` · **5열 그리드**.

승인 범위에 없어 **손대지 않은 것**: `pages.css`의 `.curriculum-progress > div`가 `--ink-500`
(3.16:1)을 유지한다. 이 클래스는 커리큘럼 상세 페이지와 공유하므로 별도 승인이 필요하다.

### 4.2 검색·정렬 도구줄 (`.catalog-controls`) — `/curriculums` (2026-08-04)

승인 범위: 포커스 복구 · 입력 가능성 · 작은 글씨 대비 · 지우기 버튼.

**포커스 표시가 완전히 없었다.** `pages.css`의 `.search-field input { outline: 0 }`(특이도 0,1,1)이
전역 `:focus-visible`(0,1,0)을 이기고, 그 위에 `design-system.css`가 `:focus-within`의
`border-color`·`background`·`box-shadow`를 모두 지워 남는 표시가 하나도 없었다 — WCAG 2.4.7
(Level A) 위반이다. 링을 입력이 아니라 **필드 껍데기**(`:focus-within`)에 걸어 복구했다.

| 대상 | before | after | 근거 |
|---|---|---|---|
| 검색창 포커스 | 표시 없음 | `outline: 2px --ink-950` + `offset: 2px` | 전역 `:focus-visible`과 같은 값. §4에 따라 그림자 대신 outline |
| 정렬 select 포커스 | `border-left` 색만 | 검색창과 같은 링 | 같은 도구줄의 두 입력이 같게 반응해야 함 |
| 검색창 테두리 | `border: 0` | **변경 없음** | 아래 "테두리 대신 면 색" 참고 |
| 검색창 면 색 | `transparent` | `--paper-pure` (1.08:1 vs 배경) | 배경보다 한 톤 밝게 들어올려 입력란으로 읽히게 함 |
| **정렬 select** | `transparent` + 좌측 구분선 | **변경 없음** | 면을 칠하지 않는다 — 아래 참고 |
| placeholder | 브라우저 기본 (~3.2:1) | `--ink-muted` (6.16:1) | 브라우저마다 2.3~3.7:1로 갈렸음 |
| 돋보기 | `--ink-950` (13.4:1) | `--ink-600`, 포커스 시 진해짐 | 아이콘이 placeholder보다 진해 라벨이 내용보다 강했음 |
| 지우기(×) | 글리프 ~19px · `--ink-500` | `24×24px` · `--ink-700` (7.57:1) · hover·focus | 터치 타겟 부족, 아이콘 버튼에 상태 없음 |
| 개수·초기화·업데이트 안내 | `--ink-500` 2.97:1 | `--ink-muted` 5.69:1 | §5 — 4.1과 같은 처방 |

유지: 3칸 그리드 비율 · 필드 높이 `42px` · `radius: 0` · 요약 우측 구분선 · 디바운스·정렬 동작.

#### 테두리 대신 면 색 — 시안을 두 번 뒤집었다

1. **테두리로 감쌈**: `1px solid --ink-500`(3.22:1)로 두 입력을 둘렀다. 기존 토큰 중 비텍스트
   3:1에 닿는 유일한 값이라 골랐다. → *"네모 칸 씌운 거 너무 안 예쁘다. 그냥 색깔로 차별만 두자"*
2. **두 칸을 어둡게 채움**: 테두리를 걷고 `--ink-200`(1.26:1)으로 내려앉혔다. 밝은 쪽이 배경과
   1.08:1로 거의 같아 어두운 쪽을 골랐다. → *"최신순은 바탕 색에 아무 변경사항 없어야 하고,
   검색창은 한 톤 어둡게가 아니라 한 톤 밝게"*
3. **확정**: 검색창만 `--paper-pure`(1.08:1)로 한 톤 밝게, **정렬 select은 원본 그대로**.

3안의 근거가 결과적으로 더 낫다 — **도구줄에서 실제로 타이핑하는 칸은 검색창 하나**다. 두 칸을
같은 무게로 칠하면 "입력"과 "선택"이 다시 뭉개진다. 밝은 면은 어두운 면보다 그 위 글자 대비도
높다(placeholder 6.16:1 vs 4.51:1).

**대가**: WCAG 1.4.11(비텍스트 대비, AA)은 입력 요소의 *경계*에 3:1을 요구한다. 면 색만으로는
이 팔레트에서 어떤 값을 골라도 3:1에 닿지 못한다 — `--paper-pure`가 1.08:1이고, 3:1을 만들려면
회색이 한참 어두워져 1안에서 반려된 그 무게가 된다.

**남는 것**: 포커스 상태는 온전하다 — 13.4:1 링이 붙어 WCAG 2.4.7(Level A)을 넘는다. 키보드
사용자에게 필요한 대비는 링이 담당하고, 마우스 사용자용 구분은 톤을 위해 1.08:1에서 멈춘다.
**보기 좋음을 택한 의도된 트레이드오프**이며, 이 판단을 뒤집으려면 이 절을 근거로 삼는다.

정렬 select은 `height`·`margin-block`·`border`·`border-left`·`border-radius`·`background`가
**원본과 값이 완전히 같다.** 720px·480px 구간의 `border-left`/`border-top`도 원래 값이다.
이 칸에 더한 것은 `:focus-visible` 링 하나뿐이다.

반영 범위는 이 도구줄에 한한다. 폼 입력(`.form-grid input` 등)과 인증 화면(`.input-shell`)은
여전히 다른 규칙을 쓰므로, 그 회차에서 같은 방식으로 맞출지 따로 결정한다.

### 4.3 페이지네이션 (`.pagination`) — 공유 3곳 (2026-08-04)

승인 범위: 말줌임 대비 · 화살표 테두리. (제안한 4개 중 2개만 승인)

`.pagination`은 **커리큘럼 탐색 · 내 커리큘럼 · 수강생 명단**이 공유한다. 화살표는 커리큘럼
탐색에만 있고 나머지 둘은 숫자만 렌더링한다.

| 대상 | before | after | 근거 |
|---|---|---|---|
| 화살표 테두리 | `--ink-200` 1.26:1 | `--ink-400` 2.07:1 | 원형 컨트롤의 경계가 보이지 않았음 |
| 말줌임(…) | `--ink-500` 2.97:1 | `--ink-muted` 5.69:1 | §5 — 4.1·4.2와 같은 처방 |

유지: 39×39 크기 · `gap: 6px` · 배치 · `margin-top` 값들 · 붓터치 현재 페이지 표시 · 포커스 링.

**붓터치는 손대지 않았다.** `pagination-ink-stroke.png`를 디코딩해 재보니 512×135 원본에 중앙부가
완전 불투명 검정이고 흰 글자 대비가 **19.43:1**이다. 48×24로 축소해도 해상도가 충분하며 이 테마의
정체성이다. 포커스도 이미 정상이다 — 검색창과 달리 `outline: 0`이 없어 전역 링이 그대로 걸린다.

숫자 버튼에는 새 테두리가 걸리지 않는다: `.pagination .pagination__number`(특이도 0,2,0)의
`border: 0`이 `.pagination button`(0,1,1)을 이긴다.

부수 효과: `disabled`의 `opacity: 0.35`를 그대로 두었으나 테두리 색이 진해진 덕에 disabled
화살표 테두리도 1.08:1 → 1.26:1로 함께 올랐다.

승인받지 않아 **손대지 않은 것**:
- **Disabled 화살표**(A안). `opacity: 0.35`가 글리프를 **1.58:1**로 만들어, 첫 페이지의 `←`가
  "갈 수 없다"가 아니라 **"버튼이 없다"**로 읽힌다. 원 브리핑의 "Disabled를 단순히 흐리게만
  처리하지 말 것"에 걸리는 지점이다. 제안했던 처방: `opacity: 1` + 글리프 `--ink-500`(2.97:1)
  + 테두리 `--border-soft`.
- **Hover 피드백**(C안). 숫자 버튼은 테두리·배경이 없어 hover가 색 변화뿐이다. 면으로 주려 해도
  이 팔레트에서 hover 면은 최대 1.26:1이라 보이지 않으므로 밑줄을 제안했다. 화살표 hover는
  `--blue-200`/`--blue-600`(회색 별칭)에 의존해 의도가 코드에 드러나지 않는다.
- `.pagination__status`는 어느 `.tsx`에서도 쓰이지 않는 죽은 셀렉터다.

화살표 테두리를 `--ink-500`(2.97:1)까지 올리면 3:1에 닿지만 톤을 위해 `--ink-400`에서 멈췄다.
지금까지 세 회차 모두 요청자가 더 절제된 쪽을 택해 왔다는 판단이다.

승인 범위에 없어 **손대지 않은 것** 둘:
- `.catalog-controls`의 `border-bottom: --ink-950`(13.4:1). 필드에 테두리가 생겨 역할이 겹치지만,
  이 선은 도구줄과 목록을 가르는 **구조선**이라 약화하면 페이지의 구조 인상이 바뀐다. 미세 조정
  범위를 넘는다고 보아 제안에서 뺐다.
- **입력 radius가 앱에서 두 가지다.** 이 도구줄은 `0`, `.input-shell`(인증)과 워크스페이스 폼
  입력은 `6px`. 카탈로그 영역은 카드도 `0`이라 국소적으로는 일관되나 전역으로는 어긋난다.
