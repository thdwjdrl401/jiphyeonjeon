# ADR-0091: 커리큘럼 운영 기간은 날짜만 입력하고 서버 경계 시각으로 변환한다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-08-06
- **관련**: Sub Ⅱ · [ADR-0086](0086-curriculum-period-editable-in-manage-info-tab.md)(운영 기간 관리)

## 맥락 (Context)

커리큘럼 생성·관리 화면은 운영 시작일과 종료일에 `datetime-local`을 사용했다. 운영 기간은 강사가
날짜 단위로 정하는 정책인데 시·분까지 요구해 불필요한 결정을 만들고, 같은 날 운영하는 커리큘럼도
`종료 ≤ 시작` 검증 때문에 표현할 수 없었다.

서버 계약의 `startsAt`/`endsAt`은 `OffsetDateTime`이므로 프론트 입력만 날짜로 바꾸더라도 저장 시에는
명확한 시각 경계로 변환해야 한다.

## 결정 (Decision)

- 생성 화면과 관리 화면의 공용 운영 기간 입력을 `date`로 바꾼다.
- 시작일은 사용자 지역 시각의 `00:00:00.000`, 종료일은 `23:59:59.999`로 변환해 ISO-8601로 보낸다.
- 서버 값을 다시 표시할 때는 사용자 지역 날짜인 `YYYY-MM-DD`만 꺼낸다.
- 종료일이 시작일보다 빠를 때만 거절한다. 두 날짜가 같으면 1일 과정으로 허용한다.
- 라이브 강의 예정 시각은 실제 시작 시간이 필요하므로 기존 `datetime-local` 입력과 변환을 유지한다.

## 근거 (Rationale)

- 종료일을 자정으로 보내면 종료일 당일 대부분이 운영 기간 밖으로 판정될 수 있다. 하루의 마지막
  시각을 사용하면 사용자가 선택한 종료일 전체가 포함된다.
- 날짜 문자열을 `new Date('YYYY-MM-DD')`로 직접 해석하면 UTC 날짜가 되어 지역에 따라 하루가 어긋날
  수 있다. 연·월·일을 지역 시각으로 조립한 뒤 ISO로 변환한다.
- API 필드와 타입은 바꾸지 않고 프론트의 표시·변환 정밀도만 바꾸므로 백엔드 수정이 필요 없다.

## 영향·후속 (Consequences)

- 기존에 시각까지 저장된 운영 기간은 관리 화면에서 날짜만 보인다. 사용자가 날짜를 수정하면 시작은
  그날의 시작, 종료는 그날의 끝으로 정규화된다.
- 기간 미정(null/null), 한쪽만 입력한 기간의 저장 보류, 과거 종료일 거절 규칙은 유지된다.
- 하네스: **계약 테스트 불필요**(POLICY 🟢). API 필드명·상태코드·DTO 형식은 그대로이며 UI 입력과
  프론트 변환만 바뀐다. 대신 단위 테스트로 날짜 경계 변환과 1일 과정을, 통합 테스트로 생성·관리
  저장 왕복을 검증한다.
