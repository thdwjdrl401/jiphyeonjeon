# ADR-0088: 프로필은 조회 후 수정하고 커리큘럼 사용 흐름을 정돈한다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md) · 계약: [../../CONTRACT.md](../../CONTRACT.md)

- **상태**: 채택
- **일자**: 2026-08-06
- **관련**: [0011](0011-profile-page-compaction.md)(프로필 화면 배치), [0086](0086-curriculum-period-editable-in-manage-info-tab.md)(커리큘럼 관리 화면)

## 맥락

학생 프로필은 진입 즉시 편집 폼을 노출했고, 강사 공개 프로필도 조회와 수정 상태가 구분되지 않았다.
또한 여러 하위 화면에서 상단 메뉴가 넓게 활성화되어 현재 위치와 메뉴 밑줄이 일치하지 않았고, 학생의
승인 대기·학습 중 커리큘럼은 서로 다른 목록이라 한 상태 필터로 찾을 수 없었다. 녹화강의 업로드도
라이브 강의 생성 화면과 정보 배치가 달라 같은 저작 흐름에서 학습 비용이 생겼다.

## 결정

1. 학생과 강사 모두 프로필 진입 시 정보를 읽기 전용으로 표시하고 `프로필 수정` 버튼으로 닉네임과
   이미지를 수정한다. 이는 [0011] §7의 학생 인라인 편집 결정을 대체한다.
2. 강사는 기본 프로필과 별개인 `공개 프로필 수정` 버튼으로 소개와 전문 분야를 편집한다.
3. 상단 `커리큘럼 탐색`은 탐색 목록에서만 활성화한다. `마이 페이지`는 역할별 커리큘럼 목록,
   강사 커리큘럼 관리, 프로필, 전체 알림에서만 활성화하며 그 밖의 상세·편집·학습 화면에서는
   활성 밑줄과 메뉴 호버 밑줄을 표시하지 않는다.
4. 학생 내 커리큘럼은 승인 대기와 활성 수강을 한 목록으로 합치고 `수강 신청 대기 중`, `학습 중`,
   `학습 완료` 필터를 제공한다. 별도 완료 상태가 없는 현재 계약에서는 강의가 하나 이상이며 진도가
   100%인 활성 수강을 완료로 해석한다.
5. 새 섹션 설명은 빈 값으로 만들고 안내 문구는 placeholder로만 표시한다. 과거 UI가 저장한 안내
   문구는 화면 진입 시 제거하되, 안내 문구 사이에 입력된 사용자 텍스트는 보존한다.
6. 녹화강의 업로드는 라이브 강의 생성과 같은 2열 저작 레이아웃을 사용한다. 왼쪽은 기본 정보와
   PPTX 자료, 오른쪽은 MP4 업로드와 파일·자동 처리 정책 확인 영역으로 구성한다. MP4는 한 개만
   선택할 수 있고 선택 후에는 영상 썸네일, 파일명, 교체·삭제 동작을 한 카드에 표시한다.

## 근거

- 조회와 수정 상태를 구분하면 프로필을 확인하려는 사용자가 입력 폼을 편집 상태로 오인하지 않는다.
- 기본 프로필과 강사 공개 정보를 별도 진입점으로 두면 공개 범위가 다른 필드를 구분할 수 있다.
- 활성 경로를 명시적으로 제한하면 상세·편집 화면에서 상위 메뉴가 현재 위치인 것처럼 보이지 않는다.
- 수강 상태를 한 목록과 한 필터로 합치면 승인 전후에 목록 위치가 바뀌지 않는다.
- 녹화·라이브 저작 화면의 정보 구조를 맞추면 강사가 강의 유형마다 다른 레이아웃을 다시 익힐 필요가
  없다.

## 영향

- FE 화면·라우팅·표시 상태만 변경한다. API 요청/응답 필드와 상태코드는 변경하지 않는다.
- 완료 판정은 현재 수강 응답의 `enrollmentStatus`, `lessonCount`, `progress`를 조합한 화면 파생값이다.
- 녹화 영상의 HLS 변환, AI 자막, 자동 공개 문구는 기존 녹화강의 계약의 자동 처리 정책을 설명하며
  새로운 조절 API를 만들지 않는다.
- 관련 통합 테스트로 역할별 프로필 진입, 허용 경로의 메뉴 활성, 학생 통합 상태 목록, 섹션 placeholder,
  녹화 업로드 레이아웃과 제출 흐름을 고정한다.
