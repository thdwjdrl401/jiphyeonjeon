# ADR-0007: 스피커 테스트음은 외부 음원을 쓰지 않고 Web Audio로 합성한 금속 타격 차임으로 만든다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-07-30
- **관련**: 브랜치 `feat/fe/speaker-test-coin-chime`, `frontend/src/features/live-session/speakerTest.ts`

## 맥락 (Context)

입장 전 점검(`StudentPrejoinPage`)의 스피커 테스트음이 **부저처럼 거칠게 들린다**는 요청을 받았다.
레퍼런스로 유튜브 영상 하나가 지정됐다(`XtFzulfX1iA`).

기존 구현은 사인파 하나를 구간 내내 일정 음량으로 끄는 방식이었다 —
`attack(30ms) → 일정 음량 유지 → release(120ms)`, C5·E5·G5. 이 화면은 학생이 입장할 때마다,
경우에 따라 "다시 듣기"로 여러 번 듣는다. 그래서 음색의 자극이 그대로 피로가 된다.

확인 결과 **레퍼런스 영상은 「코인 소리」라는 제목의 효과음 클립**이고(채널 `산딕이의효과음저장소`),
스테레오 테스트음 데모가 아니었다. 요청 문구의 "Chime 계열"과 영상의 실제 내용(짧고 밝은 금속
타격음)이 완전히 같지는 않으므로, **영상을 "음색 레퍼런스"로만 받아들이고 재생 흐름은 기존 것을
유지**하는 것으로 범위를 정리했다.

## 결정 (Decision)

1. **외부 음원 파일을 쓰지 않는다.** 레퍼런스 음원도, 대체 음원도 내려받지 않고 Web Audio
   `OscillatorNode`로 직접 합성한다.
2. **음색은 "금속을 한 번 때린 차임"이다** — 코인·글로켄슈필 계열. 구현은 가산 합성으로,
   배음 6개(`CHIME_PARTIALS`)를 타격 엔벨로프로 감싼다.
3. **배음 구성은 역할을 둘로 나눈다.**
   - **몸통**(1·2·3.01배음, 0.17초 이상 남음) — 음높이와 종 같은 밝기. 협음이라 반복해도 거슬리지 않는다.
   - **타격 색**(2.76·5.42·8.93배음, 0.06초 안에 사라짐) — 양단 자유 금속 막대의 실제 진동 모드비.
     비정수배가 '금속'이라는 인상을 만든다.
4. **엔벨로프에 유지 구간(plateau)을 두지 않는다.** `2ms 어택 → 급감 → 조용한 여운`.
   감쇠는 **두 단계로 꺾는다**(`DECAY_KNEE_AT`·`DECAY_KNEE_GAIN`).
5. **음역을 한 옥타브 올린다** — C5·E5·G5 → **C6·E6·G6**.
6. **노이즈 계열(화이트·핑크)은 쓰지 않는다.** 금속 질감은 노이즈가 아니라 짧은 비정수배 배음으로 만든다.
7. **재생 흐름·시간은 손대지 않는다.** 좌(0ms) → 우(1000ms) → 양쪽(2000ms), 800·800·950ms, 총 약 2.95초.
   `StereoPanner` 값도 -1·+1·0 그대로다.
8. **음량은 한 곳(`PEAK_GAIN`)에서만 정한다.** 배음 피크의 합이 1이 되게 정규화한 뒤 곱한다.

## 근거 (Rationale)

- **외부 음원을 쓰지 않은 이유**: 레퍼런스는 개인 효과음 채널의 유튜브 업로드다. 표준 YouTube
  라이선스는 플랫폼 외부 재배포를 허용하지 않고, 업로더가 원저작자인지도 확인할 수 없다. 우리 제품에
  번들해 배포하면 **출처 불명 음원을 재배포하는 것**이 된다. 합성은 이 문제를 원천적으로 없앤다 —
  덤으로 네트워크 요청·번들 용량·디코딩 실패 처리도 사라진다. 요청에서도 "직접 생성"을 허용했다.
- **부저와 악기를 가르는 것은 음높이가 아니라 (1) 배음과 (2) 엔벨로프다.** 사인파 하나는 배음이
  없어 기계음으로 들리고, 음량을 유지하는 구간이 있으면 "울리는 소리"가 아니라 "켜져 있는 소리"가 된다.
  실제 악기는 때린 순간이 가장 크고 계속 잦아든다.
- **감쇠를 두 단계로 꺾는 이유**: 최고점에서 무음까지 `exponentialRamp` 하나로 내리면 dB가 일정한
  속도로 떨어져 기계적으로 들린다. 실제 금속 타격음은 직후 급격히 작아지고 그 뒤 작은 음량이 길게
  남는다. 이 꺾임 하나가 "때렸다"는 인상을 만든다.
- **타격 색 배음의 gain을 낮게 두지 않은 이유**: 처음엔 0.05~0.12로 잡았는데, 10ms 창으로 타격 순간의
  스펙트럼을 재 보니 **고역이 전체의 4.6%뿐이라 금속 질감이 사실상 들리지 않았다.** 0.12~0.30으로
  올려 10.4%까지 맞췄다. 감쇠가 짧아서 이 정도로 올려도 여운에는 불협으로 남지 않는다.
- **음역을 올린 이유**: 노트북 내장 스피커는 500Hz 아래를 거의 못 낸다. C5(523Hz)는 있는 힘껏 내도
  빈약하게 들리는데 C6(1046Hz)와 그 배음은 내장 스피커가 가장 잘 내는 대역에 들어온다. 고역이 좌우
  정위(ILD)도 더 뚜렷하게 만들어 "좌우를 명확히 구분"이라는 요구에 함께 맞는다.
- **`PEAK_GAIN`이 기존 부저(0.18)보다 큰 이유(0.55)**: 감쇠음은 같은 진폭이라도 실제 에너지(RMS)가
  유지음의 4분의 1 수준이다. 같은 숫자를 쓰면 "소리가 작아졌다"가 되고, 확인해야 할 소리가 작아지면
  스피커 테스트 자체가 무의미해진다. 정규화 덕에 실측 최고점은 0.39로 **8.1dB 헤드룸이 남는다.**
- **구간당 한 번만 때리는 이유**: 한 구간에서 두 번 때려 보면(낮은음 → 높은음) 두 여운이 겹쳐 두 음이
  아니라 뭉개진 한 덩어리로 들린다.
- **정규화를 두는 이유**: 배음이 동시에 최고점을 지날 때 합이 1을 넘으면 클리핑이 나고, 클리핑은 정확히
  "거친 부저" 소리다. 음량을 키우려다 음색을 망치는 경로를 구조적으로 막는다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| **(선택) Web Audio 가산 합성** | 저작권·번들·네트워크 문제 없음, 파라미터로 음색 조정 가능, 좌우 분리를 코드로 보장 | 음색을 코드로 튜닝해야 함(귀로 확인 필요) |
| (기각) 레퍼런스 음원 직접 사용 | 레퍼런스와 100% 동일 | 표준 YouTube 라이선스는 외부 재배포 불허, 원저작자 확인 불가 |
| (기각) CC0 효과음 파일 번들 | 음질이 좋고 구현이 단순 | 에셋 관리·번들 용량·디코딩 실패 처리가 생기고, 출처 검증 부담이 남는다 |
| (기각) 노이즈 버스트 계열 | 전 대역을 한 번에 확인 가능 | 요청에서 명시적으로 배제. 좌우 정위가 흐려지고 '쉭' 소리가 거슬린다 |
| (기각) 사인파 유지 + 음량만 낮추기 | 변경 최소 | 부저 느낌의 원인은 음량이 아니라 배음 없음·유지 구간이다 |

## 영향·후속 (Consequences)

- **FE**: `speakerTest.ts`의 `scheduleTone` → `scheduleChime`으로 교체.
  `SPEAKER_TEST_STEPS`의 `frequency`만 한 옥타브 올렸고 `startMs`·`durationMs`는 그대로다.
  공개 API(`playSpeakerTest`·`SPEAKER_TEST_STEPS`·`SPEAKER_TEST_CHANNEL_LABEL`·
  `SPEAKER_TEST_DURATION_MS`)와 `StudentPrejoinPage`는 **변경 없다.**
- **BE·계약**: 없음. API 요청/응답 필드·상태코드와 무관한 FE 내부 구현이라
  [POLICY](../../harness/POLICY.md) 기준 **계약 테스트 대상이 아니다.**
- **단위 테스트**: 계약은 없지만 `speakerTest.test.ts`가 이미 있었고, "귀로만 확인되는 부분"과
  "코드로 고정할 수 있는 부분"을 가르는 것이 이 기능의 핵심이라 후자를 확장했다(14개).
  특히 **좌우 분리(pan `[-1, 1, 0]`)**, **유지 구간 없음**, **감쇠 꺾임 존재**, **비정수배 배음 존재**,
  **음량 이중 적용 방지**를 못 박았다 — 전부 화면만 봐서는 회귀를 알 수 없는 항목이다.
- **음색 검증 방법**: 단위 테스트는 소리를 듣지 못한다. 그래서 `speakerTest.ts`의 상수를 그대로
  파싱해 WAV로 오프라인 렌더링하고 실측했다 — 최고점 0.394(클리핑 없음, 헤드룸 8.1dB),
  좌/우 구간의 **반대 채널 누출 0.000**, 구간 사이 침묵 0.00000(겹침 없음),
  타격 최고점 2.8ms(기존 부저 35.8ms), -20dB까지 182ms(기존 716ms).
  이 스크립트는 일회성 검증 도구이므로 저장소에 커밋하지 않는다.
- **후속**: 최종 음색은 사람이 들어봐야 확정된다. 조정이 필요하면 만질 손잡이는 세 개다 —
  밝기는 `CHIME_PARTIALS`의 타격 색 3줄 gain, 길이는 기본음 `decaySec`,
  "때린 느낌"의 세기는 `DECAY_KNEE_GAIN`(작을수록 급감이 크다).
