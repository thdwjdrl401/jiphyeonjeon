# ADR-0097: 코드 블록은 밝힌 언어만 칠한다 — 그리고 하이라이터를 직접 붙인 이유

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 아키텍처: [../../ARCHITECTURE.md](../../ARCHITECTURE.md) · 계약: [../../CONTRACT.md](../../CONTRACT.md)

- **상태**: 채택
- **일자**: 2026-08-07
- **관련**: [0096](0096-ai-answers-render-as-markdown.md)(AI 답변 Markdown — **이 결정의 전제**),
  [0086](0086-resource-ceilings-we-choose.md)(우리가 정하는 상한)
- **오너 경계**: FE — 렌더러·번들 / BE — 없음

## 맥락

[ADR-0096](0096-ai-answers-render-as-markdown.md)에서 AI 답변을 Markdown으로 그리기 시작했고, 코드
블록은 등폭 글꼴 상자로만 남겼다. **여기는 코딩을 가르치는 화면이다** — 강조가 있는 편이 낫다.

### 먼저 재 본 것 — 근거가 생각보다 약하다

운영 DB의 라이브 AI 답변 **126건**(2026-08-03~08-07)을 전수로 셌다.

```
전체 126 · 코드 펜스 0 · 백틱 0 · 굵게 0 · 목록 0 · 제목 0
평균 길이 106자 · 최장 577자
```

**코드는커녕 Markdown 자체가 하나도 없다.** 그런데 화면에서는 실제로 Markdown이 보인다 —
`live_ai_answer`에 쌓이는 것은 **라이브 갈래뿐**이고, 업로드 녹화강의(`RECORDED`) 답변은
라이브 세션이 없어 **기록을 남기지 않기 때문이다**(`docs/CONTRACT.md` §3-9).

즉 **관찰된 갈래를 우리는 측정할 수 없다.** 이 결정은 측정이 아니라 판단으로 내린다는 뜻이고,
그 사실을 여기 적어 둔다. 따라오는 것 하나: **RECORDED AI 답변에는 관측 수단이 없다.**
빈도·품질·실패를 알 방법이 지금 없다(후속으로 다룬다).

## 결정 1 — `rehype-highlight`를 쓰지 않는다

표준 선택지인데 **번들이 줄지 않는다.** `rehype-highlight/lib/index.js`가 이렇게 시작한다.

```js
import {common, createLowlight} from 'lowlight'   // 37개 언어를 통째로
```

`languages` 옵션은 무엇을 **등록**할지만 정하고 무엇을 **내려보낼지**는 못 정한다. 실측이 그대로다.

| 구성 | MarkdownBody 청크(gzip) | 기준 대비 |
|---|---|---|
| 강조 없음(ADR-0096 상태) | 47.5 kB | — |
| `rehype-highlight`, 언어 9개 등록 | 101.3 kB | **+53.7** |
| `rehype-highlight`, **언어 1개** 등록 | 101.2 kB | **+53.7** ← 줄지 않는다 |
| `lowlight` 직접, 언어 1개 | 57.5 kB | +9.9 |
| **`lowlight` 직접, 언어 9개(채택)** | **69.3 kB** | **+21.8** |

그래서 `lowlight`를 직접 쓰고 고른 언어만 import하는 40줄짜리 rehype 플러그인을 둔다
(`shared/ui/rehypeCodeHighlight.ts`). 탐색도 `unist-util-visit`를 끌어오지 않고 직접 돈다 —
찾는 것이 `pre > code` 하나뿐이라 전이 의존을 직접 import할 값이 없다.

**이 청크는 지연 로드된다**(ADR-0096). 로그인 화면은 한 바이트도 더 받지 않고, 강의를 여는 사람만
+21.8 kB를 받는다.

### 언어 9개

`java` · `javascript` · `typescript` · `python` · `sql` · `bash` · `json` · `xml` · `css`.

운영 커리큘럼 44개의 제목 분포로 골랐다(Java·Spring 4 / React·JS·TS 3 / Python 1 / SQL 1).
뒤의 넷은 어떤 수업에서든 나오는 것이고 `xml`이 HTML도 맡는다. 8개를 더한 값이 11.8 kB이므로
(하나당 ~1.5 kB) 여기서 더 줄일 이유가 없다.

## 결정 2 — 자동 감지를 켜지 않는다

언어를 밝힌 코드(` ```java `)만 칠하고, 안 밝혔으면 예전처럼 등폭 상자로 둔다.

**여기는 코드를 가르치는 화면이라 잘못 칠한 색이 색이 없는 것보다 나쁘다.** 자동 감지는 짧은
조각에서 자주 틀리는데 — 답변 평균이 106자다 — 학생은 색을 문법의 근거로 읽는다. `String`이
키워드 색으로 칠해지면 그것이 키워드라고 배운다.

칠하지 않는 것은 **아무것도 잃지 않는다**. ADR-0096 이전 화면과 같다.

## 결정 3 — 색은 다섯 갈래뿐이다

highlight.js는 토큰을 30여 개 낸다. 그대로 칠하면 코드 한 줄이 색 견본이 되고, 무엇보다 이 제품의
색이 **먹과 인장**뿐이다(수묵 모노톤). 무지개 하이라이팅은 화면 전체와 싸운다.

```
키워드   인장 붉은색 + 굵게      ← 붉은색을 쓰는 유일한 곳
문자열   먹빛 초록
주석     흐린 먹 + 이탤릭
이름     가장 진한 먹
숫자     본문보다 한 단계 진하게
```

색은 CSS 변수로 두고 **잉크 모드는 변수만 다시 정의한다**(`design-system.css`) — 갈래와 굵기는
한 곳에서만 정한다.

## 결정 4 — 덜 온 코드에도 터지지 않는다

스트리밍 중에는 따옴표가 안 닫히고 괄호가 열린 채로 들어온다. highlight.js는 그런 입력도 최선으로
칠하지만, 혹시 던지면 **답변 전체가 빈 화면이 된다.** 감싸서 실패하면 강조만 포기하고 코드는 남긴다.

## 남겨 둔 것

**RECORDED 갈래의 관측 수단.** 위에서 적었듯 업로드 녹화강의 AI 답변은 어디에도 남지 않아서
빈도도 품질도 실패도 알 수 없다. 이번 변경의 범위 밖이지만 **이 결정을 근거 없이 내리게 만든 원인**
이므로 따로 다룬다.

**줄 번호·복사 버튼.** 코드가 실제로 자주 나오는 것이 확인되면 그때 본다. 지금은 근거가 없다.
