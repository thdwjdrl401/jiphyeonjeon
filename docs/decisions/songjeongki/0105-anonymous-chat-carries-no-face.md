# ADR-0105: 익명 채팅은 얼굴을 싣지 않는다

> 관련 결정: [ADR-0050 익명은 발신자 선택이다](0050-chat-anonymity-is-sender-choice.md) ·
> [ADR-0023 익명 가명은 등장 순번이다](../yoongwanghyeok/0023-anonymous-chat-alias-is-sequential.md)

- **상태**: 채택
- **일자**: 2026-08-08
- **적용 범위**: 채팅 REST 응답·WS 브로드캐스트의 `avatarUrl`, `UserDirectory` 포트

## 맥락

채팅에 프로필 사진을 보이게 해 달라는 요구가 들어왔다. 지금은 이름에서 만든 **이니셜 아바타**뿐이다.

단순한 필드 추가처럼 보이지만 아니다. 채팅 응답은 [ADR-0050](0050-chat-anonymity-is-sender-choice.md)에
따라 **이름을 `alias` 한 필드로만** 내보내고 `userId`조차 담지 않는다. 발신자가 익명을 골랐는지
수신자가 알 수 없게 하려는 설계다.

여기에 사진 URL을 그냥 실으면 **그 설계가 무너진다.** 이름을 가려도 사진이 실리면 사람이 특정된다 —
같은 강의를 듣는 사람들끼리는 얼굴을 알고, 프로필 사진은 대개 얼굴이다. 게다가 URL은 사용자마다
고정이라, 여러 익명 발언이 **같은 사람의 것임을 잇는 열쇠**도 된다(가명 번호는 세션마다 새로 도는데
URL은 그렇지 않다).

## 결정

### 1. 익명 메시지에는 `avatarUrl`이 실리지 않는다

REST 응답과 WS payload 모두 익명이면 `null`이다. 사진을 올리지 않은 사용자도 `null`이다 — 화면은
그때 이니셜로 채운다.

### 2. 그 판단을 호출자에게 맡기지 않는다

`ChatMessageResponse.from`은 `userId → URL` 지도를 받되, **익명이면 그 지도를 보지 않는다.**

```java
m.isAnonymous() ? null : avatarUrls.get(m.getUserId())
```

호출자가 실수로 익명 발신자의 URL을 지도에 섞어 넣어도 **새어 나갈 길이 없다.** 프라이버시 규칙이
호출 규약이 아니라 **구조**가 되어야 하는 자리다 — 규약은 다음 사람이 모른 채로 어길 수 있다.

WS 경로도 같다. `ChatService`가 익명이면 **조회조차 하지 않는다**. `null`을 넣는 것으로 충분해
보이지만, 손에 없는 것은 실을 수 없다.

### 3. 사진은 저장 시점이 아니라 **읽는 시점**에 해석한다

`sender_name`은 저장 시점에 확정해 둔다(가명 번호가 세션에 묶여야 하므로). 사진은 반대로 둔다 —
프로필을 바꾸면 지난 메시지에도 새 사진이 보이는 편이 사람이 기대하는 동작이고, 컬럼을 늘리지
않아도 된다. **이 결정 덕분에 마이그레이션이 없다.**

대신 N+1을 막아야 한다. `UserDirectory.findAvatarUrls(Collection<UUID>)`를 더해 **사람 수만큼만**
왕복한다(메시지 수가 아니다 — 한 사람이 열 줄을 말해도 한 번). 구현은 사용자 배치 조회 →
에셋 URL 배치 해석 두 단계다.

### 4. 익명 발신자는 애초에 묻지 않는다

컨트롤러가 지도를 만들 때 익명 메시지는 걸러낸다. §2가 있어 새지는 않지만, **필요 없는 사람의
presigned URL을 만들 이유가 없다** — presigned는 만드는 순간부터 유효하다.

## 결과

- 실명으로 보낸 채팅에 프로필 사진이 보인다. 사진이 없으면 예전처럼 이니셜이다.
- 익명 채팅은 가명 + 이니셜 폴백(`?`)으로 남는다. 이름으로도 사진으로도 특정되지 않는다.
- 스키마 변경이 없다 — Flyway 마이그레이션도, 번호 충돌 위험도 없다.
- 채팅 목록 한 페이지의 추가 왕복은 **사람 수 기준 두 번**이다.

## 검증

- `ChatAvatarPrivacyTest` **3건(신규)** — **지도에 URL이 있는데도** 익명 메시지에 실리지 않는지 ·
  익명이 아니면 실리는지 · 사진이 없으면 `null`인지.
- **돌연변이 확인**(실제로 되돌려 돌려 봤다): `m.isAnonymous() ? null :` 가드를 지우면 첫 번째가 깨진다.
- `ChatContractTest` — 실제 HTTP 응답에서 익명 메시지의 `avatarUrl`이 `null`인지(배선 확인).
- `chatMessageAlignment.test.tsx` **3건(신규)** — 사진이 있으면 `<img>`를 그리는지 · 없으면 이니셜인지 ·
  익명이면 사진도 이니셜도 아닌 `?`인지.
- FE 전체 1255건 통과, `tsc`·`eslint --max-warnings 0` 클린. BE `ChatContractTest`·`ChatAvatarPrivacyTest` 통과.

## 남은 것

**낙관적 항목(전송 중)에는 사진이 없다.** 서버 에코가 오면 채워진다 — 짧은 순간 이니셜로 보였다가
사진으로 바뀐다. 내 사진 URL을 로그인 세션에 들고 있으면 없앨 수 있지만, 지금 `/me` 응답은 그 값을
항상 담지 않는다. 그 경로를 넓히는 편이 나아 보여 여기서는 손대지 않았다.
