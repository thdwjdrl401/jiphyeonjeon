# ADR-0058: 판서 해석 이미지는 **본문에 싣지 않고 URL로** 준다

> 📍 계약: [../../CONTRACT.md](../../CONTRACT.md) · 관련: [0054](0054-annotation-ai-semantics-not-coordinates.md)(판서 AI는 의미만 묻는다)

- **상태**: 채택 (설계 확정)
- **일자**: 2026-08-02
- **오너 경계**: BE·FE(송정기)

## 맥락 (Context)

판서를 크게 그린 뒤 정리를 누르면 해석이 **502로 실패한다.** 작게 그리면 된다.

원인을 찾는 데 오래 걸린 이유는 오류 문구가 원인을 가리키지 않기 때문이다. 상류(GMS)가 돌려준 것은:

```
status=400  {"message":"[GMS 에러] Model not found in request for domain api.openai.com"}
```

모델 이름 문제로 읽힌다. 그런데 같은 이름으로 작은 요청을 보내면 통과한다. 본문 크기를 이진 탐색해 경계를 찾았다(실측 2026-08-02):

| 요청 본문 | 결과 |
|---|---|
| 1KB ~ 99,000 B | 통과 |
| **102,400 B** | `Model not found in request` |

**게이트웨이의 본문 한도(~100KB)** 다. 넘으면 본문을 읽지 못하고 "모델이 없다"고 답한다.

우리는 이미지를 `data:image/png;base64,...`로 요청 본문에 실어 왔다. 판서가 커질수록 본문이 커지므로 이 한도에 반드시 닿는다.

## 결정 (Decision)

**이미지를 본문에서 뺀다.** 모델에는 `image_url`에 **URL**을 준다. 본문은 수백 바이트로 고정되고 이미지 크기와 무관해진다.

```
{"model":"gpt-4.1","messages":[{"role":"user","content":[
  {"type":"text","text":"..."},
  {"type":"image_url","image_url":{"url":"https://…/api/annotation-interpret-images/<token>"}}]}]}
```

받아가는 쪽이 모델 제공자의 서버이므로 그 주소는 **인터넷에서 닿아야 한다.** 실증했다 — GMS를 거쳐 우리 도메인의 이미지를 정상적으로 읽어 응답했다(본문 288 B).

### 어디에 두나 — 메모리, 디스크가 아니라

이 이미지는 **모델이 한 번 읽고 버리는 것**이다. 저장소에 두면 수명주기 관리(정리 정책·TTL·용량)가 따라붙는데 얻는 것이 없다. 메모리에 두고 호출이 끝나면 지운다.

### 공개 경로가 되는 것을 어떻게 감당하나

받아가는 주체가 우리 인증 체계 밖이라 **토큰 자체가 자격**이다. 판서는 강의 내용이므로 토큰이 새면 그 판서가 보인다. 창을 좁히는 것으로 감당한다.

- **128비트 난수 토큰** — 추측할 수 없다.
- **짧은 TTL(2분)** — 모델이 받아가는 시간만.
- **호출이 끝나면 즉시 폐기** — 성공이든 실패든.
- **보관 상한** — 정리되지 않는 경로가 생겨도 무한히 쌓이지 않는다(닿으면 경고).

**"한 번 읽으면 폐기"로 하지 않았다.** 모델 쪽이 이미지를 다시 받아가려 하면 그 시도가 실패해 해석 전체가 무너진다. 재시도를 깨뜨리는 대신 위 넷으로 창을 좁힌다.

## 근거 (Rationale)

### 왜 압축이나 축소가 아닌가

먼저 이미지를 줄여 맞추려 했고, 두 번 실패했다.

1. **긴 변 1600px 고정** — 같은 픽셀 수라도 획이 많으면 PNG가 훨씬 커진다. 못 맞췄다.
2. **바이트 예산(80KB)에 맞을 때까지 축소** — 맞기는 한다. 그런데 크게 그린 판서를 360px까지 줄이면 **모델이 글씨를 못 읽는다.** 해석이 성공해도 결과가 쓸모없다.

축소는 한도를 늦출 뿐이고, 늦춘 만큼 기능을 깎는다. 크기와 **무관해지는** 방법은 본문에서 빼는 것뿐이다.

### 남는 위험

- **우리 도메인이 인터넷에서 닿아야 한다.** 닿지 않는 환경(로컬 개발)에서는 모델이 이미지를 못 받는다. 로컬에서 판서 해석을 쓰려면 별도 노출이 필요하다.
- **모델 제공자가 우리 서버로 GET을 보낸다.** 요청량은 해석 호출당 한 번이고 TTL이 짧다.

## 대안 (Alternatives)

**이미지를 압축·축소한다.** 위 참조. 기각 — 기능을 깎고 한도를 늦출 뿐이다.

**에셋 스토리지(MinIO)에 올리고 presigned URL을 준다.** 본문 문제는 똑같이 풀린다. 기각 — 한 번 읽고 버릴 것을 저장소에 남기면 정리 정책이 따라붙는다. 메모리로 충분하다.

**게이트웨이 한도를 올려 달라고 요청한다.** 우리 통제 밖이고, 올려 받아도 더 큰 판서에서 다시 만난다.

## 영향·후속 (Consequences)

- 공개 GET 경로 `/api/annotation-interpret-images/{token}`가 생긴다(§CONTRACT).
- FE는 더 이상 화질을 깎지 않는다. 긴 변 상한(2000px)만 남는데, 그건 크기 한도가 아니라 **강사가 기다리는 시간**을 위한 것이다.
- `maxImageBytes`(4MB)는 그대로 남는다 — 본문 한도와 무관하게 힙을 지키는 상한이다.
