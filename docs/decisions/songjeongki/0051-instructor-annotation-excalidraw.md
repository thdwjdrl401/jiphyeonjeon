# ADR-0051: 강사 판서는 Excalidraw 문서로 두고, Egress는 `exportToCanvas`로 읽기 전용 렌더한다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 판단 정책: [../../harness/POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-07-30
- **관련**: Sub Ⅲ, ADR-0032(수강생은 합성 결과만 본다), ADR-0046(강사 스테이지 캔버스·카메라 미러), ADR-0048(Egress 합성 오디오 계약)

## 맥락 (Context)

강사가 화면공유 위에 판서할 수 있어야 한다. 이어서 판서를 AI로 인식해 **손그림 → 실제 도형**,
**수식 → 그래프**로 바꾸는 기능을 얹으려 한다. 이때 인식 결과가 **이미지가 아니라 편집 가능한 도형
객체**여야 한다 — 인식된 뒤에도 늘리고 줄이고 고칠 수 있어야 하기 때문이다. 이 요건이 문서 포맷 선택을
지배한다.

제약은 셋이다.

1. **브라우저 밖으로 나갈 수 없다.** 투명 클릭스루 오버레이를 네이티브 앱 위에 띄우는 API는 웹에 없고
   권한으로도 못 얻는다. 판서는 우리 탭 안에서만 존재하고, 다른 앱 화면은 화면공유 트랙으로 그 아래에
   깔린다.
2. **수강생에게는 합성 결과만 간다.** ADR-0032에 따라 수강생은 LiveKit을 직접 구독하지 않는다. 즉
   판서가 수강생에게 도달하는 유일한 경로는 **Egress 합성 프레임**이다.
3. **Egress 렌더 비용이 그대로 Egress CPU다**(ADR-0048).

## 결정 (Decision)

**Excalidraw(MIT)를 채택한다.** 판서 문서의 정본 포맷은 **Excalidraw 요소 배열**이다.

- **강사 화면**: 전체 대화형 Excalidraw 에디터를 `React.lazy`로 로드해 스테이지 위에 얹는다.
- **Egress**: 에디터를 **마운트하지 않고** `exportToCanvas`로 같은 문서를 읽기 전용 렌더해
  `<video>` 위에 CSS로 레이어링한다.
- **문서 좌표계**: `1920x1080` **논리 프레임**. 위치는 `getCommonBounds`로 얻은 실제 오프셋을
  **보정해서** 맞춘다(아래 실측 참조) — 프레임 앵커나 좌표 클램프에 의존하지 않는다.
- **전송**: LiveKit **데이터 채널**(reliable)로 op를 흘리고, 참가자가 새로 들어오면 강사가 **전체
  스냅샷**을 다시 publish한다. 강사가 단일 writer이므로 CRDT가 필요 없다.

## 근거 (Rationale)

### 왜 Excalidraw인가 — "편집 가능한 객체" 요건이 공짜로 충족된다
문서가 Excalidraw 요소 JSON이면, AI 인식 결과를 그 요소로 만들어 넣는 것만으로 **선택·리사이즈·수정이
그대로 따라온다**. 직접 만들면 이 편집 기능 전체가 우리 몫이 된다.

### 왜 Egress에서 에디터를 마운트하지 않는가
`exportToCanvas`는 에디터 없이 요소 배열만으로 렌더한다. 덕분에 **선택 핸들·툴바가 녹화에 새는 문제가
원천적으로 사라진다** — `viewModeEnabled`/`UIOptions`로 UI를 숨기려 애쓰는 접근은 "무엇이 숨겨지는지"를
버전마다 다시 검증해야 하는 반면, 렌더 전용 경로는 그릴 UI가 애초에 없다.

### 왜 오프셋 보정인가 — 앵커·클램프는 빈틈이 있다 (실측으로 확정)

`exportToCanvas`는 **내용 바운딩 박스**를 기준으로 `scrollX = -minX`만큼 평행이동시킨다. 즉 획을 하나 더
그을 때마다 기존 판서가 영상 대비 밀린다. 처음에는 프레임 전체를 덮는 투명 **앵커 요소**로 바운딩 박스를
고정하려 했고, 사각형 기준으로는 실제로 고정됐다(마커 중심이 획 추가·우하단 획 추가와 무관하게
(959.5, 539.5)로 유지, 앵커 없으면 (899.5, 479.5)로 밀림).

**그런데 앵커+클램프는 `freedraw`에서 깨진다.** 선언된 `x/y/width/height`가 프레임 안이어도 `points`가
그 bbox를 넘어갈 수 있고, `getCommonBounds`는 **선언값이 아니라 실제 geometry**를 쓴다:

| 요소 | 선언 bbox | 실제 bounds | export 캔버스 |
|---|---|---|---|
| freedraw (프레임 안) | (10, 10, 100, 100) | `[-70, -50, 1920, 1080]` | **1990x1130** ❌ |
| freedraw (우하단) | (1850, 1030, 60, 40) | `[0, 0, 2050, 1180]` | **2050x1180** ❌ |
| rectangle 음수 좌표 | (-120, -90, 60, 60) | `[-120, -90, ...]` | 2040x1170 (클램프로 방어 가능) |

선언 bbox를 클램프해도 freedraw의 실제 geometry는 프레임을 벗어난다. **그래서 클램프는 불변식이 될 수
없다.** 대신 `getCommonBounds`로 실제 오프셋을 읽어 **보정**한다. 이 방식은 geometry와 무관하게 정확했다:

| 케이스 | export 캔버스 | 오프셋 | 복원한 프레임 좌표 |
|---|---|---|---|
| 마커만 | 40x40 | (940, 520) | (959.5, 539.5) ✅ |
| 마커 + 좌상단 삐짐 | 1050x610 | (-70, -50) | (958.5, 538.5) ✅ |
| 마커 + 우하단 삐짐 | 1110x660 | (940, 520) | (960.5, 540.5) ✅ |
| 마커 + 양쪽 삐짐 | 2120x1230 | (-70, -50) | (959.5, 539.5) ✅ |

(기준값 (960, 540), 오차 ±1.5px = 서브픽셀 라운딩)

부수 효과로 **캔버스가 내용 크기만큼만 생긴다** — 마커 하나면 40x40이다. 앵커 방식은 늘 1920x1080을
할당했으니 메모리와 export 시간 모두 이쪽이 싸다. 프레임을 벗어난 판서는 CSS `overflow: hidden`으로
자연히 잘린다 — 클램프처럼 획을 순간이동시키지 않고 강사가 그린 자리에 그대로 둔다.

### 왜 데이터 채널인가 — metadata가 아니라
카메라 배치(ADR-0046)는 작은 상태 blob이라 participant metadata가 맞았다. 판서는 **고빈도 op 스트림**이고
metadata에는 크기 상한이 있다. 대신 metadata의 장점(새 참가자가 현재 상태를 읽음)을 스냅샷 재전송으로
대체한다 — Egress가 도중에 재접속해도 판서가 복원된다.

### 폰트 — 경쟁 조건은 없다(실측)
`exportToCanvas` 구현의 첫 줄이 `await loadFonts()`(`Fonts.loadElementsFonts(elements)`)다. 한글 폰트가
0개 로드된 상태에서 export해도 결과가 예열 후와 **픽셀 해시까지 동일**했다(cold 89.3ms / warm 2.7ms,
hash 1313086251 동일). 첫 렌더가 fallback 글꼴로 조용히 찍힐 위험이 없다.

단 **`window.EXCALIDRAW_ASSET_PATH`를 반드시 설정한다.** 미설정 시 기본값이
`https://esm.sh/@excalidraw/excalidraw@<version>/dist/prod/`이며, Egress가 외부 CDN에 의존하게 된다.
설정 후 외부 요청은 **0건**으로 확인했다. 한글은 Xiaolai 서브셋 209개 중 50개가 Hangul 범위를 덮고,
실제 렌더도 정상이다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| **Excalidraw + `exportToCanvas`(채택)** | 편집 가능 객체·되돌리기·도형 인식 결과 주입이 공짜, MIT, React 19 정상 | 초기 번들 +309~365KB gzip, 트리셰이킹 불가 |
| Excalidraw 에디터를 Egress에도 마운트(`viewModeEnabled`) | 코드 경로 하나 | UI 크롬이 녹화에 샐 위험을 버전마다 재검증해야 함 |
| 자체 최소 에디터 | 번들 최소, 완전한 통제 | 선택·리사이즈·되돌리기·텍스트를 전부 직접 구현 — AI 인식 결과의 "편집 가능" 요건이 곧 이 작업 전체를 뜻함 |
| 판서를 이미지로 합성 | 구현 단순 | **요건 위반** — 인식 결과를 다시 편집할 수 없다 |
| OS 레이어 오버레이 | 다른 앱 위에 자유롭게 판서 | 웹에 API가 없고 권한으로도 못 얻는다 |

## 실측 근거 (Measurements)

격리 환경(vite 5 + React 19)에서 빌드해 실제 Chrome으로 측정했다.

**번들(초기 로드, gzip)** — 트리셰이킹은 기대하면 안 된다.

| 구성 | eager gzip | 증분 |
|---|---|---|
| React 베이스라인 | 59 KB | – |
| 렌더 전용(`exportToCanvas`만 import) | 368 KB | +309 KB |
| 전체 에디터 | 424 KB | +365 KB |

렌더 전용이 겨우 56KB만 줄었다. 원인은 package.json에 `sideEffects` 선언이 없고 export map에 `.` 하나뿐
(렌더 전용 진입점 부재)이다. **즉 Egress도 에디터 무게를 거의 다 지불한다.** 다만 청크 127개(mermaid
다이어그램들, katex 78KB, cytoscape 142KB, 폰트 서브셋 워커 737KB)는 지연 로드로 남아 초기 로드에 없다.

참고로 현재 우리 엔트리는 65KB gzip이다. 에디터는 그 5.6배이므로 **강사 라우트 `React.lazy`가 필수**다.
ADR-0032 덕분에 **수강생 번들은 0KB 증가**한다 — 수강생은 합성 결과만 보므로 Excalidraw를 받지 않는다.

**렌더 시간**(1920x1080 출력, median): 획 10개 4.3ms · 50개 32.5ms · 200개 55.1ms · 500개 108.4ms.
도형+한글 텍스트 6.8ms.

→ **프레임마다 export하면 안 된다**(200개면 55ms로 30fps 예산 33ms 초과). 다만 Egress 합성은 캔버스
루프가 아니라 **DOM 합성**이므로(ADR-0048의 `<video>` + CSS 구조) 프레임마다 우리가 할 일이 없다.
**문서가 바뀔 때만** re-export해 캔버스를 갈아 끼우면 Chrome 컴포지터가 나머지를 한다.

**React 19**: 에디터 마운트·freedraw 드로잉·속성 패널 정상, 콘솔 메시지 0건.

## 영향·후속 (Consequences)

- 강사 라우트에만 Excalidraw를 `React.lazy`로 싣는다. 수강생 번들 영향 없음.
- 빌드 단계에서 `node_modules/@excalidraw/excalidraw/dist/prod/fonts`를 `public/`으로 복사한다
  (13MB를 git에 넣지 않는다) 그리고 `window.EXCALIDRAW_ASSET_PATH`를 설정한다.
- **Egress 배치는 `getCommonBounds` 오프셋 보정으로만 계산한다.** 이 계산이 틀리면 판서가 영상 대비
  밀리는데 **강사 화면에서는 드러나지 않고 녹화·수강생 화면에서만 어긋난다** — 그래서 배치 계산을 순수
  함수로 떼어 계약 테스트로 고정한다.
- 판서 op 계약을 [CONTRACT](../../CONTRACT.md)에 추가한다.
- 후속 단계: ② 손그림 정리(클라이언트 기하 계산, AI 불필요) ③ 수식 → 그래프. ③은 GMS 게이트웨이가
  멀티모달 `image_url` 파트를 통과시키는지 **미검증**이며, 그 확인 전에는 착수하지 않는다.
- 라이선스 파일 2건(Excalidraw MIT 전문, Xiaolai `OFL.txt`)을 동봉한다.
