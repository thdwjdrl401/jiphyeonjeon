# ADR-0111: 용어 삭제는 원본을 지우지 않고 묘비 행을 남긴다

- **상태**: 채택
- **일자**: 2026-08-09
- **적용 범위**: `core.lesson_glossary_override`, 강사 용어 삭제 API·화면

## 맥락

주요 용어는 두 곳에서 온다.

| 출처 | 표 | 누가 쓰나 |
|---|---|---|
| AI가 자료에서 뽑음 | `ai` 스키마 | ai-worker |
| 강사가 고치거나 더함 | `core.lesson_glossary_override` | 우리 |

조회는 둘을 합친다 — 원본을 깔고 강사 덮어쓰기로 덮는다. **그래서 강사가 AI 용어를 지울 방법이
없었다.** `ai` 스키마는 우리가 읽기만 하고, 지운다 해도 자료를 다시 읽을 때 되살아난다.

## 결정

### 1. 삭제도 덮어쓰기와 같은 자리에 남긴다

`core.lesson_glossary_override`에 `deleted_at`을 더한다. 이 행이 있고 `deleted_at`이 차 있으면
합칠 때 **원본까지 걷어낸다**.

```java
if (override.getDeletedAt() != null) { merged.remove(override.getTerm()); continue; }
```

원본을 건드리지 않으므로 자료를 다시 읽어도 되돌아오지 않는다.

### 2. **빈 정의를 삭제로 쓰지 않는다**

"빈칸으로 덮어쓰면 삭제"가 가장 먼저 떠오르는 방법이고, 표를 늘리지 않아도 된다는 장점이 있다.
그래도 쓰지 않는다.

- **뜻이 겹친다.** 강사가 정의를 다시 쓰려고 입력칸을 비우는 순간과 구분되지 않는다. 실수로 지워지는
  쪽이 훨씬 나쁘다 — 지워진 줄 모르면 되살릴 생각도 못 한다.
- **읽는 사람이 규칙을 알아야 뜻이 선다.** `definition = ''`을 본 사람이 "빈 정의"인지 "삭제"인지
  알려면 이 결정을 알고 있어야 한다. `deleted_at`은 스스로 말한다.
- 지금 `upsert`는 정의를 그대로 받는다. 빈칸에 뜻을 실으려면 그 자리에 검증을 새로 넣어야 하는데,
  그러면 "정의를 비워 두는" 정상적인 쓰임을 영영 막게 된다.

컬럼 하나가 이 셋을 모두 없앤다.

### 3. 다시 등록하면 되살아난다

`upsert`가 `deleted_at`을 NULL로 되돌린다. 되돌릴 길이 열려 있으므로 **확인 창을 두지 않는다** —
용어를 내리는 것은 강의를 건드리지 않고, 같은 이름으로 다시 쓰면 그만이다.

### 4. 멱등이다

없는 용어를 지워도 204, 두 번 지워도 204. 목록을 여러 탭에서 보다 두 번 눌러도 실패하지 않는다.

### 5. 강사만 지운다

`ensureCanViewInsights`로 `upsert`와 같은 게이트를 쓴다. 용어는 수강생에게도 보이지만 고치는 것은
강의를 소유한 사람의 일이다.

## 결과

- AI가 잘못 뽑은 용어를 강사가 내릴 수 있다. 자료를 다시 읽어도 되돌아오지 않는다.
- 마이그레이션 한 줄(`V39`)로 끝난다. `ai` 스키마는 그대로다.
- 지운 용어를 되살리는 길이 항상 열려 있다.

## 검증

- `LessonGlossaryContractTest` **3건(신규)** — 지우면 목록에서 빠지는지 · 없는 용어를 지워도, 두 번
  지워도 204인지 · 다시 등록하면 되살아나는지.
- **돌연변이 확인**(실제로 되돌려 돌려 봤다): 합치기에서 묘비 분기를 지우면 첫 번째가 깨진다.
- `glossaryDelete.test.tsx` **4건(신규)** — AI가 뽑은 용어도 지워지는지 · 지운 것만 목록에서 빠지는지 ·
  되살릴 수 있다고 알리는지 · 실패하면 목록을 건드리지 않는지.
- FE 전체 1292건 통과, BE 용어집 계약 통과, `tsc`·`eslint --max-warnings 0` 클린.
- **눈으로 보지 못했다** — 삭제 버튼을 브라우저에서 확인하지 않았다. 리뷰 때 함께 본다.
