# ADR-0099: 마이크는 표시하되 막지 않는다

> 관련 결정: [ADR-0002 라이브 시작 오케스트레이션](../choinhoo/0002-live-start-egress-stt-orchestration.md)(§1 개정) ·
> [ADR-0048 Egress 합성 오디오 계약](0048-egress-composite-audio-contract.md) ·
> [ADR-0098 장치 실패는 연결 실패가 아니다](0098-device-failure-is-not-connection-failure.md)

- **상태**: 채택
- **일자**: 2026-08-07
- **적용 범위**: 강사 라이브 시작 게이트 — 사전 점검 화면, `/start`, 시작 도중 재검증

## 맥락

[ADR-0002 §1](../choinhoo/0002-live-start-egress-stt-orchestration.md)이 시작 조건을 이렇게 세웠다.

> 소유 강사의 unmuted microphone 하나가 확인돼야 시작 버튼을 활성화한다.

그래서 마이크가 없는 컴퓨터에서는 **라이브를 아예 열 수 없었다.** 서버가 세 곳에서 막는다.

| 위치 | 하는 일 |
|---|---|
| `LivePreflightService.check` | `ready = present && trackCount==1 && published && !muted && 중복없음` |
| `LiveStartOrchestrator.start` | `ready`가 아니면 409 |
| `LiveStartOrchestrator` Gate S3① | 시작 도중 같은 판정으로 재검증, 실패면 `INSTRUCTOR_NOT_PUBLISHING` |

**그런데 두 번째·세 번째의 주석에 적힌 의도는 마이크가 아니었다.**

> FE의 로컬 토글 값만으로 준비 완료를 판단하지 않는다. (ADR-0002 §1)
>
> STARTING이 수십 초 걸리는 동안 강사 연결이 끊겨도 여기서 잡지 않으면 **빈 방이 LIVE가 된다**.
> (`LiveStartOrchestrator`)

둘 다 재려던 것은 **"강사가 실제로 방에 있는가"**다. 마이크는 그것을 재는 대리 지표였는데, 지표가
목적보다 넓었다. `instructorPresent`가 그 목적을 그대로 만족한다.

기술적으로 막을 이유도 없다. [ADR-0048](0048-egress-composite-audio-contract.md)이 확정한 대로 **Egress는
트랙을 직접 믹스하지 않고 헤드리스 Chrome의 재생 출력을 pulseaudio로 담는다.** 오디오 트랙이 없으면
합성이 실패하는 게 아니라 **그 구간이 조용할 뿐이다.** STT도 소리가 없으면 자막이 비는 것으로 끝난다.

## 결정

### 1. 막는 조건에서 마이크를 뺀다

```
ready = 강사가 방에 있다  &&  강사 마이크 트랙 ≤ 1  &&  강사 외 마이크 publisher == 0
```

`trackCount ≤ 1`과 `중복 publisher == 0`은 남긴다 — **둘 이상이면 소리가 겹쳐 들린다**. 이건 "없어서
못 하는 것"이 아니라 "잘못 나가는 것"이라 성격이 다르다.

`microphonePublished`·`microphoneMuted`는 응답에 **그대로 남긴다.** 판정에서 빠질 뿐, 화면이 강사에게
알리는 근거로 계속 쓰인다. 그래서 응답 필드 구성은 바뀌지 않는다 — `ready`의 의미만 느슨해진다.

### 2. 시작 도중 재검증은 "빈 방"만 본다

Gate S3①은 이름을 `instructorStillConnected`로 바꾸고 같은 완화된 판정을 쓴다. 여기서 막으려는 것은
**빈 방이 LIVE로 공개되는 것**이지 무음이 아니다. 실패 메시지도 "강사의 마이크 송출이 확인되지
않습니다"에서 "강사 연결이 확인되지 않습니다"로 바꾼다.

### 3. 대신 무엇을 잃는지 시작 지점에서 말한다

**무음은 조용히 실패한다**([ADR-0048](0048-egress-composite-audio-contract.md)이 같은 지적을 한다) —
로그도 에러도 없고, 강사는 자기 화면을 보고 있어 알아채지 못한다. 막지 않기로 한 이상 알리는 일은
더 중요해진다.

- 시작 버튼 옆: **"마이크 없이 시작 준비됨 / 소리 없이 송출됩니다 — 녹화와 자막에도 소리가 남지
  않습니다."** 확인 창은 두지 않는다. 클릭을 한 번 더 받는 것보다 **누르기 전에 읽히는 문장**이 낫고,
  마이크는 강의 중에도 켤 수 있어 되돌릴 수 있는 선택이다.
- 점검 목록의 "마이크 송출"은 `소리 없음`·`음소거됨`·`n개 송출`로 적는다. **"대기"라고 쓰지 않는다** —
  기다리면 풀리는 줄 알게 된다.
- 항목 부제를 "없어도 시작할 수 있습니다"로 두어 이 줄이 게이트가 아님을 밝힌다.

### 4. FE의 서버 점검 시작 조건에서도 마이크를 뺀다

예전에는 `연결됨 && 마이크 켜짐`이라야 readiness 조회가 시작됐다. 마이크가 없으면 **조회가 영영 시작되지
않아** 화면이 멈춘 것처럼 보였다. 이제 연결만 확인되면 조회한다.

### 5. 소리가 실제로 들어오는지는 게이지로 재고, 이것도 막지 않는다

서버 점검이 확인해 주는 마지막 지점은 **"마이크 트랙 1개가 publish 중"**이다. 그 트랙에 <b>소리가
실려 있는지</b>는 아무도 모른다 — 운영체제 음소거, 엉뚱한 입력 장치(모니터 내장 마이크가 잡히는 경우가
흔하다), 죽은 마이크는 **전부 publish에 성공한다.** 그러면 강사는 "1개 송출"을 보고 안심한 채 무음
강의를 한다. §3에서 무음을 알리기로 한 이상, 여기서 멈출 이유가 없다.

그래서 사전 점검에 **입력 레벨 게이지**를 둔다. 강사가 한마디 하면 칸이 차오르고, 한 번 차오르면
"소리가 들어옵니다"가 **남는다**(말 사이의 정적으로 판정이 깜빡이면 안 된다).

- 배선은 livekit의 `createAudioAnalyser`를 쓰되, 눈금은 **시간영역 샘플의 RMS에서 직접** 낸다.
  순수 진폭이라 계산을 시험할 수 있고, 분석기의 dB 창 설정에 휘둘리지 않는다.
- **dB로 편다.** 선형이면 보통 말소리(RMS 0.02~0.2)가 게이지 바닥에 다 붙어 구분이 안 된다.
  바닥 `-60 dBFS`(조용한 방의 바닥소음 아래), 천장 `-12 dBFS`.
- 빠르게 오르고 천천히 내린다. 같은 속도면 말의 사이사이에 게이지가 바닥까지 떨어져 깜빡인다.
- **이것도 게이트가 아니다.** 소리가 확인되지 않아도 시작 버튼은 열려 있다. 게이지는 강사가 스스로
  판단할 재료지, 통과해야 하는 관문이 아니다 — 그게 이 ADR의 원칙이다.

## 결과

- 마이크가 없거나 음소거인 강사도 라이브를 연다. 소리가 안 나간다는 사실은 시작 전에 안다.
- 강사가 방에 없으면 예전처럼 막힌다. 빈 방이 LIVE로 공개되지 않는다는 보호는 그대로다.
- 마이크가 겹치면 여전히 막는다.
- API 응답 필드는 그대로다. `ready`의 의미만 넓어진다.

## 검증

- `LiveSessionLifecycleTest.start_is_allowed_without_a_microphone_and_readiness_says_so` — 강사가
  방에 있고 마이크가 없을 때 readiness가 `ready=true`·`microphonePublished=false`를 함께 내려주고,
  시작 게이트를 모두 통과해 `LIVE`가 되는지.
- **돌연변이 확인**: `ready`를 옛 식으로 되돌리면 이 테스트가 깨진다.
- `start_rejects_before_attempt_when_instructor_is_not_in_the_room`(개명) ·
  `instructor_who_left_the_room_does_not_go_live`(개명) — 두 테스트 모두 원래부터 **빈 방**을 재고
  있었다. 이름만 실제로 재는 것에 맞췄다.
- `InstructorPreflightPage.test.tsx` **6건(신규)** — 마이크 없이도 버튼이 열리는지 · 무엇을 잃는지
  문장이 뜨는지 · 음소거도 같은 취급인지 · 마이크가 없어도 서버 점검이 시작되는지 · 강사가 방에
  없으면 여전히 잠기는지 · 권한 차단이 항목으로 보이는지.
- **돌연변이 확인**: FE 게이트에 `microphoneEnabled`를 되돌리면 2건이 깨진다.
- `micLevel.test.ts` **8건** — 무음이 0인지 · 바닥과 천장을 자르는지 · 보통 말소리(-24 dBFS)가
  게이지 가운데 위쪽에 오는지(같은 소리가 선형에서는 바닥에 붙는다는 것도 함께) · 바닥소음(-55·-50)은
  통과 못 하고 작은 목소리(-40)는 통과하는지 · 감쇠가 오를 때는 즉시 내릴 때는 한 프레임만큼인지.
- `MicrophoneLevelMeter.test.tsx` **6건** — 소리를 넣으면 칸이 차고 "소리가 들어옵니다"가 뜨는지 ·
  말을 멈춰도 그 판정이 남는지 · 화면을 떠나면 오디오 컨텍스트를 닫는지 · Web Audio가 없는
  브라우저에서 게이지만 접히고 화면은 살아 있는지.
- **돌연변이 확인**: 판정 유지를 매 프레임 재계산으로 바꾸면 "말을 멈춰도 남는다"가 깨진다.
- 게이지 표시는 브라우저에서 직접 확인했다(조용함·말하는 중·과입력 구간·움직이는 상태).
