# ADR-0113: 종료 뒤 채팅은 갈 곳이 없다 — ENDED부터 채팅만 닫는다

> 📍 하네스 개요: [../../harness/README.md](../../harness/README.md) · 아키텍처: [../../ARCHITECTURE.md](../../ARCHITECTURE.md) · 계약: [../../CONTRACT.md](../../CONTRACT.md)

- **상태**: 채택 — BE(게이트 분리)·FE(입력창 잠금)·계약 테스트 반영 완료.
- **일자**: 2026-08-10
- **부분 개정**: [choinhoo/0004](../choinhoo/0004-ended-session-conversation.md) §1의 "채팅을 `ENDED`에서도 허용한다".
  같은 ADR의 **AI 질문 허용은 그대로 둔다.**
- **관련**: [choinhoo/0005](../choinhoo/0005-ended-hls-caption-drain.md)(종료·drain 분리),
  [choinhoo/0003](../choinhoo/0003-simple-live-end-sequential-process.md)(원래 `ENDED`부터 잠갔다),
  [0050](0050-chat-anonymity-is-sender-choice.md)(채팅 익명)

## 맥락

ADR-0004는 `ENDED` 뒤에도 채팅과 AI 질문을 허용하기로 했다. 근거는 셋이었다.

1. 방금 수업 내용에 대한 후속 질문과 수강생 간 토론
2. 저장된 전체 자막을 근거로 한 AI 복습 질문
3. 종료 직전에 시작한 AI 답변의 수신과 재시도

**그런데 채팅에는 시간축이 붙어 있다는 것을 고려하지 않았다.**

채팅은 저장될 때 `sessionMs`를 함께 남긴다.

```java
// ChatService
m.setSessionMs(elapsedMs(session));   // clockOriginAt부터 지금까지. 상한이 없다.
```

그리고 다시보기는 그 좌표로 **재생 위치까지 올라온 채팅만** 보여 준다.

```ts
// replayTimeline.ts
messages.filter((m) => m.sessionMs == null || m.sessionMs <= positionMs)
```

`positionMs`의 최댓값은 **영상 길이**다. 녹화가 멈춘 `ENDED` 뒤에 쓴 글은 `sessionMs`가 영상 길이를
넘어서므로 **그 조건이 영원히 참이 되지 않는다.**

| 어디서 보는가 | 종료 뒤 쓴 채팅 |
|---|---|
| 라이브 강의실 (그 URL에 남아 있는 동안) | 보인다 — 강의실은 `revealThroughMs`를 넘기지 않아 전부 그린다 |
| **다시보기** | **영원히 안 보인다** — 쓴 본인에게도 |

즉 **그 강의실 URL에 머무는 사람에게만 보이는 글**이 된다. 나갔다 다시보기로 들어오면 사라진다.
ADR-0004의 "감수하는 것"은 *"종료된 세션에도 새 채팅이 계속 쌓인다"*까지만 적었고, 그 글이
**어디에서도 다시 읽히지 않는다는 것**은 적지 않았다.

## 결정

**채팅 전송은 `LIVE`·`ENDING`까지만 허용한다. `ENDED`는 `409 LIVE_SESSION_STATE_CONFLICT`다.**

- `ENDING`은 허용한다 — 녹화가 아직 돌고 있어 `sessionMs`가 영상 안에 들어간다.
- **AI 질문은 `ENDED`에서도 그대로 허용한다.** 시간축에 얹히지 않기 때문이다(개인 패널이고 이력은
  브라우저 메모리다). ADR-0004의 근거 2·3은 그대로 지켜진다.
- 게이트는 `LiveInteractionGuard`에서 갈라진다: `requireInteractionAllowed`(AI) /
  `requireChatAllowed`(채팅). REST와 STOMP 두 입구가 같은 게이트를 쓴다 — 한쪽만 막으면 다른
  통로로 같은 글이 들어온다.
- 화면은 **입력창을 지우지 않고 잠근다.** 통째로 사라지면 채팅이 원래 없는 화면인지 지금만 막힌
  것인지 구별할 수 없다(시작 전 잠금이 이미 쓰는 규칙). 왜 닫혔는지와 어디로 이어가면 되는지를
  같이 말한다 — "지난 대화는 다시보기에서 볼 수 있고, 궁금한 점은 AI에게 이어서 물어볼 수 있습니다."

## 근거

**갈 곳이 없는 글은 받지 않는 편이 낫다.** 받아서 한 화면에서만 보이게 두면, 쓴 사람은 남들이
읽었다고 믿고 읽는 사람은 그런 글이 있는 줄 모른다. 조용히 어긋난다.

**ADR-0004가 지키려던 것의 대부분은 채팅이 아니었다.** 근거 셋 중 채팅이 필요한 것은 하나뿐이고,
나머지 둘은 AI 경로라 이 결정에 영향받지 않는다.

## 대안

| 대안 | 장점 | 왜 안 골랐나 |
|---|---|---|
| **`ENDED`부터 채팅만 닫기 (선택)** | 구멍이 사라진다. AI 복습은 그대로 | 종료 뒤 수강생 간 토론은 잃는다 |
| 다시보기에 "수업 후 대화" 영역을 따로 | 토론을 살린다 | 화면·계약 작업이 크다. 필요해지면 이 위에 얹으면 된다 |
| `sessionMs`를 영상 길이로 clamp | 다시보기에 보이긴 한다 | **거짓이 된다** — 일주일 뒤 쓴 글이 `1:29:59`에 붙어 그때 나온 말처럼 보인다 |
| 그대로 두기 | 변경 없음 | 쓴 글이 조용히 사라지는 것을 방치한다 |

## 영향·후속

- ADR-0004 §1의 채팅 조항과 그 계약 테스트(`ending_and_ended_allow_chat_for_follow_up_discussion`,
  WS의 `ended_still_allows_chat`)를 새 계약으로 바꿨다.
- **이미 쌓인 종료 후 채팅은 그대로 둔다.** 지우면 그 강의실에서 오간 대화 기록이 사라진다.
  다시보기에서 안 보이는 것은 종전과 같다.
- 종료 뒤 토론 요구가 생기면 위 표의 두 번째 대안(다시보기 별도 영역)으로 확장한다. 세션 생명주기와
  분리된 정책 필드가 필요하다는 ADR-0004의 관측은 그때도 유효하다.
