## 맥락

시연에서 라이브를 <b>실제로</b> 진행하기 어렵다. 사람이 20분간 말하면서 판서·화면공유·질문 응답까지
해야 하고, 한 번이라도 어긋나면 되돌릴 수 없다.

세 가지를 검토했다.

| 안 | 판정 |
|---|---|
| **미리 녹화한 MP4를 카메라 자리에 올린다** | **채택** |
| 기능들을 시나리오대로 자동화한다 | 기각 |
| VOD를 실시간처럼 보이게 한다 | 기각 |

## 왜 파일 송출이 "가짜"가 아닌가

**STT가 브라우저가 아니라 서버에서 돈다.** `realtime-agent`가 방에 참가자로 들어와 강사 오디오
트랙을 구독한다.

```python
# ai/realtime-agent/app/livekit/audio_source.py
participant.identity == self._publisher_identity
and track.kind == rtc.TrackKind.KIND_AUDIO
and publication.source == rtc.TrackSource.SOURCE_MICROPHONE
```

그 트랙이 마이크에서 왔는지 파일에서 왔는지 파이프라인은 <b>구분하지 않는다</b>. 자막이 진짜로
나오고, 자막이 나오면 그 뒤가 전부 따라온다 — 강의 노트, AI 답변의 RAG 근거, Egress 합성·녹화,
끝나고 생기는 VOD까지. **시연에서 보여줄 것이 전부 실제로 동작한다.**

기능 자동화(2안)는 정반대다. `DevLivePanel`이 이미 `mockLiveSessionService`를 찔러 화면만 바꾸는데,
녹화도 AI도 돌지 않는다 — <b>보여주고 싶은 것을 정확히 가짜로 만든다</b>. 3안은 학생이 이미 WebRTC가
아니라 Egress HLS를 보므로(ADR-0032) 라이브 상태 기계와 Egress를 통째로 속여야 한다.

## 결정 1 — 갈리는 지점은 `openLocalDevices` 한 곳뿐이다

```
openLocalDevices(room, ['microphone','camera'])
  ├─ 평소   setMicrophoneEnabled(true) / setCameraEnabled(true)     ← getUserMedia
  └─ 데모   <video src=…>.captureStream()
              → publishTrack(audio, { source: Microphone })
              → publishTrack(video, { source: Camera })
```

**이 아래로는 코드가 한 줄도 갈리지 않는다.** 판서·채팅·화면공유·카메라 위치·화질·참가자 수가 전부
평소 코드다. 화면공유는 `Track.Source.ScreenShare`로 별도 캡처라 <b>진짜 화면</b>이 나가고, 카메라
위치는 0~1 비율로 room metadata에 실려(`cameraOverlay.ts`) 트랙 출처와 무관하다.

**서버 봇도 검토했지만 기각했다.** 더 확실해 보이지만 STT가 <b>먼저 들어온 마이크</b>를 강사로
고정하고 두 번째가 오면 `multiple remote microphone publishers`로 트랙을 죽인다. 그래서 봇을 쓰면
강사는 마이크를 못 켜고, 강사 브라우저는 `autoSubscribe: false`라 봇 영상을 받지 않아 <b>자기 화면엔
카메라가 비고 학생만 봇 영상을 본다</b>. `강사 화면 = 수강생 화면`이 깨진다.

## 결정 2 — `source`를 명시한다 (조용히 실패하는 지점)

그냥 올리면 source가 `UNKNOWN`이 된다. 그러면 **영상과 녹화는 멀쩡한데 자막만 영영 안 뜬다** —
자막이 없으면 강의 노트도 AI 근거도 빈 채로 간다. 아무 오류도 안 나고, 시연 도중에야 드러난다.

그래서 이것만은 테스트로 잠갔다(`demoPublishProvider.test.tsx`). `source`를 빼면 실패한다.

`capture` 제약(해상도)은 넘기지 않는다 — getUserMedia 전용이라 파일에는 걸리지 않는다. 대신
`publish`(인코딩·사이멀캐스트·열화 우선순위)는 그대로 적용된다. **그래서 해상도만 파일 원본을
따르고**, 강사가 화질을 1080p로 골라도 파일이 720p면 720p로 나간다. 화면에 그렇다고 적어 준다.

## 결정 3 — 진짜 카메라가 켜질 경로를 전부 막는다

`setCameraEnabled(true)`가 한 번이라도 불리면 LiveKit이 장치를 열어 **발표자의 실제 방이 수강생
화면에 뜬다.** 그 경로가 셋 있었고 전부 막았다.

| 경로 | 데모에서의 동작 |
|---|---|
| 최초 연결 | 장치를 아예 열지 않는다. 권한도 묻지 않는다 |
| 카메라·마이크 토글 | `publication.mute()/unmute()` — publication을 유지하므로 판정도 그대로 맞는다 |
| 화질 변경 재게시 | 트랙을 내리고 **같은 element에서** 다시 올린다(파일을 새로 열면 영상이 되감긴다) |

## 결정 4 — 파일을 잃으면 카메라로 되돌아가지 않는다

`File`은 새로고침을 넘지 못하는데 무장 여부는 `sessionStorage`에 남는다. **이 비대칭이 안전
장치다.** 새로고침 뒤에는 "무장됐지만 준비 안 됨"이 되고, 그때 아무것도 올리지 않고 그렇다고 말한다.

되돌아가는 쪽이 편해 보이지만, 그러면 시연 중 새로고침 한 번에 발표자의 실제 방이 송출된다.
**검은 화면 + 이유 설명**이 그보다 낫다.

## 결정 5 — 운영 계정에게만, 그리고 숨기지 않는다

`user.isAdmin`일 때만 스위치가 보인다. `isAdmin`은 가입 역할이 아니라 서버 allowlist
오버레이라(ADR-0089) 이 화면 자체는 소유 강사만 열 수 있다 — 즉 버튼이 보이는 사람은 "이 강의의
강사이면서 운영 계정"뿐이다.

**env 스위치는 두지 않는다.** 시연이 운영에서 도는데 운영에서 켜 둬야 할 잠금은 잠금이 아니라 방해다.

대신 **강의 내내 배너를 띄운다.** 데모 모드의 화면은 평소와 <b>완전히 같다</b> — 그게 이 기능의
목적이자 위험이라, 말해 주지 않으면 진짜 수업에 켜 둔 채 들어간 것을 알아챌 방법이 없다.

## MP4 요건

`captureStream()`은 <b>디코드된 프레임</b>만 준다. 무슨 포맷을 주든 WebRTC가 다시 인코딩하므로
전송용으로 최적화할 이유가 없다 — 파일에 요구할 것은 "브라우저가 싸게 디코드할 수 있는가"뿐이다.

| 항목 | 값 | 이유 |
|---|---|---|
| 코덱 | **H.264 High + AAC / mp4** | 하드웨어 디코드가 보편적. 시연 노트북이 디코드·인코드·판서·화면공유를 동시에 한다 |
| 픽셀 포맷 | `yuv420p` | `yuv422p`/`444p`는 Chrome이 거부하거나 이상하게 그린다 |
| 해상도 | 1920×1080 | Egress 캔버스와 같다. 작으면 확대돼 흐려지고, 화질 설정으로는 못 올린다 |
| 프레임률 | 고정(CFR), 15fps 이상 | 가변이면 `captureStream()` 간격이 튄다. Egress가 15fps로 낸다 |
| 오디오 | 48kHz, 실제 한국어 발화, 화자 1명 | agent가 48k mono로 리샘플링한다. 무음이면 자막·노트·AI가 전부 빈다 |
| 길이 | **시연 시간보다 길게** | 반복하면 STT가 같은 말을 다시 받아 강의 노트가 같은 주제를 두 번 쌓는다 |

AV1은 피한다 — 소프트웨어 디코드가 흔하고, 그 CPU를 WebRTC 인코더와 나눠 쓴다.

## 보완 (2026-08-07) — 뒤집기와 재생 제어

첫 배포에서 **화면이 좌우로 반전돼 나왔다.** 위의 "갈리는 지점은 한 곳뿐"이 카메라의 <b>방향</b>까지는
못 덮은 것이다.

카메라는 **일부러** 뒤집고 있었다 — 강사가 자기 얼굴을 거울로 보는 것이 이 서비스의 기준이고,
Egress 템플릿도 같은 방향으로 뒤집어 두 화면을 맞춰 뒀다. 웹캠에는 맞지만 **파일에는 틀리다.**
미리 녹화한 영상은 거울상이 아니라서, 뒤집으면 화면 속 글자가 반전된다.

**그리고 그것이 영구히 남는다.** 네 곳이 뒤집고 있었는데 그중 `.egress-stage__camera`는 합성
캔버스라 그대로 HLS·녹화가 된다 — 강사 화면만 고치면 강사는 멀쩡해 보이는데 수강생만 반전을 보고,
그 상태로 VOD에 남는다.

### 뒤집기를 배치와 같은 통로로 싣는다

`CameraOverlay`에 `mirrored`를 더한다. 배치(x·y·w)가 이미 room metadata로 Egress에 전달되고 있으므로
같은 통로를 쓴다 — **강사 화면과 Egress가 같은 값을 읽는다**는 성질이 그대로 유지된다.

```
웹캠  mirrored: true   (기본값. 이 키가 없는 옛 세션도 true로 읽는다)
파일  mirrored: false  (송출을 켤 때 내보내고, 끄면 되돌린다)
```

기본값을 `true`로 둔 것이 중요하다. 진행 중인 강의의 metadata에는 이 키가 없는데, 없을 때 뒤집지
않으면 **강의 도중 카메라가 갑자기 좌우로 뒤집힌다.**

### 재생 제어를 붙인다

시연 중에 정지·재생·구간 이동이 필요하다. `<video>` element를 화면에 내주고 손잡이를 그린다.

**이건 로컬 재생 제어가 아니라 송출 제어다.** element를 멈추면 `captureStream()`이 내보내던 프레임과
소리가 함께 멈춘다 — 수강생 화면이 정지 화면이 되고 녹화에도 그대로 남는다. 뒤로 감으면 STT가 같은
구간을 다시 받아 **강의 노트에 같은 주제가 두 번 쌓이고**, 앞으로 감으면 그 구간이 통째로 빠진다.
시연에서는 대개 괜찮지만 모르고 하면 안 되므로 화면과 주석에 적어 둔다.

구간 이동은 **손을 뗄 때 한 번만** 적용한다. 끄는 내내 옮기면 매 프레임 seek이 걸려 송출이 끊긴다.

## 남겨 둔 것

**장치 오류 안내는 데모로 시연할 수 없다.** 권한·장치 확인 경로를 아예 타지 않으므로 "마이크가
없습니다" 같은 화면(ADR-0099)은 진짜 장치로만 보여줄 수 있다.

**Safari에서는 안 된다.** `captureStream()`이 없다. 막지 않고 "Chrome에서 실행해 주세요"라고 말한다.
