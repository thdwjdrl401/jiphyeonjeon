# ADR-0006: VOD = 영상 공개·AI 게시본 분리 + 강사 검수·버전 관리

> VOD 컴포넌트: [VOD_LESSON.md](../../frontend/components/VOD_LESSON.md) · API 초안: [VOD_LEARNING_AI.md](../../frontend/api/VOD_LEARNING_AI.md) · VOD 기반 ADR: [0010](../songjeongki/0010-self-host-vod.md)

- **상태**: 제품 목표 채택
- **일자**: 2026-07-21
- **적용 범위**: VOD 공개, AI 콘텐츠 검수, 개인 학습, 퀴즈

## 맥락

라이브 종료 후 HLS 영상, 2-pass 자막, 용어·챕터·퀴즈 후보는 서로 다른 시간에 준비되며 일부만 실패할 수 있다. 이를 하나의 `PUBLISHED` 상태로 묶으면 AI 처리 지연이 영상 공개를 불필요하게 막거나, 검수 전 AI 후보가 학생에게 노출될 수 있다.

강사가 AI 산출물을 검수할 때 원본을 덮어쓰면 재생성·감사·비교가 어려워지고, 퀴즈 게시본을 수정하면서 기존 응시 기록을 바꾸면 학습 이력의 의미가 깨진다.

## 결정

1. VOD는 라이브 Egress HLS만 사용하며 별도 영상 업로드를 제공하지 않는다.
2. 다음 상태 축을 분리한다.
   - live session 상태
   - `videoAssetStatus`: 녹화·검증의 기술 상태
   - `replayStatus`: 학생 영상 공개 상태
   - 자막·용어·챕터·퀴즈의 영역별 AI 처리·게시 상태
3. `videoAssetStatus=READY`는 강사 미리보기 가능을 뜻하며 학생 자동 공개가 아니다.
4. 수강생 영상 재생은 `replayStatus=PUBLISHED`일 때만 허용한다.
5. 영상은 AI 게시본 없이 먼저 공개할 수 있다. AI 일부 실패도 이미 게시된 영상과 다른 게시 영역을 막지 않는다.
6. AI 원본과 후보는 `ai` 영역에 보존하고 학생에게 자동 공개하지 않는다.
7. 강사는 VOD 페이지 안의 전용 검수 패널에서 후보·검수 초안·현재 게시본을 비교한다.
8. 검수 초안 저장과 학생 게시를 분리한다. 게시 시 `core`에 새 version을 만들고 활성 게시본을 원자적으로 교체한다.
9. 게시 실패 시 기존 학생 게시본을 유지한다.
10. 학생은 현재 활성 게시본만 보고, 강사는 원본 후보·초안·게시본을 구분해 본다.
11. 채팅 리플레이는 가명·시간 동기화·읽기 전용이다.
12. 개인 AI Q&A 기록과 답변은 본인만 확인한다. 강사에게는 질문 원문과 시점만 익명 통계로 제공한다.
13. 마지막 재생 위치와 진행률을 자동 저장하고, 서버가 유효 시청량 90%를 완료 기준으로 판정한다.
14. 북마크는 라이브와 VOD가 같은 `lessonId`·`sessionMs`를 사용한다.
15. 퀴즈는 별도 패널에서 응시한다. AI 후보는 강사가 검수·게시하며 서버가 결정론적으로 채점한다.
16. 퀴즈 새 version이 게시되어도 기존 응시 결과는 응시 당시 version과 함께 보존한다.

## 근거

- 상태 축 분리는 영상의 핵심 가용성을 AI 처리와 격리한다.
- 원본 보존과 게시본 version은 강사 검수, 재현, 동시 편집 충돌 처리를 가능하게 한다.
- 서버의 유효 시청량 판정은 단순 seek 위치를 완료로 오인하지 않는다.
- 퀴즈 응시 version 보존은 게시본 변경 후에도 과거 점수의 의미를 유지한다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 영상·AI를 한 번에 게시 | 상태 단순 | AI 지연·실패가 영상 공개 차단 |
| AI 후보 자동 공개 후 검수본 교체 | 빠른 노출 | 오답·부적절 콘텐츠 노출 위험 |
| 검수 시 AI 원본 덮어쓰기 | 저장 구조 단순 | 비교·감사·재생성 어려움 |
| 퀴즈 수정 시 기존 응시 재채점 | 최신 정답 반영 | 과거 결과 의미 변경 |
| **독립 공개 + 버전 게시(선택)** | 부분 실패 격리, 신뢰성 | 상태·버전·검수 UI 복잡도 증가 |

## 영향·후속

- HLS URL 만료·재발급과 replay 회수 시 기존 URL 무효화 정책이 필요하다.
- 자막·용어·챕터·퀴즈별 draft version과 게시 충돌 계약을 확정해야 한다.
- 90% 완료를 계산할 watched range 병합·중복 재생·out-of-order 저장 정책이 필요하다.
- 퀴즈 재응시 횟수와 정답·해설 공개 범위를 별도 확정한다.
- 게시본 되돌리기와 종료 후 자료 revision은 후속 범위다.
