## 맥락

강사는 학생의 질문이 많이 발생한 구간을 영상 진행 바에서 빠르게 찾고, 해당 시점의 질문 원문을 확인할 필요가 있다. 일반 채팅을 문장 내용으로 자동 분류하면 오탐과 설명 가능성 문제가 있고, 개인 AI Q&A를 무시하면 학생이 실제로 어려워한 구간을 놓친다.

VOD에서는 라이브 채팅이 단순 로그가 아니라 영상 시각과 동기화되어야 라이브 당시 맥락을 재현할 수 있다.

## 결정

1. 수강생이 채팅을 보낼 때 `질문으로 등록`을 직접 체크할 수 있게 한다.
2. 일반 채팅을 텍스트 내용만으로 자동 질문 분류하지 않는다.
3. 강사용 질문 핀에는 두 출처를 포함한다.
   - `질문으로 등록`된 라이브 채팅
   - 라이브·VOD에서 수강생이 입력한 개인 AI 질문
4. 모든 질문은 `sessionMs`로 영상 시간축에 연결한다.
5. 강사 화면은 전체 질문 개수, 시간대별 핀, 질문 집중 정도, 핀별 익명 질문 원문을 제공한다.
6. 강사에게 학생 userId·실명·가명과 개인 AI 답변을 제공하지 않는다. 질문 원문·출처·시점만 익명으로 제공한다.
7. 핀을 선택하면 해당 영상 시각과 자막·근거로 이동할 수 있다.
8. 초기 구현은 개별 질문 또는 고정된 짧은 시간 bucket 집계만 제공한다.
9. 유사 질문 의미 묶음, 밀도 heatmap, 질문 처리 완료 표시는 후속 기능이다.
10. VOD 채팅 리플레이는 라이브 당시 가명을 유지하고 영상 시각까지 발생한 메시지를 순서대로 보여주는 읽기 전용 기능이다.
11. 영상 탐색 시 채팅 목록을 같은 `sessionMs`로 재구성하며, 삭제·제재된 메시지는 정책에 따라 제외한다.

## 근거

- 명시적 질문 체크는 사용자의 의도를 직접 받으므로 자동 분류보다 예측 가능하다.
- 개인 AI 질문을 익명 집계하면 강사가 반복해서 어려워하는 구간을 알 수 있으면서 개인 학습 기록을 보호한다.
- 영상과 채팅의 공통 시간축은 VOD에서 당시 맥락을 복원하고 핀 이동을 단순화한다.
- 유사도 clustering 없이도 질문 개수·집중 구간만으로 초기 피드백 가치를 제공할 수 있다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 모든 채팅 자동 질문 분류 | 사용자 입력 추가 없음 | 오탐·누락, 설명 어려움 |
| 질문 전용 별도 게시판 | 구조 명확 | 라이브 채팅 흐름과 분리, 진입 비용 |
| 학생 식별 정보를 강사에게 제공 | 개별 피드백 가능 | 개인 AI 질문의 프라이버시 침해 |
| **명시 체크 + 익명 핀(선택)** | 의도 명확, 빠른 MVP, 프라이버시 | 체크하지 않은 질문 누락 가능 |

## 영향·후속

- 채팅 command에 `isQuestion`과 필요 시 `viewingSessionMs`가 필요하다.
- 되감기 중 질문 채팅의 핀 기준을 서버 수신 시각과 사용자가 시청하던 시각 중 무엇으로 할지 확정해야 한다.
- bucket 크기와 집중도 계산 기준을 백엔드와 협의해야 한다.
- STOMP 브로드캐스트는 [ADR-0019](../songjeongki/0019-ws-realtime-chat-stomp.md)에 따라 userId를 제거하고, 내 메시지는 `clientMessageId`와 REST `mine`으로 판별한다.
- 익명 집계에서 소수 사용자 재식별을 막기 위한 최소 집계 기준은 운영 단계에서 검토한다.
