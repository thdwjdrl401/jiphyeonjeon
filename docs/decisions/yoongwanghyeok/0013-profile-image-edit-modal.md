# ADR-0013: 프로필 편집 = 페이지 내 모달 + 구현된 이미지 계약만 저장

> 페이지 명세: [PAGES.md](../../frontend/PAGES.md) · 컴포넌트: [PROFILE.md](../../frontend/components/PROFILE.md) · 에셋 결정: [ADR-0023](../songjeongki/0023-asset-presigned-upload.md)

- **상태**: 채택
- **일자**: 2026-07-22
- **적용 범위**: 프론트 프로필 수정 UX, 프로필 이미지 업로드, 인증 사용자 캐시

## 맥락

프로필 페이지의 수정 대상이 많지 않은데도 닉네임·강사 소개·전문 분야 입력 폼이 페이지에 직접 노출돼 있었다. 해당 필드의 수정 API는 구현되지 않아 기존 저장 행동은 로컬 상태만 바꾸고 실제 영속화처럼 보일 위험이 있었다. 반면 프로필 이미지는 범용 asset 업로드와 `PUT /api/me/profile-image` 계약이 이미 구현돼 있다.

별도 수정 페이지와 모달 중에서, 현재 지원되는 작업은 이미지 한 장 선택·확인·저장으로 범위가 작고 사용자가 계정 정보 맥락을 유지하는 편이 자연스럽다.

## 결정

1. 프로필 페이지는 계정 정보와 기본 프로필을 읽기 중심으로 표시한다.
2. 기본 프로필 영역의 `프로필 수정` 버튼으로 모달을 연다.
3. 모달에서 실제 저장 가능한 프로필 이미지만 변경한다. JPG·PNG·WEBP, 5MB 이하를 프론트에서도 먼저 검증한다.
4. 업로드는 `upload-requests` → presigned 스토리지 PUT → `complete` → `me/profile-image` 순서로 실행한다.
5. 이미지 지정 응답의 인증 사용자 DTO를 TanStack Query의 `['auth', 'me']` 캐시에 반영해 헤더·사이드바·프로필을 즉시 갱신한다.
6. 닉네임은 현재 값을 읽기 전용으로 보여주고 수정 API 준비 중임을 명시한다. 강사 공개 소개·전문 분야도 입력·가짜 성공 상태를 제공하지 않는다.
7. 수정 필드가 늘어나 복잡한 검증·이탈 방지·하위 설정 탐색이 필요해질 때 별도 페이지 전환을 다시 검토한다.

## 근거

- 한정된 작업은 모달이 현재 페이지 문맥과 짧은 완료 흐름을 유지한다.
- 구현된 서버 계약만 활성화해 새로고침 후 사라지는 가짜 저장을 막는다.
- 인증 캐시를 단일 원본으로 사용하면 여러 레이아웃의 아바타가 서로 다르게 보이지 않는다.
- presigned URL에는 공용 `/api` 클라이언트를 사용하지 않아 base URL·CSRF 헤더가 외부 스토리지 요청에 섞이지 않는다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 별도 프로필 수정 페이지 | 필드 확장에 유리 | 현재 한 가지 작업에 라우트·이탈 흐름이 과함 |
| 페이지 인라인 편집 | 구현 단순 | 조회와 수정 상태가 항상 섞이고 기존 가짜 저장 문제를 반복할 수 있음 |
| 미구현 필드까지 로컬 저장 | 데모 상호작용 증가 | 서버 상태와 불일치하고 저장 성공으로 오인 |
| **이미지 전용 모달(선택)** | 짧은 흐름, 계약 정직성, 맥락 유지 | 수정 필드가 많아지면 재설계 필요 |

## 영향·후속

- 닉네임·강사 공개 프로필 API가 구현되면 같은 모달에 무조건 누적하지 않고 필드 수와 검증 복잡도를 다시 평가한다.
- 프로필 이미지 제거·기본 이미지 복원은 백엔드 해제 계약이 생긴 뒤 추가한다.
- 모달 접근성은 `dialog`, `aria-modal`, Escape 닫기와 닫기 버튼 포커스를 기본으로 유지한다.
