# ADR-0009: 보호 라우팅 = 역할 prefix 상위 가드 + 라이브 입장 전 점검

> 라우터: [AppRouter.tsx](../../../frontend/src/app/router/AppRouter.tsx) · 경로 생성기: [paths.ts](../../../frontend/src/app/router/paths.ts) · 관계별 UI: [ADR-0002](0002-curriculum-roles-and-access-composition.md)

- **상태**: 채택
- **일자**: 2026-07-21
- **적용 범위**: 프론트 URL, 인증·역할 가드, 라이브 입장 흐름

## 맥락

초기 라우팅은 페이지마다 인증·역할을 확인하거나 학생과 강사 URL의 구분이 약했다. 이 구조에서는 새 페이지를 추가할 때 권한 검사가 빠질 수 있고, 같은 `lessonId` 또는 `sessionId`가 어떤 사용자 화면인지 URL만으로 파악하기 어려웠다.

또한 사용자가 라이브 강의실 URL을 직접 입력하면 카메라·오디오·연결 상태를 확인하지 않고 입장할 수 있었다. 레슨과 라이브 세션은 MVP에서 일대일이지만, 콘텐츠와 실시간 실행 상태의 수명주기가 다르다.

## 결정

1. 공개 URL은 `/`, `/login`, `/signup`, `/curriculums/*`에 둔다.
2. 학생 기능은 `/student/*`, 강사 기능은 `/instructor/*` 아래에 둔다.
3. 각 역할의 상위 라우트에 `RequireRoleRoute`를 한 번 배치하고 자식 페이지가 인증·역할 검사를 상속받게 한다.
4. 비로그인 사용자는 안전하게 인코딩한 `returnTo`와 함께 로그인으로 이동한다. 다른 역할은 `/forbidden`으로 이동한다.
5. URL의 여러 단어는 underscore가 아니라 kebab-case를 사용한다. 경로 문자열은 `paths.ts`의 생성 함수에서 관리한다.
6. 학생의 라이브 강의실은 항상 `prejoin`을 통과해야 한다. 직접 classroom URL을 입력해도 `RequireStudentPrejoinRoute`가 입장 준비 완료 여부를 검사한다.
7. 강사는 별도의 `preflight`에서 장치와 시작 조건을 확인한다.
8. 레슨은 학습 콘텐츠·자료·게시·다시보기의 기준 리소스이고, live session은 일정·입장·실시간 진행·녹화 처리의 기준 리소스로 유지한다.
9. lesson당 session이 하나인 MVP에서도 두 ID를 합치지 않는다. 레슨 화면은 `lessonId`, 라이브 화면은 `sessionId`를 사용한다.
10. 역할 가드는 URL 영역의 1차 경계일 뿐이다. 커리큘럼 소유권과 수강 관계 같은 리소스 권한은 서버 판정 또는 `viewerContext`를 사용한다.

## 근거

- 상위 가드는 페이지 추가 시 권한 검사 누락을 줄인다.
- 역할 prefix는 URL만으로 사용자 영역과 레이아웃을 식별할 수 있게 한다.
- prejoin 강제는 브라우저 autoplay·오디오·네트워크 문제를 강의실 진입 전에 발견한다.
- lesson과 session을 분리하면 재예약, 실패 재시도, 녹화 처리 같은 상태를 콘텐츠 게시 상태와 독립적으로 확장할 수 있다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 페이지별 인증 검사 | 페이지 단위 제어 | 누락·중복 가능성 |
| 역할 구분 없는 공통 URL | 경로 짧음 | 화면·권한·레이아웃 식별 어려움 |
| classroom 직접 입장 허용 | 클릭 수 감소 | 장치 실패를 강의실에서 발견 |
| lessonId를 sessionId로 겸용 | MVP 모델 단순 | 콘텐츠와 실시간 실행 수명주기 결합 |
| **역할 상위 가드 + prejoin(선택)** | 일관된 권한·입장 흐름 | 관계별 서버 권한은 별도 필요 |

## 영향·후속

- 링크는 문자열 결합 대신 `publicPaths`, `studentPaths`, `instructorPaths`를 사용한다.
- 세션 입장 준비 완료 상태는 새로고침·다중 탭·만료 시 동작을 추가로 확정해야 한다.
- 관리자 기능이 생기면 실제 요구가 확인된 뒤 `/admin/*` 상위 가드를 추가한다.
- 서버는 URL prefix만 신뢰하지 않고 모든 보호 endpoint에서 역할·소유권·수강 상태를 다시 검사해야 한다.
