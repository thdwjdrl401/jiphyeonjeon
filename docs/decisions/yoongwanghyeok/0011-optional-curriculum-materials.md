# ADR-0011: 커리큘럼 공통 강의 자료 = 선택 항목 + 관계 기반 노출

> 레슨 자료 결정: [ADR-0003](0003-lesson-pptx-incremental-processing.md) · 미확정 API: [DECISIONS_PENDING.md](../../frontend/DECISIONS_PENDING.md) · 구현 가이드: [IMPLEMENTATION_GUIDE.md](../../frontend/IMPLEMENTATION_GUIDE.md)

- **상태**: 프론트 UI·fixture 채택, 백엔드 API·AI 처리 정책 미확정
- **일자**: 2026-07-21
- **적용 범위**: 커리큘럼 생성·관리·상세, 공통 강의 자료 권한

## 맥락

[ADR-0003](0003-lesson-pptx-incremental-processing.md)은 자료를 레슨에 귀속하는 것을 제품 목표로 두었다. 이후 개별 레슨 자료와 별도로 커리큘럼 전체에서 공통으로 제공할 자료가 필요해졌다. 공통 자료는 모든 커리큘럼에 존재하지 않으며, 공개 상세를 볼 수 있다는 이유만으로 파일 정보까지 공개되어서는 안 된다.

현재 백엔드에는 커리큘럼 공통 자료의 업로드·목록·삭제 계약과 저장 schema가 없다. 따라서 프론트 초안과 실제 계약의 경계를 명확히 유지해야 한다.

## 결정

1. 레슨 자료와 별도로 커리큘럼에 귀속되는 공통 강의 자료를 허용한다. 이는 ADR-0003의 “레슨 전용” 범위를 확장한다.
2. 커리큘럼 공통 자료는 선택 항목이며 자료가 없어도 커리큘럼 초안을 생성·저장할 수 있다.
3. 현재 프론트 초안은 기존 레슨 자료 정책과 일관되게 PPTX 복수 선택을 제공한다. 최종 허용 형식·크기·개수는 API 협의 후 확정한다.
4. 생성 화면에서는 대표 이미지 등록 영역의 오른쪽에 공통 자료 등록 영역을 배치한다.
5. 관리 화면에서는 기본 정보 영역 최하단에서 공통 자료를 추가·제거한다.
6. 상세 화면은 활성 수강생(`ENROLLED`)과 해당 커리큘럼 운영 강사(`OWNER_INSTRUCTOR`)에게만 자료를 표시한다.
7. 비로그인, 승인 대기, 미수강 학생과 비운영 강사에게는 파일명·크기 등 메타데이터도 표시하지 않는다.
8. 프론트의 조건부 렌더링은 UX 보조일 뿐 최종 권한 경계가 아니다. 실제 파일 목록과 다운로드 URL은 서버가 수강 상태·소유권을 검사한 뒤 반환해야 한다.
9. mock 모드에서는 통합 저장소에 자료 메타데이터를 저장·수정한다.
10. 실제 API 모드에서는 응답에 `materials`가 없으면 빈 배열로 정규화하되, 생성 요청에 합의되지 않은 자료 필드를 전송하지 않는다.
11. 공통 자료가 레슨 AI 검색 범위·readiness·게시 상태에 미치는 영향은 현재 결정하지 않는다.

## 근거

- 오리엔테이션·공통 실습 환경처럼 여러 레슨에서 반복 사용하는 자료를 한 번만 관리할 수 있다.
- 선택 항목으로 두면 자료가 필요 없는 커리큘럼 생성 흐름을 막지 않는다.
- 공개 정보와 보호 학습 자료를 분리해 승인 전 파일명 노출도 방지한다.
- 미확정 API 필드를 전송하지 않아 프론트 초안이 공유 계약으로 오인되는 것을 막는다.

## 대안

| 대안 | 장점 | 단점 |
|---|---|---|
| 모든 자료를 레슨에만 귀속 | AI 범위 단순 | 공통 자료 중복 등록·수정 |
| 공통 자료를 공개 상세에 노출 | 접근 간단 | 미수강자에게 보호 자료 메타데이터 노출 |
| 공통 자료를 필수로 지정 | 학습 구성 일관성 | 불필요한 커리큘럼 생성 차단 |
| **선택 공통 자료 + 관계 기반 노출(선택)** | 중복 감소, 권한 명확 | API·상속·AI 영향 정책 추가 필요 |

## 영향·후속

- 업로드·목록·삭제 endpoint, presigned upload, 파일 크기·개수 제한을 확정해야 한다.
- 자료 목록을 커리큘럼 상세 응답에 포함할지 권한 전용 endpoint로 분리할지 결정해야 한다.
- 자료 다운로드 URL은 짧은 만료 시간과 서버 권한 재검사를 적용해야 한다.
- 공통 자료의 레슨 상속, 중복 embedding, 삭제 시 AI 산출물 무효화 범위를 별도 ADR로 확정해야 한다.
- 백엔드 계약이 확정되면 `CONTRACT.md`, FE·BE 구현과 계약 테스트를 같은 변경에서 갱신한다.
