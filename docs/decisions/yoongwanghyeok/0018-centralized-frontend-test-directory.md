# ADR-0018: 프론트 테스트를 중앙 테스트 디렉터리에서 관리한다

> 구현 기준: [프론트 테스트 구조](../../../frontend/src/test/README.md) · 프론트 운영 규칙: [frontend/AGENTS.md](../../../frontend/AGENTS.md)

- **상태**: 채택
- **일자**: 2026-07-23
- **적용 범위**: `frontend/src` 아래의 Vitest 및 React Testing Library 테스트

## 맥락

서비스·순수 함수 테스트는 각 feature와 shared 디렉터리에 있고, 앱 통합 테스트는 `src/test`에 있어 전체 테스트 위치를 한눈에 확인하기 어려웠다. 테스트를 한 파일로 합치면 책임 분리와 파일 단위 실행성이 나빠지므로, 파일 분리는 유지하면서 위치만 중앙화할 필요가 있었다.

## 결정

1. 모든 `*.test.ts`, `*.test.tsx` 파일을 `frontend/src/test` 아래에 둔다.
2. 단일 feature 테스트는 `test/features/<feature>/`, 공용 코드 테스트는 `test/shared/`, 여러 feature와 라우터를 연결하는 테스트는 `test/integration/`에 둔다.
3. `test/setup.ts`는 전체 테스트 환경 초기화를 계속 담당한다.
4. 중앙 테스트에서 구현 모듈을 참조할 때는 상대 경로 대신 `@/` alias를 사용한다.
5. 테스트 파일은 대상과 책임별로 유지하고 하나의 파일로 합치지 않는다.

## 근거

- 테스트 파일의 전체 위치와 분류를 한 디렉터리에서 확인할 수 있다.
- 구현 디렉터리에는 런타임 코드만 남아 파일 구조가 단순해진다.
- 책임별 파일 분리와 Vitest의 파일 단위 실행·격리는 유지된다.
- 경로 이동 후에도 Vitest의 `*.test.*` 자동 탐색을 그대로 사용할 수 있다.

## 영향

- 테스트가 구현 파일과 물리적으로 떨어지므로 import는 `@/` alias를 사용한다.
- API 요청·응답 계약이나 런타임 동작은 변경하지 않는다.
- 이번 변경은 테스트 위치만 바꾸므로 `docs/CONTRACT.md` 갱신은 필요하지 않다.
