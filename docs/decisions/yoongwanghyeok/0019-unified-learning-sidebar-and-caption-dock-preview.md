# ADR-0019: 라이브·다시보기 학습 UI = 공통 4탭 + 자막 도크

> 라이브 컴포넌트: [LIVE_LESSON.md](../../frontend/components/LIVE_LESSON.md) · VOD 컴포넌트: [VOD_LESSON.md](../../frontend/components/VOD_LESSON.md)

- **상태**: UI 목업 기준 채택
- **일자**: 2026-07-23
- **적용 범위**: 학생·강사 라이브 강의실, 학생·강사 다시보기, 자막·구간 요약·핵심 용어 상호작용

## 맥락

기존 라이브와 다시보기의 보조 패널은 역할마다 채팅, 자막, 자료, 질문 핀, 검수, 통계, 퀴즈를 서로 다른 탭으로 제공했다. 역할과 재생 형태를 오갈 때 학습 기능의 위치가 달라졌고, 자막이 영상 위에 겹치면서 긴 문장과 핵심 용어 설명으로 이동하는 흐름도 제한되었다.

실시간 강의 요약은 매번 전체 요약을 다시 만드는 대신 완성된 시간 구간별 블록을 누적해야 한다. 핵심 용어는 강의 전에 강사가 확정한 설명을 보여주고, 자막의 용어 선택에서 같은 상세 항목으로 이동해야 한다. 백엔드·AI 이벤트 계약과 DVR HLS는 아직 구현 전이므로 이번 단계에서는 UI와 목업 데이터 경계를 먼저 검증한다.

## 결정

1. 학생·강사, 라이브·다시보기의 기본 사이드바를 다음 네 탭으로 통일한다.
   - `채팅·질문`
   - `실시간 노트`
   - `AI 질문`
   - `핵심 용어`
2. `채팅·질문`은 같은 메시지 목록을 사용하고 `전체 / 질문` 필터로 명시적으로 질문 등록된 메시지만 모아볼 수 있게 한다.
3. 실시간 노트는 `startMs`·`endMs` 범위를 가진 완성 블록을 시간순으로 누적한다. 블록마다 핵심 내용, 주요 개념과 설명, 강사 강조, 예시·사례를 표시한다. 프론트가 생성 주기를 계산하지 않는다.
4. 다시보기는 라이브에서 생성된 동일 블록을 읽기 형태로 보여준다. 종료 후 전체 구조 재정리는 후속 범위다.
5. 핵심 용어는 검색 가능한 압축 목록과 선택 상세를 한 패널에 둔다. 강사 등록 또는 자료 추출 출처와 강사 검수 완료 설명을 표시한다.
6. 자막은 영상 밖 하단 도크에 문장 단위로 누적 표시한다. 자막 시각을 선택하면 영상과 자막이 같은 `sessionMs`로 이동한다.
7. 자막의 핵심 용어는 백엔드가 제공할 `termId`와 문자열 범위를 렌더링한다. 프론트는 단순 문자열 일치로 용어를 추측하지 않는다. 용어 선택 시 핵심 용어 탭과 해당 상세를 함께 연다.
8. 진행 바, LIVE 복귀, 재생·송출 제어는 영상 하단 오버레이로 옮긴다. 강의 제목·세션·연결 상태·참여 인원과 강사 액션은 별도 페이지 헤더 대신 영상 상단 오버레이에 둔다. 두 오버레이 모두 포인터 환경에서는 hover·focus 시 보이고 터치 환경에서는 항상 보인다.
9. 별도의 강사 `화면 공유 중` 카드는 제거한다. 화면 공유 상태와 제어는 하단 미디어 제어에서만 제공한다.
10. 기존 강사 운영 상태와 다시보기 검수 상태는 사이드바 밖 운영 영역에 유지한다. 세부 운영·검수 탭 재배치는 후속 제품 논의로 남긴다.
11. 이번 구현은 `VITE_USE_MOCK_API=true`의 UI 목업이다. 새 REST endpoint를 추측해 추가하지 않으며, 실제 API·WS 계약 확정 전에는 `docs/CONTRACT.md`를 변경하지 않는다.
12. 라이브 페이지는 브라우저의 남은 높이에 고정해 문서 전체 스크롤을 만들지 않는다. 실시간 노트처럼 내용이 길어지는 패널은 탭 헤더를 고정하고 패널 본문만 독립적으로 스크롤한다.

## 근거

- 역할과 재생 형태에 관계없이 학습 기능 위치가 같아 탐색 비용이 줄어든다.
- 자막과 영상이 하나의 `sessionMs`를 쓰면 라이브 되감기와 다시보기에서 같은 상호작용을 재사용할 수 있다.
- 서버가 용어 식별자와 범위를 제공하면 동음이의어, 대소문자, 부분 문자열 오탐을 피할 수 있다.
- 구간 블록 누적은 생성 비용과 화면 흔들림을 줄이고, 사용자가 이미 읽은 노트를 안정적으로 유지한다.
- 목업 전용 경계를 두면 미확정 endpoint를 완료된 HTTP 기능처럼 가장하지 않고 UI를 먼저 검증할 수 있다.

## 영향·후속

- 백엔드·AI 팀과 summary 이벤트의 식별자, 시간 범위, 상태, 재연결 복구 방식과 필드 구조를 협의해야 한다.
- 확정 용어 조회 및 자막 `termId`·문자열 범위 payload를 계약해야 한다.
- 라이브 되감기 클릭을 실제 재생으로 연결하려면 recent/DVR HLS 제공 범위와 플레이어 전환을 구현해야 한다.
- 역할별 참여자 관리, 질문 인사이트, 콘텐츠 검수, 자료, 퀴즈의 최종 위치를 후속 제품 논의에서 결정해야 한다.
- 실제 계약을 확정하면 FE/BE·AI 구현, `docs/CONTRACT.md`, 계약 테스트를 같은 변경에서 갱신한다.
