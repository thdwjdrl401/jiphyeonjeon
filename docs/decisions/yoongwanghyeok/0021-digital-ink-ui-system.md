# ADR-0021: Digital Ink UI 시스템과 Paper/Ink 화면 모드

> 기존 프론트 구조 결정: [ADR-0002](../songjeongki/0002-react-typescript-frontend.md) · 학습 화면 결정: [ADR-0019](0019-unified-learning-sidebar-and-caption-dock-preview.md)

- **상태**: 채택
- **일자**: 2026-07-29
- **적용 범위**: 프론트엔드 디자인 토큰, 공통 브랜드, 공개·인증·워크스페이스·라이브·다시보기 화면

## 맥락

기존 UI는 궁궐·도서관 이미지와 녹색·금색 장식, 둥근 카드와 입체 그림자가 혼재했다. 한국적인 인상을 유지하면서도 콘텐츠 탐색 사이트처럼 절제된 모노톤, 큰 여백, 편집 디자인에 가까운 정보 위계로 통일할 필요가 있다.

이번 변경은 시각 시스템의 재설계다. 사용자 이동 경로, 역할별 라우트, 서비스 facade, TanStack Query 상태, 라이브·다시보기 상호작용과 API 계약은 유지해야 한다.

## 결정

1. 디자인 시스템 이름을 **Digital Ink**로 정하고 `paper`, `ink`, `seal`을 핵심 의미 토큰으로 사용한다.
2. 기존 화면 CSS가 참조하는 색상 토큰은 회색조 호환 alias로 유지한다. 기능 컴포넌트를 한 번에 재작성하지 않고도 전체 화면을 같은 색 체계로 전환하기 위한 경계다.
3. 공개·인증·워크스페이스는 밝은 **Paper Mode**, 영상 집중 화면인 라이브·다시보기는 반전된 **Ink Mode**를 사용한다. 두 모드는 같은 토큰과 작은 적색 낙관 포인트를 공유한다.
4. 공통 형태는 작은 곡률, 1px 경계, 평면 표면, 큰 여백, 편집형 제목 크기를 기준으로 한다. 강한 그림자와 장식 그라데이션은 상태 구분에 꼭 필요한 경우를 제외하고 제거한다.
5. 브랜드 마크와 파비콘은 선묵과 적색 낙관을 조합한 코드 기반 SVG로 통일한다.
6. 프로젝트 전용 수묵 이미지는 생성형 이미지 도구로 만들고 웹용 JPEG로 최적화해 웰컴, 카탈로그, 인증, 커리큘럼 대체 이미지에 재사용한다.
7. `design-system.css`를 기존 화면별 스타일 다음에 로드해 최종 시각 계층을 제공한다. 이 단계에서는 DOM 구조와 동작 코드를 보존하고, 후속 변경에서 화면별 기존 선언을 점진적으로 정리한다.
8. 기존 반응형 중단점을 보완하고 `prefers-reduced-motion`을 존중한다. 키보드 포커스와 의미 있는 상태색은 모노톤 전환 뒤에도 식별 가능해야 한다.

## 근거

- 의미 토큰과 호환 alias를 함께 두면 전면 재설계 중에도 기능 화면의 회귀 범위를 시각 계층으로 제한할 수 있다.
- Paper/Ink 모드는 탐색·작성 화면의 가독성과 미디어 화면의 집중도를 각각 높이면서도 하나의 브랜드로 보이게 한다.
- 프로젝트 전용 이미지와 코드 기반 브랜드를 사용하면 외부 이미지 의존성과 출처 불확실성을 없앨 수 있다.
- 서비스·라우트·상태 구조를 유지하면 디자인 변경을 API 계약 변경과 분리해 검증할 수 있다.

## 영향·후속

- API 요청·응답, 상태코드, URL prefix는 변경하지 않으므로 `docs/CONTRACT.md`와 계약 테스트 변경은 없다.
- 이번 변경의 자물쇠는 프론트 lint, typecheck, 기존 전체 테스트, production build와 `git diff --check`다.
- 화면별 기존 CSS는 동작 안정성을 위해 남아 있다. 다음 유지보수에서 사용되지 않는 장식 규칙을 제거하고 최종 토큰 레이어로 병합할 수 있다.
- 실제 브라우저와 모바일 기기에서 수묵 이미지의 대비, 긴 한국어 제목 줄바꿈, 라이브 패널의 독립 스크롤을 지속 점검한다.
