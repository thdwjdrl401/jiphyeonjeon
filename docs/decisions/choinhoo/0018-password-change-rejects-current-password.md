# ADR-0018: 비밀번호 변경은 현재 비밀번호와 같은 새 비밀번호를 거절한다

> 정본 규칙: [AGENTS.md](../../../AGENTS.md) · 공유 계약: [CONTRACT.md](../../CONTRACT.md) ·
> 판단 정책: [POLICY.md](../../harness/POLICY.md)

- **상태**: 채택
- **일자**: 2026-08-13
- **관련**: `PUT /api/me/password`, liveclass-201
- **적용 범위**: 로그인한 사용자의 일반 비밀번호 변경
- **비적용 범위**: 임시 비밀번호 로그인 후 교체, 비밀번호 찾기, 회원가입

## 맥락 (Context)

일반 비밀번호 변경은 현재 비밀번호가 맞는지와 새 비밀번호 형식만 검사했다. 따라서 사용자가 현재
비밀번호를 새 비밀번호로 다시 제출해도 서버가 새 BCrypt 해시를 만들고 204로 응답했다. 사용자는
비밀번호가 바뀌었다는 성공 안내를 받지만 실제 인증 값은 달라지지 않는다.

이 제약은 화면에서만 검사할 수 없다. API를 직접 호출하거나 오래된 프론트엔드를 사용하는 요청도
같은 계정 불변식을 지켜야 한다. 또한 BCrypt 해시는 같은 평문을 인코딩할 때마다 달라지므로 저장된
해시 문자열과 새 해시 문자열을 비교해서는 동일 여부를 알 수 없다.

## 결정 (Decision)

`AuthService.changePassword`는 다음 순서로 처리한다.

1. `currentPassword`를 저장된 기본 비밀번호 해시와 대조한다. 실패하면 기존 계약인
   401 `AUTH_PASSWORD_MISMATCH`를 유지한다.
2. `newPassword`를 같은 저장 해시와 `PasswordEncoder.matches`로 대조한다.
3. 일치하면 비밀번호와 임시 비밀번호 상태를 변경하지 않고 409
   `AUTH_PASSWORD_UNCHANGED`를 반환한다.
4. 일치하지 않을 때만 새 해시를 저장하고 기존 비밀번호 변경 후속 처리를 수행한다.

오류 메시지는 `새 비밀번호는 현재 비밀번호와 다르게 입력해 주세요.`로 통일한다. 요청은 형식상
유효하고 인증도 성공했지만 현재 자격 증명 상태와 충돌하므로 400이나 401이 아니라 409를 사용한다.
특히 프론트엔드는 401을 세션 만료로 처리하므로 정책 위반을 401로 표현하지 않는다.

프론트엔드는 같은 값을 입력하면 안내를 표시하고 제출 버튼을 비활성화한다. 이는 빠른 사용자 피드백을
위한 보조 검증이며, 서버 검증을 대체하지 않는다. Mock 서비스도 실제 서버와 같은 409 오류를 낸다.

이번 결정은 제보된 일반 변경 경로에만 적용한다. 현재 비밀번호 입력 자체가 없는
`PUT /api/me/password/temporary`의 정책은 이 변경에서 확장하지 않는다.

## 대안 (Alternatives)

| 대안 | 장점 | 단점 |
|---|---|---|
| 저장 해시에 두 평문을 순서대로 대조하고 409 반환(채택) | 서버가 실제 인증 값 기준으로 불변식을 보장하고 기존 401 의미를 유지함 | 성공 요청에 BCrypt 대조가 한 번 추가됨 |
| 요청의 두 평문 문자열만 비교 | 구현 비용이 작음 | 저장된 자격 증명을 정본으로 검증하지 못하고 서버 정책이 DTO 표현에 묶임 |
| 프론트엔드에서만 제출 차단 | 즉시 안내 가능 | 직접 API 호출과 구버전 클라이언트를 막지 못함 |
| 동일한 변경을 204 멱등 성공으로 유지 | 별도 오류 계약이 필요 없음 | 실제 변경이 없는데 성공을 안내하는 기존 문제를 해결하지 못함 |

## 영향·검증 (Consequences)

- `PUT /api/me/password`에 409 `AUTH_PASSWORD_UNCHANGED` 응답 계약이 추가된다. 요청 DTO는 바뀌지 않는다.
- 거절 경로에서는 비밀번호 해시와 활성 임시 비밀번호가 모두 그대로 남는다.
- FE/BE 공유 상태코드가 바뀌므로 `AccountProfileContractTest`에서 409 코드와 기존 비밀번호 유지 여부를
  검증한다.
- 프론트엔드 테스트에서 동일 값 안내와 제출 차단을 검증하고, Mock 서비스도 같은 오류 코드를 반환한다.
- DB 스키마와 마이그레이션 변경은 없다.
