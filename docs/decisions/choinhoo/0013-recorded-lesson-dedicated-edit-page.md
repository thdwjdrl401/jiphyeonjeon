# ADR-0013: 녹화강의 수정은 라이브 수정 폼과 분리하고 전용 라우트에서 처리한다

> 관련 결정: [ADR-0008 녹화강의 업로드·HLS 변환](0008-recorded-lesson-upload-and-hls-transcoding.md) ·
> [ADR-0009 녹화강의 상세·재생](0009-recorded-lesson-detail-polling-and-playback.md) ·

- **상태**: 채택 — 프론트 구현·자동화 검증 완료
- **일자**: 2026-08-04
- **적용 범위**: 강사 녹화강의 수정 라우팅, 제목·설명·자료 수정, 삭제, 유형별 수정 경로 보호

## 맥락

커리큘럼 관리 목록은 녹화강의의 상세 링크만 전용 화면으로 분기하고, 수정 링크는 라이브 강의와 같은
`LessonFormPage`로 보냈다. 이 폼은 `liveSession`이 없는 레슨을 수정 가능한 라이브 일정으로 판단하므로
녹화강의에도 일정 입력과 라이브 운영 정책을 표시했다.

저장하면 레슨 제목·설명을 먼저 `PATCH`한 뒤 라이브 세션 생성을 요청한다. 백엔드는 녹화강의의 라이브
세션 생성을 409로 거절하므로, 화면은 실패를 알리지만 기본 정보만 이미 저장되는 부분 쓰기도 가능했다.

## 결정

녹화강의 수정은 다음 전용 라우트와 `RecordedLessonEditPage`가 담당한다.

```text
/instructor/curriculums/{curriculumId}/sections/{sectionId}/recorded-lessons/{lessonId}/edit
```

- 관리 목록, 강사 소유 커리큘럼 목차, 녹화강의 상세의 수정 링크를 모두 전용 경로로 연결한다.
- 수정 화면은 제목·설명, PPTX 자료 추가·삭제, 영상 처리 상태, 강의 삭제만 제공한다.
- 저장은 기존 `PATCH /instructor/lessons/{lessonId}`와 자료 API만 사용하며 라이브 세션 API를 호출하지 않는다.
- 라이브 일정, 입장 가능 시간, Egress·실시간 자막 운영 정책은 표시하지 않는다.
- 기존 라이브 수정 URL로 녹화강의에 직접 접근하면 전용 수정 URL로 `replace` 이동한다.
- 반대로 녹화강의 수정 URL에서 LIVE 레슨이 조회되면 라이브 수정 URL로 이동한다. URL만으로 유형을 신뢰하지 않는다.
- 저장·자료 삭제 뒤 커리큘럼 projection뿐 아니라 녹화강의 상세와 수정 폼 Query도 무효화한다.

페이지는 분리하지만 수정 경로 판정은 `resolveInstructorLessonEditPath` 한 곳에서 공유한다. 제목·설명과
자료 API는 전달 방식과 무관한 기존 레슨 계약을 재사용하므로 백엔드 endpoint나 `CONTRACT.md` 변경은 없다.

## 비목표

- 업로드 완료 뒤 원본 MP4 교체 또는 녹화강의 버전 관리
- 영상·자막의 수동 게시 상태 변경
- 처리 중인 녹화강의 삭제 허용
- 라이브 강의와 녹화강의 사이의 전달 방식 변환

원본 교체는 현재 API가 지원하지 않으므로 화면에 파일 선택을 가장하지 않고 상세 화면의 처리 확인·재시도
동선만 제공한다. 교체가 필요하면 별도 상태 전이와 업로드 계약을 먼저 결정한다.

## 검증

- 전용 수정 링크와 라우트, 기존 URL 정규화, 라이브 일정 미노출, 수정 후 상세 복귀를 화면 통합 테스트로 검증한다.
- HTTP 어댑터 테스트에서 기존 녹화강의 수정은 기본 정보 `PATCH`만 호출하고 라이브 세션 `POST`를 호출하지 않음을 검증한다.
- 수정 뒤 녹화강의 상세·수정 폼 캐시 무효화를 QueryClient 테스트로 검증한다.
